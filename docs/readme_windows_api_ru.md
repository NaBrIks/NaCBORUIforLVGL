# Windows: NaWServer и веб-редактор

Windows-приложение использует NaWServer для HTTP и WebSocket,
раздаёт собранный веб-редактор и предоставляет общие HTTP/WS API.
Встроенный MCP проигрывателя описан в разделе [подключения MCP-клиента](#подключение-mcp-клиента).

Сквозные проверки работают с настоящим нативным сервером, LVGL и постоянным store;
их результаты отделены от проверки платы.

## Запуск

```powershell
npm run build
node examples/windows_player/run.mjs examples/windows_player/registry-demo.json `
  --schemes examples/windows_player/registry-schemes.json --api `
  --api-store '<existing-data-directory>/windows-project'
```

`--api` открывает `http://127.0.0.1:5300` с редактором в корне. Обычная команда
`npm run player` тоже включает NaWServer. Прямой запуск `run.mjs` без API-флагов
оставляет сетевой доступ выключенным.
Другой порт задаётся явно через `--api-port PORT`; занятый порт не освобождается
остановкой чужой программы. Порт 443 запрещён. `--api-port 0` используется в
автотесте для временного порта; реальный URL приходит в stdout-событии
`{"event":"api_ready","url":"http://127.0.0.1:..."}`.

`--api-store` также включает API, если его порт ещё не задан. Это префикс файлов
изменений, а не имя исходного JSON. Launcher создаёт
родительский каталог; он должен быть доступен для записи. Без явного префикса выбирается
каталог данных приложения для открытого пути проекта. `--no-settings` выключает
только сохранение выбранной палитры; сохранение проекта управляется отдельно.
Собранный редактор берётся из `frontend/dist`; другой каталог задаётся через
`--web-root PATH`. Launcher передаёт нативному процессу `--api-port` и
`--web-root`; запросы обслуживает NaWServer внутри Windows-приложения.

График `registry-demo.json` требует сборку с DataHistory. Внешний вид может
создаваться из поддерживаемых компонентов/ресурсов и произвольных собственных
`project.styles`. [Три примера и стек стилей](readme_appearance_ru.md) используют
тот же исполнитель. Палитры приложения и документ проекта имеют отдельную
область действия; редактирование проекта не регистрирует скрытно новый пункт
меню Appearance.

## Что находится на каждом уровне

```text
Веб-редактор / ProjectClient / DataClient
                         |
              Windows NaWServer: HTTP / WS
                         |
          ProjectService / StyleService / DataRegistry
                         |
                        LVGL
```

NaWServer-адаптер не повторяет проверку проекта, биндинги, стили, навигацию или
хранилище. Он ограничивает транспортные тела/очереди, принимает CBOR,
передаёт его общим сервисам и возвращает результат. JSON компилируется
общими кодеками на стороне редактора. Отдельный JSON-движок в C++ не добавлен.
Временные передаваемые пакеты удаляются после операции; FileProjectStore
используется для принятых постоянных изменений.

## HTTP/WS endpoints

| HTTP | Назначение |
|---|---|
| `GET /`, `/editor/` и `/assets/...` | Собранный веб-редактор |
| `GET /api/info` | Windows target, boot ID и fingerprints общих ABI |
| `GET /api/capabilities` | Фактические компоненты, ресурсы, методы, схемы данных/действий и лимиты |
| `GET /api/data?kind=...` | Общая C++ выборка групп/источников/действий/полей/значений |
| `GET /api/data` | Совместимый снимок значений и ограниченные receipts |
| `POST /api/data` | CBOR-команда write/action/диагностический LVGL event |
| `GET /api/project?action=info` | Состояние сервиса, storage, revision и текущая композиция |
| `GET /api/project?action=read` | Сохранённый проект CBOR и `X-Project-Revision` |
| `POST /api/project?action=begin/chunk/finish/cancel` | Ограниченная передача проекта для preview или save |
| `POST /api/project?action=show/reset` | Отдельные показ сохранённого экрана и сброс слоя изменений |
| WS `/ws` | События CBOR `project_changed`, `data_catalog_changed`, `data_changed`; ACK для команд |
| WS `/screen-ws` | ACK для команд экранов |

## Preview, save и restart

HTTP preview использует настоящий `ProjectService::preview`; предыдущий
сохранённый проект остаётся доступен через HTTP read. Неверный стиль,
ресурс или документ должен отвергаться с сохранением рабочего отображения.

HTTP save записывает проект через FileProjectStore с актуальной revision.
Операция не переключает показанный экран: можно показывать preview A и сохранить
вариант B. HTTP show отдельно загружает сохранённый экран. Старая
revision даёт конфликт; клиент должен прочитать новое состояние вместо
автоматической повторной записи.

После остановки приложения повторный запуск с тем же ROM-проектом и префиксом
store подхватывает принятый слой изменений. Это сохранение описаний UI, не
автоматическая запись всех живых источников/счётчиков приложения. На новом
подключении нужно заново прочитать revision и актуальные runtime ID.

Reset удаляет слой изменений или выбранный override существующей операцией.
Показанный экземпляр не меняется до отдельного show/load. Исходный JSON-файл
проекта API не переписывает; палитра приложения сохраняется своим механизмом.

## Receipts, границы и доступ

HTTP 202 для данных означает приём команды в ограниченную очередь. Общий
DataClient ждёт receipt с тем же ID, если `wait` не выключен. Завершённая команда,
неподтверждённая отправка и вытесненный receipt различаются. POST автоматически
не повторяется. Диагностическая data-команда event вызывает LVGL callback и не доказывает
физическое касание или работу мыши.

Транспорт принимает одну загрузку проекта до 2 МиБ, chunk до 2048 байт,
команды до 4096 байт; одновременно ожидают не более четырёх data-команд,
хранятся последние восемь результатов. Каталог/выборочные значения вычисляются
общим C++ реестром с бюджетами ответа и catalogRevision.
Лимиты описаний/значений и фактической native памяти остаются отдельными
ограничениями; размер HTTP-ответа не равен общему расходу RAM.

NaWServer привязан к `127.0.0.1`; произвольные Host и чужой Origin отвергаются.
Wildcard CORS и публикация в LAN не включаются. У этого локального API нет
отдельной пользовательской аутентификации: клиент работает с разрешениями
запущенного приложения. Это не основание публиковать порт через внешний proxy.

Редактор и API используют один origin. Событие CBOR `project_changed` приходит
через `/ws`; редактор может подхватить сохранённые другим API-клиентом изменения без
перезагрузки вкладки. Локальные несохранённые правки редактора остаются отдельным
состоянием и требуют разрешения конфликта существующим механизмом редактора.
Показ стилей/экранов редактора идёт через общий HTTP project preview;
устаревшая прямая WS-команда получает отрицательный ACK
`project_preview_required`. Отдельный экранный исполнитель не добавляется.

## Проверка нативного API

Проверять нужно настоящий NaWServer/LVGL с отдельным тестовым store:
preview/save/show, конфликт revision, data receipts, ошибки команд, перезапуск,
UTF-8 пути и WebSocket-события. Для `/mcp` есть отдельный
[набор проверок с включённой и выключенной опцией](readme_windows_native_mcp_ru.md#проверка).

## Подключение MCP-клиента

Designer по умолчанию использует прямой HTTP/CBOR API. Для отдельной проверки
можно включить `LVGL_CBOR_NATIVE_MCP=ON` и получить `/mcp` на том же адресе.
См. [сборку и каталог инструментов](readme_windows_native_mcp_ru.md).

Внешний агент может также подключиться к [локальному MCP Designer](readme_mcp_ru.md#внешний-mcp-designer-на-windows).

## Обновление базового проекта Windows

WindowsProjectStore — host-обёртка над существующим FileProjectStore. Она
сохраняет исходный compiled CBOR базы рядом с changes под суффиксом
`.base.<baseRevision>.0`/`.1`. Это данные восстановления на диске Windows,
не кэш экранных экземпляров, не новый формат UI и не часть прошивки МК.

При обновлении authored базы сохранённый пользовательский проект восстанавливается
на прежней базе через ProjectService и сохраняется относительно новой тем же
ProjectService. Сохраняется весь эффективный проект и его revision; новые экраны
базы не подмешиваются в пользовательский дизайн. Reset возвращает уже новую базу.
Публикация changes происходит только после успешной загрузки нового LVGL-экрана.
Проверка core base fingerprint остаётся строгой.

Для старого changes без сохранённой базы можно один раз передать точную прежнюю
версию JSON/CBOR: `npm run player:graphics -- --base-recovery original.json`.
Неподходящая версия или другой project ID возвращают ошибку, changes не стираются.
После успешного восстановления следующий запуск обходится без этого аргумента.
Не запускайте два проигрывателя одновременно с одним changes prefix. Базы
сохраняются по ревизиям; автоматическое удаление старых файлов не выполняется.

Проверка: `node examples/windows_player/test-base-migration.mjs PATH_TO_EXE`.
Прежний скрытый тест с посредником проверяет точный проект, revision и реальные стили после
смены базы; reset, повторный запуск, recovery JSON и неизменность обоих changes
банков при ошибочной recovery. Используются только временные тестовые stores.

## Настоящий кадр в общем редакторе

В `/editor/` панель предпросмотра имеет вкладки «Макет / LVGL». Вторая использует
тот же `NativeViewer`, что отдельный `/viewer`, с адресом текущего подключения.
Выбор вкладки или страницы редактора не переключает runtime: отображается именно
текущий дисплей, а не обязательно выбранный документ. Встроенный вариант работает
только на чтение; для показа документа остаётся явная кнопка «Посмотреть на МК».
Протоколы и Windows CORS/Origin gate не менялись.
