# Проверка обычных запросов к модели и общего контекста

> Результаты MCP в этом отчёте относятся к прежней реализации.
> Актуальные способы подключения описаны в [руководстве MCP](../readme_mcp.ru.md).


Дата: 08.11.2026. Windows, реальный NaWServer, существующий stdio MCP,
общие кодеки и настоящий LVGL. МК и NTP не затрагивались. Результаты относятся
к конкретным запросам/моделям, а не обещают качество произвольного провайдера.

## Исторические изменения и опыты

- Общая host-инструкция вынесена в assistant-system-prompt.md; readAssistantGuide
  читает её перед новым запросом в role:system. Последняя версия2026-11-08.5.
  Правила JSON, локальных координат, layout/flex/grid, transform, ресурсов,
  состояний, данных, сохранения и вложенного показа; без рецепта проверяемого UI.
  Alias, enum-имена/значения и пересечения составных методов берутся из общего
  style-контракта, не копируются второй таблицей. Полный screen-пример компилируется
  отдельным тестом. В журнале видны version и размер действительно переданного текста.
- В параметре document существующих MCP-инструментов прямо указано: JSON-объект,
  не строка. Валидация и кодеки остались прежними; ответ модели не исправляется
  автоматически и не принимается при ошибке типа.
- Ошибки отсутствующего/повторного node.id, children и лимита дерева теперь
  содержат путь root.children[N]... в исходном документе. Это общая диагностика
  кодека, не подсказка координат конкретного экрана.
- Completion ожидается до120 секунд в пределах прежнего общего deadline3 минуты;
  раньше один медленный ответ ограничивался45 секундами. Каталог — до45 секунд.
  До8192 completion tokens с учётом declared maximum выбранной модели; optional
  reasoning выключается только при прямом подтверждении метаданных.
  Незаконченный ответ с finish_reason=length не применяется.
- Большой законченный JSON в текстовом ответе отвергается явно вместо усечения;
  полный документ должен идти структурированным аргументом существующего tool.

## Измеренные опыты

Ранние варианты с конкретными координатными подсказками и ручной организацией
показа не засчитываются как самостоятельная работа модели. Они сохранены только
как диагностика. В них проявились смешение координат контейнера/экрана, старый
flex при абсолютной раскладке и обрезание масштабированных часов.

На выбранной владельцем qwen/qwen3.8-27b выполнен обычный запрос по изображению
панели умного дома. Первая попытка упёрлась в45-секундный HTTP timeout; повтор с
новым timeout дважды передал document строкой и завершился по общему deadline.
Обе попытки — неуспех, сохранённая revision не изменилась.

Затем обычный запрос «кнопка Запуск по центру с тенью, без действия, меню и
статусбар оставить, сохранить и показать» прошёл. Проверяющий не менял JSON и
не подсказывал координаты/стили/последовательность инструментов. Модель сама
исправляла отказы Node ID, сохранила документ и показала дочернюю страницу через
оболочку. Около64 секунд,15 model rounds; это функциональный успех, но пока
избыточный путь для простой задачи. JSON1175 байт, общий CBOR573 байта.

Реальный LVGL-кадр: кнопка целиком по центру, подпись читается, тень видна,
меню/статусбар сохранены. display.revision совпадает с сохранённой; дочерний
canvas выбран, ошибок загрузки нет. Остальные screens/styles совпадают с
исходным состоянием. Ответ модели честно отделил проверку runtime от визуальной.

Саморазбор Qwen назвал нехватку свежего кадра, точного каталога ресурсов и bounds
контейнера. Идея пиксельного извлечения всех параметров референса не обязательна:
цель — самостоятельная компоновка по мотивам, а не точная копия изображения.
Объяснение модели проверяется журналом, не считается доказанной причиной.
Её длинный аналитический ответ упёрся в прежний4096-byte текстовый канал;
последняя часть не сохранилась. Это не лимит CBOR-документа или МК.

## Последующие проверки обратной связи

Реальная Qwen получила кадр и сама перечислила дефекты своего сложного макета:
неподдержанные символы-иконки, светлые фоны со светлым текстом и проблемы размеров.
Сохранение и показ подтверждены; качество макета не принято. Следующая общая
просьба о доработке завершилась120-секундным provider timeout без записи. Ещё
одна попытка встретила неверный align_y, затем пересекающиеся padding; исчерпав
раунды, модель напечатала XML-подобный псевдовызов вместо настоящего tool call.
Он не исполнялся. Теперь это явная ошибка, а не успешный текстовый ответ.

В системный контекст добавлены общие правила glyph coverage LVGL без browser
font fallback, полные точные имена style properties, составные свойства и запрет
перекрытий внутри одного props. Никаких координатных подсказок конкретному макету.
MCP JSON теперь попадает в модель без лишнего string-экранирования content envelope.

Нативная проверка in-memory model → реальный MCP/NaWServer/LVGL прошла7 rounds/10
calls с двумя реальными PNG-кадрами, batch ordering и вытеснением первого кадра.
Host raw decoder подтверждён для RGB565 LE/BE, mono1 MSB/LSB, RGB/BGR/BGRX,
включая stride, ориентацию BMP и Full HD. MCU capture/wire этим не реализован.

Отдельно воспроизведён ECONNRESET на reused HTTP socket при idle timeout устройства.
MCP-клиент использует Connection:close, не меняет сервер и не повторяет mutations.
Перезапуск Windows после обновления сохраняет точные project/revision/model и
наличие ключа; bindingErrors=0. Измерения остаются только local.

## Авторский JSON и очищенный MCP — итог текущего уточнения

Системная инструкция 2026-11-08.15 объясняет, что агент создаёт разметку/стили
LVGL в JSON, и содержит ссылку на официальную документацию LVGL. Вложенность,
методы, события и данные описаны без бинарного протокола. Цветной пример Grid
2×2 имеет две кнопки, checkbox и textarea для ввода числа как строки; учебные
источники/действия не выдаются за существующие в приложении.

Два полных отдельных справочника разметки/стилей включаются в role:system:
12 встроенных типов, 26 методов компонентов, 8 общих методов, 138 методов стилей,
перечисления и соответствие JSON. Документационная проекция проверяется через
реальные кодеки; это не внутренний контракт конвертера. Генератор подключён к
contract/contract:check. Новые нативные компоненты доступны через metadata устройства.

Из MCP удалены get_contract, compile_document, decode_document, section:all и
дублирующий section:data. Вместо них get_ui_reference и validate_document;
get_device выдаёт формы авторского JSON без opcodes/signatures/ABI. Конвертеры
продолжают обслуживать тот же API/редактор. Кода для конкретного макета нет.

Проверено: 394/394 workspace, 10/10 MCP, скрытый нативный Windows end-to-end с
тестовым провайдером и настоящими MCP/NaWServer/LVGL, нативный каталог и история,
схемы и наложение стилей. Платные модельные прогоны не запускались. МК не тронут.

## История между сообщениями и JSON-вложения

Добавлены host-модуль assistant-chat.mjs и страница истории assistant.chat через
существующий DataRegistry/WS. Внешний host сохраняет user/assistant/tool messages,
картинки и JSON между отправками. Повторно не вставляет системный prompt в историю;
использует текущие английские инструкции. Сохраняется только последний feedback
кадр LVGL, пользовательские референсы остаются. Незавершённым инструментам после
отмены добавляется unconfirmed response без автоматического повторения действия.

Кнопка «Новый чат» и постраничный просмотр используют обычные actions. Фото и JSON
не передаются через публичный источник истории; там текст и имена файлов. Сам JSON
идёт как текстовая часть модельного user content через существующий private chunk
transport, а не применяется автоматически. Браузер принимает читаемый JSON до
1 MiB, нормализованный документ ограничен 64 KiB. У модели без vision JSON работает.

Проверено: 398/398 workspace; отдельные проверки истории, картинки в следующем
сообщении, JSON text-only, нового чата, восстановления после прерванного tool batch
и постраничного сохранения записей. Собран и запущен настоящий Windows LVGL/NaWServer;
нативный MCP end-to-end событий/биндинга и PNG feedback прошёл.

Веб-приёмка выполнена через отдельный headless Chromium без управления мышью и
клавиатурой владельца. После явного разрешения владельца Qwen/OpenRouter получил
картинку и реальный прежний JSON, затем второе сообщение без новых файлов. Модель
сохранила маркер и прочитала заголовок/ID прежнего JSON. Время на исходной картинке
назвала 17:33 вместо 17:32: ошибка визуального распознавания не засчитана успехом.
Перезагрузка страницы сохранила все четыре сообщения; «Новый чат» сменил id и
очистил историю, сохранив project revision 186784242627022e и bindingErrors=0.
Материалы приёмки и снимки находятся только в ignored local/chat-evidence.

Независимый новый чат получил только три английских документа, референс и MCP,
без кода и истории проекта. Он создал/сохранил реальный UI, сам нашёл часы через
каталог, затем применил 18 экземпляров MIT Tabler как геометрию в JSON. Родительский
чат не исправлял разметку этого макета. Исходная картинка неизвестной лицензии и
артефакты стороннего чата в публичный Git не добавлялись.

Граница текущей реализации: история живёт в RAM host-процесса и переживает reload
браузера, но не перезапуск Windows-приложения. UI-проект сохраняется независимо.
