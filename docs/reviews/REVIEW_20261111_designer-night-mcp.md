# Проверка Night и внешнего MCP Designer

На 7-дюймовом примере Designer сохранил восемь ролей Night и изменил оформление
кнопки. При повторном чтении из постоянного хранилища в этих восьми ролях
присутствовали ровно три заданных цвета. Отображаемая ревизия совпала с
сохранённой, активная схема — Night.

Ограничение всего интерфейса тремя цветами осталось невыполненным:

- Четыре локальных янтарных подписи на Dashboard, Radar и Trip остались в проекте.
  Модель подтвердила, что пропустила этот шаг. Условная привязка или тематическая
  роль позволила бы изменить их из JSON, сохранив остальные схемы.
- Нативные спидометр, индикатор сигнала и радар рисуют ряд цветов из C++.
  Их зарегистрированные методы управляют данными, а внутренние цвета в
  возможности устройства не входят. Нужны тематические стили или параметризуемые
  свойства компонентов, если палитра должна распространяться и на них.
- Модель изменила локальные цвета кнопки Night, поэтому этот цвет применяется к
  ней и при других схемах. Финальные кадры Setup и остальных схем она не сверила.

При сохранении часть HTTP-ответов оборвалась с `ResponseEnded` или тайм-аутом.
После обрыва ревизии продолжали меняться, а документы читались из хранилища.
По журналу причина закрытия соединения на уровне TCP или устройства не
установлена. Отдельное редактирование документа ограничивает объём аргументов
модели, но существующий ProjectClient отправляет весь CBOR-проект.
Потерю ответа на `finish` теперь обрабатывает общий клиент: он перечитывает
сохранённый проект и подтверждает только совпавший кандидат. При отсутствии
подтверждения инструмент сообщает `unconfirmed` и наблюдавшуюся ревизию,
если её удалось получить. Команда сохранения автоматически не повторяется.

Для сравнения агентов используйте одинаковый начальный проект, одинаковый
пользовательский запрос и один каталог инструментов. Внешний агент начинает с
`get_authoring_instructions` и получает тот же английский системный текст,
что Designer. Отдельно фиксируются ошибки аргументов модели, ошибки транспорта,
доступность нужных возможностей, содержимое сохранённого проекта и итоговый кадр.

Приёмка Windows. Один запущенный экземпляр Designer обслужил внешний клиент по
Streamable HTTP, протокол 2025-11-25. Клиент получил 23 инструмента, полный
английский промпт версии 2026-11-11.2, стиль с живой S3 и PNG с метаданными кадра.
Отсутствующий аргумент и устаревшая ревизия возвращаются как MCP tool error.
Обычное повторное использование HTTP-соединения проверено. Проект S3 не менялся
во время проверки внешнего клиента. Запись и перезапуск на временном Windows
проекте проверены через общий инструментарий Designer. Сам Antigravity не
запускался.
