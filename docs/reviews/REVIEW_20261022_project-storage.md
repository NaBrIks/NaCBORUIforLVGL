# Проверка: файловый каталог проекта, TPMS/GPS и S3

Дата: 2026-10-22. Область: только lvgl-cbor. Продолжение проверки ProjectService; предыдущий отчёт описывает стадию с RAM-хранилищем. Текущий стенд использует постоянный каталог SPIFFS.

## Результат

- ROM-база: dashboard, четыре давления/температуры, нативный GPS-спидометр и состояние GPS; общие panel/reading/caption. База CBOR 2600 B.
- FS: radar, trip, workbench-main; независимые radar_grid и сохранённые пользовательские accent/style_1. Итоговый проект CBOR 5278 B. Прежний проект перед миграцией прочитан в local/project-before-filesystem.cbor/.json и включён в Мастерскую; исходная копия также сохранена.
- Значения подписаны DEMO. Реальные TPMS/GNSS источники и bindings не подключены.
- Формализован lvgl-project-catalog-1: независимые CBOR-документы, точный индекс, origin/location/bytes через ProjectService и API. В редакторе: Проект → Каталог экранов и стилей МК. Никаких специальных ветвей редактора для радара.
- Стили перечислены слева; верхний selector удалён. ПКМ дерева/стилей, видимые иконки и перенос узлов проверены на предыдущем этапе; актуальный список из шести стилей и каталог проверены в браузере повторно.

## Размещение и установка

COMx, ESP32-S3 rev0.2, MAC 02:00:00:00:00:01, Flash 16 МиБ, PSRAM 8 МиБ. Раздел project/SPIFFS добавлен по явному запросу владельца: 0xC00000, 0x400000 B, конец 0x1000000. Первые три записи таблицы NVS/PHY/factory сохранены байт-в-байт; NVS не записывался.

Исходный загрузчик объявлял 8 МиБ и отвергал новую таблицу. Его валидный образ прочитан посекторно и проверен esptool image-info. Сохранены код, DIO и 80 MHz; средствами esptool изменён только размер Flash в заголовке 0x3F → 0x4F с пересчётом validation SHA. После этого стенд загрузился. Дальнейшие обновления писали только приложение; FS пережила их.

Текущий BIN: 1573136 B; SHA256 53a7d66ea775d53142da1d2fe9e1dd30b1c38cf5b34df56321949130e3864cab. Адрес 0x10000, hash verified. IP 192.0.2.1. Финальный boot s3-f3b79d3b, сохранённая revision 11cf6e7860a3b3ec, база 9bc57d284f68ca71.

SPIFFS: раздел 4194304 B; полезный объём 3848081 B; занято 34387 B после испытаний. При первой установке было занято 6526 B. Встроенный сайт: 519589 B исходных файлов / 178299 B gzip во Flash, 8 assets. Справочники ПК не включены. HTML/JS редактора и документы проекта хранятся отдельно; localStorage — только черновик конкретного браузерного origin.

## Найденные и исправленные проблемы

Проверка каждого из 256 отсутствующих слотов растягивала finish до 13.758 s; один клиент получил timeout после уже успешного commit. Очистка заменена одним перечислением фактических файлов. Обнаружена особенность ESP-IDF 5.4 SPIFFS: прежний END_OF_OBJECT от fread отображается как EIO при первом directory EOF. Одно повторное чтение получает очищенный EOF; повторная ошибка по-прежнему прерывает commit. Носитель не форматируется и ошибки не заменяются пустым проектом.

После исправления finish занял 0.307–0.343 s в контрольных запросах. Полная тестовая передача по Wi-Fi: 2895 ms (конкретный замер, не обещание постоянной задержки). Служебные объекты транзакции и большой снимок status перенесены со стека HTTP в heap; кадры save_project/Impl::save — по 80 B. После финального нагрузочного прогона измеренный минимум свободного стека httpd: 492 B. Соседний сервер и размер его задачи не изменялись.

Проверялся программный перезапуск, не внезапное физическое обесточивание. Тесты повреждённых файлов/отката выполнены на ПК. Стойкость самого SPIFFS к отказам питания отдельно не сертифицировалась. SD не настроена, наличие физической карты не проверялось. Ограничение проекта стенда — 262144 B; физическая ёмкость FS и служебный запас также ограничивают записи.
