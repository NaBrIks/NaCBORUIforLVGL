# Размер страницы в браузерном просмотре — 2026-10-23

Требование владельца: страница несёт проектный размер, браузер перестраивает область просмотра при её выборе. Использовано существующее `screen.size`; контракт и прошивка не изменялись. Автоматическая связь с размером уже существовала. Уточнены подсказки W/H, добавлен явный возврат «Размер страницы», начальный режим контейнера изменён на «Размер документа». При включении контейнера берётся актуальный размер страницы, а не оставшийся от предыдущего просмотра.

Проверки:

- `npm run build`: успешно.
- `npm test`: 285 из 285 успешно.
- Chrome, существующий изолированный редактор `http://localhost:5298/`: ручной контейнер 800×300; возврат к размеру страницы; изменение размера тестового черновика на 800×408 сразу обновляет просмотр; переход к оболочке даёт 800×480; возврат к странице даёт 800×408.
- Повторное включение контейнера начинает с 800×408 и выбранного «Размер документа». Ручной размер 800×300 обрезает содержимое без его растягивания. Снимок: игнорируемый `local/page-size-browser.png`.
- Изменение размера тестового браузерного черновика восстановлено до исходных 800×480, затем выбран экран оболочки. На МК ничего не сохранялось и не применялось. Вкладка владельца на `127.0.0.1` не использовалась.

Браузерный просмотр остаётся CSS-приближением, нативные компоненты показываются заглушками. Это проверка геометрии браузера, а не визуальная приёмка LCD. Подхват внешних изменений проекта с МК в уже открытый редактор этой работой не добавлялся.
