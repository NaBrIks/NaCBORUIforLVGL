# Подхват внешних изменений проекта — 2026-10-23

Последующая приёмка на настоящем ESP32-S3 с прошивкой, WS-событиями, защитой локального черновика и иконкой возврата записана в [аппаратном отчёте](REVIEW_20261023_mcp-ws-hardware.md). Упоминание недоступной платы ниже относится к первоначальному этапу проверки на стенде.

## Реализация

Редактор после явного открытия/сохранения проекта с МК отслеживает ревизию по событиям существующего `/ws`. Периодический опрос проекта убран по уточнению владельца. После успешного save/reset HTTP-адаптер вызывает необязательный `onChanged` с зафиксированной ревизией, а приложение отправляет CBOR `{v:1,event:"project_changed",revision:"…"}` через имеющуюся очередь yaidfws. Командный канал браузера отличает уведомления от ACK; дополнительные WS-соединения не создаются. HTTP/CBOR API чтения и MCP-инструменты сохранены; прошивка дополнена отправкой события и объявлением `project.events` в capabilities.

После восстановления WS выполняется одна сверка ревизии; события во время чтения объединяются с повторной сверкой. Полный документ загружается только при другой ревизии и отсутствии локальных правок. Предыдущий вариант с 5-секундным опросом проекта заменён; ниже начальные снимки его проверки сохранены как вспомогательные артефакты, актуальная браузерная проверка WS описана отдельно.

Модуль `project-follow.js` владеет базовым снимком, ревизиями, признаком локальных правок и защитой от поздних ответов. Автоматическая замена использует существующее подавление автоприменения при загрузке workspace. Выбор страницы/узла/стиля сохраняется, пока соответствующие элементы существуют. Открытие файла и смена сеанса связи отключают слежение. При конфликте локальный документ остаётся в браузере; исходная ревизия для сохранения не подменяется более новой.

## Достаточность MCP

Для чтения, компиляции, сохранения с ревизией, показа и навигации имеющихся инструментов достаточно. Синхронизация браузера не требует отдельного канала MCP: источник истины — ревизия ProjectService, уведомление приходит через уже открытый WS. В качестве дальнейшей диагностики полезны снимок LCD и фактические границы/прокрутка LVGL-объектов. Сейчас таких инструментов нет; они не реализованы в этой работе. Частичные патчи и отдельный механизм хранения для синхронизации не нужны.
