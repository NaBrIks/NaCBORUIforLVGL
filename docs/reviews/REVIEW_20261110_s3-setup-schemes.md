# S3 7-inch: Setup и общие цветовые схемы — 10.11.2026

> Результаты MCP в этом отчёте относятся к прежней реализации.
> Актуальные способы подключения описаны в [руководстве MCP](../readme_mcp.ru.md).


## Реализация

К существующему проекту TPMS/GPS, Radar и Trip добавлены страница Setup 800×408
и четвёртая кнопка нижней навигации. Статусбар и прежние страницы/биндинги сохранены.
Четыре выбора: Light, Cream, Emerald, Dark; подпись показывает текущий ID,
выбранная кнопка получает CHECKED через обычный биндинг. Есть простой live-пример.

Использован существующий `examples/common/appearance` — тот же модуль, что Windows
и LilyGO. Схемы берутся из общего текущего каталога Windows и компилируются общими
кодеками в 8782 байта CBOR (`tools/appearance_image.mjs`). На S3 зарегистрированы
readonly `ui.scheme` и action `ui.select_scheme`; источник передаётся существующим
CBOR /ws. UI ссылается на стабильные `global-static:ui.*`, смена схемы не пересоздаёт
экран и не реализует отдельный движок. Для общего Appearance demo-компонент собирается
с C++ exceptions. Ядро и API не дублировались, NTP не менялся.

`examples/s3_style_lab/project/appearance-setup.mjs` — пример преобразования
авторского проекта. Он сохраняет геометрию/события/биндинги прежних страниц,
заменяя исходные цвета стенда общими ролями. Специальная графика пользовательских
виджетов может сохранять собственные цвета; полная перекраска их внутренней
отрисовки этой работой не заявляется.

## Развёртывание и проверка

- Сборка S3 ESP-IDF 5.5.6/LVGL 9.6.0 — PASS. App image 2053232 байта,
  linker RAM 85020 байт, Flash 2052829 байт; это не полная оценка runtime-памяти.
- Цель идентифицирована esptool и USB; прочитаны настоящие partition table и
  OTA metadata. Записан только app в подтверждённый активный ota1, hash verified.
  Bootloader, partition table, OTA metadata, NVS и SPIFFS не перезаписывались.
- Работающий сохранённый проект повторно прочитан через настоящий MCP;
  validate_document прошёл против возможностей платы. Сохранение использовало
  актуальную revision с дополнительной проверкой перед save, persistent=true.
- Setup и все четыре схемы проверены реальными MCP clicked-событиями;
  `ui.scheme.id` подтвердил light/cream/emerald/dark. Проверка ждёт исполнения
  очереди и публикации снимка, не считает сам ACK события результатом action.
- Пройдены все четыре нижних таба; Setup оставлен открытым, итоговая схема Cream.
  Binding errors и queueDropped равны нулю.
- После явного перезапуска плата повторно отдала сохранённый проект с Setup и
  той же revision; четыре выбора и навигация повторно прошли.

Страница/изменённый проект сохранены постоянно в штатном слое изменений.
Выбранная палитра пока хранится только в runtime: после перезапуска стартует Cream.
Это явно не новая система хранения настроек. MCP-клиент адресует кнопки дочерней
страницы через `instance` её актуального pageInstance из get_project_status;
одинаковые local node ID в разных экземплярах не смешиваются.

Проверка программная, без камеры и ручного touch. Работоспособность физического
изображения/подсветки не заявляется. Исходные журналы прошивки, адреса устройства,
MCP receipts и измерения находятся только в ignored `local/setup-s3-*`.
