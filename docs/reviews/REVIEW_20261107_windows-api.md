# Приёмка: NaWServer, Windows LVGL, веб-редактор и MCP

Дата: 2026-11-07. Сетевой слой — штатный NaWServer Windows backend.
Общие C++ ProjectService/DataRegistry/StyleService исполняют проекты и события.
Постоянное хранение использует прежний FileProjectStore и UTF-8 пути.

## Результат проверки

- Release Windows с историей и без истории собраны. Настоящий NaWServer
  раздаёт frontend/dist, API и WebSocket с одного loopback origin.
- test-api: PASS, 7,34 с. Проверены реальные HTTP/WS/MCP: Host/Origin,
  Content-Type и лимиты тела, отрицательные WS ответы со строковыми ID и явный отказ при backpressure, события
  project_changed/data_changed/data_catalog_changed, preview/save/show/reset,
  конфликт revision, сохранение стилей после перезапуска, Unicode-каталоги
  и отказ на повреждённом CBOR.
- test-catalog: ON PASS, 3,67 с; history OFF PASS, 1,99 с. В OFF нет
  sampler allocation и источников истории. Обратные события остаются доступны.
- JavaScript: 326/326; MCP unit: 9/9; contract:check и полный native suite PASS.
  Отдельная сборка S3 PASS; загрузка на плату не выполнялась.
- Изолированный headless Chrome загрузил настоящий редактор, автоматически
  подключился к same-origin API; HTTP и WS online. Изменение через реальный
  stdio MCP появилось в редакторе без reload. При локальной правке внешнее
  изменение создало конфликт, сохранив локальный черновик. Исходный проект
  восстановлен через MCP с контролем revision.
- Сообщения проекта представлены компактным статусом и диалогом по запросу.
  Верхняя координата документа оставалась 334,125 px до/после обновления,
  при конфликте и открытии/закрытии подробностей; scroll не менялся.
  Закрытие диалога возвращает фокус кнопке статуса.

Проверки браузера и нативные тесты не использовали мышь/клавиатуру владельца.
Приватные пути, снимки и измерения оставлены в ignored local. Пользовательский
сохранённый проект и его схема сохранены; галерея имеет отдельный project key.

## Границы

HTTP callbacks сериализуются с LVGL через lv_lock. Ответы владеют своими
байтами; статические файлы передаются потоково. Команды данных и receipts
ограничены очередями. Managed WS arena учитывает RX/TX и служебную память;
при невозможности отправить ACK соединение явно закрывается, без потери
подтверждения при продолжающемся сеансе. Сетевые тесты используют тот же
NaWServer, отдельного тестового HTTP сервера нет.

Модель архитектуры обновлена через SeMaps MCP. Инструкция владельца о едином
стеке закреплена в AGENTS.md. Плата и NTP в этой работе не изменялись.

Графическая приёмка описана в [руководстве](../readme_graphics_ru.md):
реальные декодеры, animated GIF, SVG/Bezier, polyline и Canvas проверяются
отдельным скрытым тестом Windows, а не эмуляцией браузера.

Финальный графический профиль ON и отдельный lean OFF собраны.
На ON прошли test-graphics (18 образцов, BIN=RAW, GIF при паузе данных,
четыре схемы, переходы по пяти вкладкам), test-resize и test-system.
На lean OFF прошёл полный test-window; расширенная графика не требуется
обычным виджетам, биндингам, событиям или вложенным страницам.

Финальная TX2 приёмка: 12 обычных отрицательных ACK с точными ID;
отдельный burst 16 запросов дал наблюдаемый disconnect, затем reconnect
и все необходимые WS события прошли. В тесте нет молчаливого ожидания
закрытого соединения. Запущенная копия соответствует проверенному EXE.
На ней галерея открыта, MCP read_project возвращает graphics-gallery,
bindingErrors=0. Построенный браузерный редактор подключён: HTTP/WS online.
