# S3: прошивка и визуальный редактор

Дата: 2026-10-21. Отдельное прямое разрешение владельца: прошить S3 и проверить изменение координат, цветов и border через вебку. Затем владелец потребовал заменить основной JSON-редактор на наглядные элементы управления всех свойств.

## Прошивка

Повторно идентифицирована ESP32-S3 rev0.2, Flash 16 MB и PSRAM 8 MB. Идентификаторы и порт записаны в игнорируемом `local/s3-deployment.json`. Живая таблица разделов считана и сравнена с построенной: совпала. Записано только приложение от `0x10000`, 1 295 280 байт; конец данных `0x14c3b0`, в пределах factory `0x500000`. Esptool 5.1.0 подтвердил hash. Bootloader, таблица разделов и NVS не перепрошивались.

Локальная Wi-Fi-конфигурация подготовлена из игнорируемого файла уже проверенного S3-примера; значения не выведены и не включаются в исходники. Esptool 5.1 установлен в отдельное локальное venv. Общие окружения и соседний проект не редактировались.

Boot: проект `lvgl_cbor_style_lab`, ESP-IDF 5.4.0, LVGL 9.4.0. PSRAM 8 MB / 80 MHz, memory test OK. Устройство получило IP и обслуживает встроенный графический интерфейс. SHA256 всех трёх распакованных assets с устройства совпал с `frontend/dist`.

На контрольном замере: uptime 402 784 ms, internal heap 59 703 B, PSRAM free 5 604 312 B, 11 задач, WS received/applied **27/27**. Это короткая аппаратная проверка, не длительный нагрузочный тест.

## Проверка с реальным LCD

1. Владелец подтвердил стартовую надпись `lvgl-cbor / Style Lab` и рамку на физической панели.
2. Через поля вебки заданы X=220, Y=180, фон `#2244AA`, border 8 px, зелёная граница. MCU после отрисовки вернул эти фактические значения. Владелец отдельно ответил: **«Да, всё изменилось»** на вопрос о перемещении, синем фоне и толстой зелёной рамке.
3. Через те же controls изменены положение до X=40/Y=260, толщина и цвет границы, цвета и выбран Montserrat 20. Владелец продолжил менять поля с автоприменением; последующие ответы MCU отражали изменения.
4. Сохранён реальный ответ с X=40/Y=260, W=420/H=150, border=15, radius=0, frame_count=5196. Фон `#0E15CD` дал framebuffer-пиксель RGB565 **2233**; border `#FFCC00` — **65120**. Оба значения точно совпадают с преобразованием заданных RGB888 в RGB565. Эти пиксели читаются после синхронного refresh и передачи кадра в RGB-драйвер, а не возвращаются из входного пакета.

Ответ: `local/s3-browser-readback.json`. Логи прошивки/USB/сборки и приватный deploy manifest — в `local/`. Изображение ниже — screenshot вебки, не фотография физической панели. Физическое изменение подтверждено владельцем отдельно.

## Исправления стенда при запуске

Сначала COMx временно исчезал; после восстановления подключения esptool 5.1 повторно подтвердил нужную S3. Другая плата не прошивалась.

Исходная сетевая конфигурация переставала отвечать на INFO после подключения WS. Проверен действующий предел yaidfws: 4096 байт на frame. В демке вход ограничен 3584 байтами с запасом для ответа, очередь и буфер ответа уменьшены, освобождено около 27 KiB статической внутренней RAM; HTTP настроен на закрытие обычных соединений и до 12 сессий. Консоль переведена на USB Serial/JTAG, добавлены IP/INFO диагностические записи. После этих изменений одновременно работали INFO, WS, отрисовка и таблица задач. Причины предыдущего зависания по отдельности не изолировались; дефект соседней библиотеки не объявляется доказанным.

Полная прошивка с Wi-Fi и встроенным визуальным frontend: static RAM 129 096 B, linker Flash 1 294 876 B. Это не стоимость только парсера или style-runtime.

## Редактор и таблица

139 JS-тестов — PASS, включая 4 проверки визуальной модели: покрытие всех 119 свойств, сохранение отступов при раскрытии сокращений, удаление свойства и допустимость начальных значений. Production build — PASS. Проверены реальные поля геометрии, HEX/цветовой picker, font select и автоприменение. Генератор сохраняет 128 индексов / 26 сигнатур без перенумерации.

Колонка «Парам.» в справочнике сужена до 46 px запроса ширины (при auto-layout действует минимум заголовка), фон совпадает с № сигн. Все числовые колонки центрируют блок фиксированной ширины и выравнивают цифры по правому краю этого блока; используются табличные моноширинные цифры. Изменения внесены и в HTML, и в генератор.

Редакторы есть для всех свойств, но специализированные pointer-параметры требуют зарегистрированных ресурсов. В этом примере предоставлены только шрифты; загрузка новых изображений/шрифтов/анимационных ресурсов не реализована. На одном label не измерялся видимый эффект каждого из 119 свойств.

Снимок аппаратной проверки хранится вне публичной документации.
