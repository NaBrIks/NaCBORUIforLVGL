# NativeViewer: RGB565 и подготовка первого кадра

Дата: 10.11.2026. Исправлена общая браузерная вкладка LVGL и отдельный NativeViewer.

Раньше просмотрщик запрашивал кадр каждые 200 мс и показывал любую 503 как
потерю связи. У S3 готовый снимок расходуется одной успешной выдачей; следующий
запрос сначала требует подготовки на UI tick. Поэтому нормальный warming
вызывал бы красное мигание состояния между успешными кадрами.

Теперь NativeViewer и локальные инструменты Designer используют общий
`packages/project-codec/native-frame.js`: безопасный BMP preflight, bounded
read и максимум два повтора только для 503 JSON frame_warming_up/frame_busy
с Retry-After 0–1 секунды. Одна операция ограничена общими 15 секундами;
ожидание отменяется при Stop/паузе/скрытии/смене origin/завершении просмотра.
Метаданные native_view_interval_ms читаются раз на origin; время подготовки
входит в этот интервал. Обычные ошибки связи остаются видимыми.

Windows BI_RGB32 и S3 BI_BITFIELDS16 RGB565 проверяются до браузерного decode.
Для RGB565 обязательны INFOHEADER40, offset66, маски f800/07e0/001f,
DWORD stride и согласованные размеры. Ручной JS-перекодировки пикселей нет.
Designer оставляет PNG-кодирование в собственном WebView canvas.

Проверки:

- 14 unit-тестов frame/local tools — PASS: форматы, padding, усечённые маски,
  размеры, warming/busy/ready, предел повторов, остальные HTTP ошибки,
  отмена в паузе и неизменяемый общий deadline.
- Production frontend — PASS, 208 модулей; Designer bundle — PASS;
  упаковка встроенных assets — PASS, 15 файлов.
- Настоящий скрытый Windows LVGL/NaWServer и headless Chromium через
  test-editor-preview.mjs — PASS: Layout/LVGL, кадр, пассивность страниц/вкладок,
  pause/resume, клавиатура вкладок, ошибка/восстановление без сдвига геометрии,
  смена выбранного устройства, EN и ширина 1100 px. Ошибок браузера нет;
  проект/runtime обоих тестовых процессов неизменны, API-записей нет.

Артефакты браузерного теста находятся в ignored local/windows-editor-preview.
Использовались отдельные скрытые процессы, временные stores и порты 0;
пользовательские приложения не перезапускались, физический ввод не выполнялся.

Реальный S3 после прошивки проверен отдельным headless Chromium непосредственно
через встроенный редактор — PASS. На S3 редактор размещён в `/`; `/editor/`
является маршрутом Windows-демо и на S3 возвращает 404. Сценарий прочитал проект
с устройства в редактор и выбрал документ только для просмотра. Вкладка «Макет»
не запрашивала кадры; LVGL получила и декодировала два последовательных снимка
800×480, BMP16 RGB565, 768 066 байт, offset66, BI_BITFIELDS и ожидаемые маски.
Наблюдались три штатных ответа 503 с Retry-After: 1. Состояния просмотрщика:
«Подключение…» → «Подключён», без красной ошибки. Изображение полностью помещалось
в области предпросмотра; после возврата на «Макет» запросы кадров прекратились.

До/после совпали ревизия проекта, корневая страница shell и выбранная вложенная
страница setup. API-записей и отправок render WS — 0; исключений браузера — 0.
Снимок экрана просмотрен визуально: Setup с верхним статусбаром и нижним меню
действительно виден, хотя в редакторе выбран другой документ. Это подтверждает
пассивность вкладки. Отчёт и screenshot находятся в ignored local/s3-native-viewer.
Использован отдельный временный профиль Chromium; приложения владельца не
перезапускались. Проверка подтверждает программный транспорт и браузерный показ
реального framebuffer; физическая LCD/камера этим тестом не проверялись.
