# Проверка: группированный каталог данных, история и Windows MCP

> Результаты MCP в этом отчёте относятся к прежней реализации.
> Актуальные способы подключения описаны в [руководстве MCP](../readme_mcp_ru.md).


Дата: 2026-11-07. Проверено на настоящем LVGL 9.6.0 Win32 и TinyCBOR 0.6.1.
Схема/значения/страницы исполняются общим C++ runtime. Устройство этой итерацией
не прошивалось; NTP не менялся. Android остаётся планом.

## Изменения и проверенные границы

Расширен существующий DataRegistry: группы, описания источников/действий/полей,
unit/nullable, отдельная catalogRevision, immutable DataView. Выборка находится
в одном C++ модуле; HTTP/MCP не реализуют второй каталог. Добавлен опциональный
DataHistory с явным tick, фиксированными кольцами и обычными readonly выходами.
События/обратная запись продолжают работать без нового глобального выключателя.

GET /api/data без kind сохраняет старый snapshot. С kind — bounded query:
16 записей/4096 байт по умолчанию, до 64/16384. Структура и значение выбираются
по группе/префиксу/имени/JSON Pointer. Целые записи, явные 409/413, без обрезания
схемы. MCP get_device теперь краткий, get_data — выборочный; legacy snapshot явный.

GPU-запись не означает наличие всех PDH-счётчиков. Стандартный системный тест
сохраняет unavailable как пропуск; отдельный строгий require-gpu обнаружил
недоступный счётчик одного адаптера. Драйверы/ОС из-за этого не менялись.

Нативные regression-проверки включают: независимые catalogue/value revisions,
пустые поля, escaping JSON Pointer, nullable vs unknown/stale, размеры UTF-8,
paging, direct C++ query validation, retained view после уничтожения реестра.
Найдены и исправлены два случая: очистка Unknown при точно заполненном payload
бюджете и ложный 413 при выдаче null для большого stale-значения. Предварительная
оценка размера проверяет текст/составные значения до создания export-копии.

DataHistory проверен на постоянных значениях, пропусках периодов, stale/unknown,
восстановлении, большом скачке/обратном времени, отрицательных/предельных числах,
mean без переполнения и лимитах. При полном бюджете неуспешная запись
history_enabled сохраняет прежний sampler/подтверждённый bool; после освобождения
места отключение проходит. Выключение освобождает кольца, re-enable начинает новую
историю. Unknown-инвалидация проходит при полностью занятом payload-бюджете.

## Реальный Windows → HTTP transport → MCP

Поставляемые registry-demo.json и test-catalog.mjs проверяют каталог реального
C++ процесса через штатный NaWServer и настоящий SDK stdio MCP.
Transport передаёт запросы в нативный DataView; селекторы/лимиты/каталог не копируются
в JavaScript. JSON и CBOR загружаются общими кодеками/ProjectService.

Проверяются группы, выбранные схемы/поля, единицы, 512-byte pages, динамическая
регистрация источника и 409 старой ревизии. Все 13 реальных widget descriptors
выдаются целиком отдельными запросами (170–888 байт, включая opcode/parameters); выборка стилевых
методов также возвращает исполнимые сигнатуры.

При истории ON демонстрируются 32 отсчёта по 200 мс, mean и изменения реальных
пикселей нативного графика. Сравнивается область графика, а не только весь screenshot.
Сбор продолжается вне страницы. Реальные switch callbacks переводят sampler в
0 выделенных точек и обратно в свежие 32. При compile OFF источников sampler нет,
выделено 0; обычные значения и события продолжают работать.

Тесты используют скрытые окна и процессные LVGL events. Ввод мыши/клавиатуры в ОС
не отправляется. Локальные BMP/JSON/логи остаются ignored, без публикации частных
путей, сетевых адресов и исходных диагностических данных.

## Полный редизайн и пользовательские схемы через MCP

В registry-demo добавлены «Строгая классика», «Космическое будущее», «Розовый пони».
Три состояния настоящего LVGL просмотрены: подписи/числа читаются, компоненты
помещаются, цвета, радиусы и границы меняются согласованно. Общая геометрия остаётся
стабильной. Классика radius/border 0/0, космос 0/1, пони 18/0; экземпляр
страницы сохраняется. Линия графика пони имеет контраст не менее 3. Кнопка соединяет глобальную роль, экранную геометрию и состояния;
поздний экранный FOCUSED-стиль перекрывает outline_width до 3 при сохранении
остальных свойств общей роли. INDICATOR/KNOB также оформлены схемой.

Расширение roleOverrides использует обычные свойства и общий стилевой codec.
Дополнительная схема с новым ID by_agent загружается без пересборки; проверены
неизвестные роли и неправильные стилевые свойства. Исходный каталог четырёх палитр
остаётся совместимым.

Через настоящий stdio MCP создан произвольный новый дизайн: project.styles,
несколько refs на компоненте, preview_project → общий CBOR → нативный ProjectService.
Проверены реальные цвета, radius и линия графика, сделан и просмотрен снимок.
Несуществующее свойство отклонено до начала preview transfer; текущие объекты и
их свойства не изменились. После удачного preview сохранённый тестовый проект
остаётся прежним. Новый set_theme/storage/renderer не добавлялся.

Прикладной Appearance-каталог и произвольный проектный дизайн — разные уровни:
MCP-оформление хранится обычным содержимым проекта, без автоматической регистрации
нового пункта в отдельном меню Windows Appearance. Windows обслуживает постоянный HTTP/WS endpoint через NaWServer.

## Ограничения

- Логические payload/metadata/maxBytes budgets не равны общей занятой куче.
  Старые DataView могут удерживать предыдущие shared snapshots; не накапливайте их
  без ограничений. Реальный HTTP-адаптер заменяет один последний view.
- catalogRevision стабилизирует состав описаний, не значения между запросами.
- Динамическая регистрация поддержана, unregister/изменение схемы имени не добавлены.
- History — latest-value sampler, не запись каждого publish и не интерполяция потерь.
- Старые истории SystemMetrics независимы от нового выключаемого sampler.
- Виджеты/стили/ресурсы ограничиваются на MCP host после полного capabilities fetch;
  selective data query выполняется в реестре. get_contract остаётся полным явным чтением.
- Windows использует штатный NaWServer для HTTP/WS и веб-редактора; host-проверка не является проверкой аппаратной платы.

Публичные Markdown-ссылки проверены без ошибок; канонический формат проверен для
20 изменённых/новых C/C++ файлов, git diff --check без замечаний. Эвристический
поиск известных credential/локальных идентификаторов в исходниках и Git history
не нашёл совпадений; это не математическая гарантия отсутствия любых секретов.

Проверенный Windows EXE установлен в стандартный local build-каталог (SHA256
совпадает со сборкой приёмки). Демка registry-demo с тремя схемами запущена штатным
launcher: loaded, 800×480, без эмуляции ввода в ОС.
