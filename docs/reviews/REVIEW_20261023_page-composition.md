# Проверка вложенных страниц, навигации и статусбара

Дата: 2026-10-23. Рабочий каталог: `../lvgl-cbor`.

## Изменение

Реализовано принятое владельцем дерево экземпляров страниц: каждый экземпляр владеет собственными объектами, биндингами, событиями и потомками. Исполнение использует существующий screen v3 cursor executor; метаданные вставок имеют отдельный composition v1 контракт. Данные остаются в общем приложении-владельце DataRegistry.

Общие формы редактора настраивают допустимые вставки, начальную страницу, размеры и политики Освобождать/Кэшировать/Удерживать. Граф проекта вычисляется из тех же ссылок. Браузерный просмотр поддерживает вложенную компоновку, переходы, выбранные вкладки и независимый viewport; кэш прошивки не эмулируется.

Опциональный пример добавляет обычную страницу `shell`: статусбар 28 px, содержимое 408 px, нижняя навигация 44 px на всю ширину 800 px. Существующие страницы сохраняют проектный размер 800×480 и прокручиваются внутри содержимого. Источники `system.network` и `system.clock` принадлежат ESP-IDF-приложению. SNTP асинхронный: основной `pool.ntp.org`, штатные fallback `ru.pool.ntp.org` и `time.google.com`, часовой пояс `YEKT-5` (UTC+5).

- Полный native-набор прошёл: стили, экраны, сервисы, нативные компоненты, ProjectService, биндинги, BLE reducer, часы и композиция. Лог `local/composition-native-full.log`.
- Композиция проверена на независимость локальных ID, release/cache/retain/LRU, первое значение и resume snapshot, паузу demand/events, отмену старых отложенных событий, ограничения, циклы, teardown/reentrancy и разделение save/display.
- Независимый review выявил замену приостановленного runtime с повторным включением подписки. Public load/mount неактивного runtime теперь отклоняются; дополнительная native-регрессия прошла после исправления.
- Браузерная модель исправлена для цикла через начальную вставку новой страницы: полная цепочка предков передаётся при построении потомков. Регрессия входит в JS-набор.

- Финальный S3 production build прошёл: код/данные flash 2 203 480 байт, статическая RAM 96 896 байт, файл приложения 2 203 888 байт. Лог `local/composition-final-build.log`. Это размеры сборки, не измерение свободной памяти.
- SHA-256 ROM base CBOR остался `e6c577fced8c3c7b517a4838e848c5e45b3ba4a60e09c49a0bd699acbdaec4bc`; экранные/стилевые ABI не менялись этой композицией.

## Аппаратная и браузерная приёмка

Резервная копия полного проекта до изменения: `local/composition-before.json`, состояние устройства: `local/composition-before-device.json`, прежняя прошивка: `local/composition-before-firmware.bin`.

В Chrome на отдельном тестовом origin `http://127.0.0.1:5300/` проверены:

- открытие сохранённого проекта с МК: 6 страниц, 6 общих стилей, entry `shell`;
- форма контейнера со всеми тремя политиками; изменение политики и возврат исходного значения;
- обычная форма события `clicked → navigate(content, ble-scanner)`;
- переключение browser-only preview на Bluetooth и выбранное состояние кнопки;
- отдельный viewport 800×300; после отключения «В контейнере» размер документа снова 800×480;
- источник `system.clock/localTime` в общей форме биндингов, без специального редактора часов;
- граф от entry к дочерним страницам. После визуальной проверки прежняя раскладка по порядку списка заменена простым BFS по уровням.

Снимки: `local/composition-ui-editor.png`, `local/composition-ui-graph.png`. Браузер показывает компоновку и исходные значения; live-данные и нативная графика принимаются на LCD.

Первичная аппаратная проверка подтвердила навигацию, reuse retain/cache, пересоздание release и подавление события скрытого BLE-экземпляра. Настоящие BLE-пакеты продолжали прибывать, массив ограничен 16 устройствами, bindingErrors=0. Ошибочный переход в предка дал `composition_cycle`, pageInstance=0, сохранённый выбор и красный крест на LCD (`local/composition-error-lcd.jpg`).

Сохранение оболочки подтверждено чтением: revision `6c619acc862edd0e`, original screens/style сохранены; `local/composition-saved.json`. Повторная app-only прошивка загрузила сохранённую оболочку при старте. NVS, PHY, таблица разделов и SPIFFS не перепрошивались.

В первой проверке NTP за отведённое время не подтвердился, поэтому она завершилась ошибкой, а не успехом. Отдельно был один timeout preview-transfer: чтение подтвердило прежнее отображение, повторный preview прошёл. Исследование NTP и окончательная аппаратная приёмка записаны ниже.

## Диагностика времени

Проверены DNS, штатный запуск SNTP и независимые запросы с контроллера. Первоначально синхронизация не подтвердилась; позднейшая проверка установила ограничение интернет-доступа. После его устранения штатный SNTP прошёл повторную приёмку на чистой прошивке. См. [проверку времени](REVIEW_20261023_ntp.md).

## Итог на финальной прошивке

Прошита только область приложения `0x10000` на COMx, ESP32-S3 MAC `02:00:00:00:00:01`. SHA-256 приложения: `bc25be1eed384b261f676ae43b52d02684b1350157a4442c13b224ecfed09fb0`. Проверка flash hash прошла; разделы/NVS/PHY/файловая система не записывались. Артефакты: `local/composition-final-deploy.log`, `local/s3-deployment.json`.

На boot `s3-a383febc` повторный `tools/composition_hardware.mjs` прошёл четыре последовательных этапа:

1. Навигация вложенных страниц; reuse экземпляров dashboard/retain и radar/BLE/cache; новый trip/release; команда скрытому приостановленному BLE-экземпляру не очищает источник.
2. BLE включён до и после проверки. За 3,5 секунды пакеты выросли 265 → 284, массив содержит 16 устройств и не превышает лимит.
3. Переход в предка даёт `composition_cycle`, сохранённый выбор и `pageInstance=0`.
4. Полный preview создаёт новые экземпляры, boot_id и сохранённая revision не меняются. `bindingErrors=0`, `queueDropped=0`, `rejectedEvents=0`.

Пятый этап — подтверждённое реальное NTP и ход секунд — завершился ошибкой после 45 секунд ожидания. Поэтому общий запуск имеет **exit 1**, а не статус полной приёмки. Отчёт: `local/composition-hardware.json`; журнал: `local/composition-final-hardware.log`. После проверки диагностическое сообщение теста сокращено до clock/network, чтобы при повторении не печатать весь BLE-массив; `node --check` прошёл.

Затем прочитан сохранённый проект: исходные пять screen-пакетов побайтово эквивалентны резервной копии после кодирования; шесть общих стилей совпадают. Сохранённая revision остаётся `6c619acc862edd0e`. Команда show вернула сохранённую оболочку без preview, в ней выбран Bluetooth. Финальное состояние: `local/composition-final-state.json`. Именованные сетевые/BLE/часовые источники находятся в known; у часов это известное состояние `syncing`, само время всё ещё отсутствует.

Физический LCD проверен USB-камерой: верхняя строка IP/NTP, содержимое BLE и выбранная нижняя кнопка видны на `local/composition-final-lcd.jpg`. Helper `capture_lcd_focused.ps1 -Focus 102` подтвердил восстановление исходной экспозиции и фокуса. События навигации подавались через диагностический API в реальные LVGL-обработчики; физическое касание пальцем не проверялось.

Временный браузерный стенд 5300 остановлен; основной редактор `http://127.0.0.1:5298/` отвечает HTTP 200. Встроенная страница МК отдаёт итоговые `index-3Te0Xb2T.js` и `index-CIBYD-og.css`. Новый commit/push в этой фазе не выполнялся.
