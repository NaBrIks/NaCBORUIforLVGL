# Проверка MAUI Windows/Android и интеграции SPLA — 2026-11-08

Состояние ниже относится к первой проверке. Реальный авторизованный чат позднее проверен на обеих платформах: [отчёт 09.11.2026](REVIEW_20261109_maui-real-chat.md).

## Реализовано

MAUI Blazor Hybrid приложение находится целиком в `tools/designer`.
Presentation/платформенное хранение — здесь; история, OpenAI-compatible/OpenRouter,
SSE/tool-call decoding, agent loop и MCP — существующие проекты SPLA через
ProjectReference. Исходники SPLA не менялись. Готовый Vue-чат SPLA исследован,
но не копировался: он связан с Vue store и сервисным протоколом, не является
Razor-компонентом. Анализ и границы — в [руководстве](../readme_maui_designer_ru.md).

Пользовательский интерфейс: многострочный ввод снизу, история вверх, Новый чат,
Markdown, обычное/подробное отображение, картинки и JSON через системный picker,
настройки endpoint/provider/model/MCP, поиск моделей, фильтр ID с `:free`, таймер,
постоянная строка состояния, подробности ошибки по ⓘ. Смена вида ответа не меняет
system prompt. Есть полный кадр LVGL, обновление и разворачивание предпросмотра.
Текущий кадр — изображение реального target, не второй движок рендеринга.

## Границы приёмки

Реальный авторизованный LLM-запрос из MAUI не выполнялся: ключ для нового клиента
не настроен. Проверка модели/tool loop/контекста выполнена в интеграционном тесте
с настоящим кодом SPLA; публичный каталог и MCP проверены по реальной сети.
Нельзя выдавать это за уже пройденную платную генерацию из Android.

Первый прототип работает с Windows LVGL через отдельный **native NaWServer**
HTTP MCP gateway на loopback. Телефон подключается через USB adb reverse,
эмулятор — через host alias. Gateway не принимает LAN bind, не содержит отдельного
API/кодеков . Плата и её прошивка не менялись.
Прямой MCU HTTP MCP, локальный LVGL renderer телефона, голос и дисковый архив
чатов остаются следующими задачами.

Отмена останавливает ожидание клиента: завершённые изменения сохраняются,
незавершённая сетевая запись может завершиться позднее. Не следует повторять
запись, не прочитав состояние target. История незавершённого tool batch очищается
штатным SPLA TruncateTo. Перенастройка соединений во время запроса запрещена.

В Android при первой попытке получения каталога зафиксирован `Connection failure`.
Повторная явная загрузка тем же SPLA-клиентом успешно вернула 461 модель; WebView
тоже получил HTTP 200. Причина первоначального сетевого сбоя не установлена;
обработчик HTTP/проверка TLS и системные сетевые настройки ради него не менялись.
Приложение оставляет диагностику доступной и позволяет повторить чтение каталога.

Дополнительно прошли две проверки реального MarkdownRenderer: обычный Markdown
форматируется, raw HTML/javascript-ссылки/генерируемые event attributes не исполняются.
Режим чата не выводит пустые assistant-карточки от промежуточных tool calls:
инструменты остаются в подробном журнале. Перечень методов и события не фильтруются.
