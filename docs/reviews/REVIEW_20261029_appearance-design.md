# Схемы оформления: проверка идеи и границы — 2026-10-29

Обновление 2026-10-30: переносимая часть Appearance и DemoData выделена в
`examples/common`, успешно собрана и испытана на T-Display-S3. Прежний вопрос
идентификации платы решён. См. [новую аппаратную приёмку](REVIEW_20261030_lilygo.md).
Ниже сохранён разбор исходного Windows-этапа; его планы не следует выдавать
за невыполненный статус последующей аппаратной работы.

Проверены Windows-пример и общий runtime после добавления страницы настроек.
Ядро, ABI, S3 и соседние проекты не менялись. Аппаратная приёмка новой платы
не включена в результаты ниже: до прошивки требуется установить её точную модель.

## Вывод

Для текущей задачи достаточно именованных ролей оформления и обычного стека
стилей LVGL. Схема меняет значения общих ресурсов, страницы явно подключают
роли к частям и состояниям компонентов. Не требуется второй renderer, CSS
селекторы, глобальная замена RGB или пересоздание проекта при выборе цвета.

Это соответствует штатным механизмам LVGL: порядок подключения стилей,
приоритет состояний, расширение темы и уведомление потребителей через
`lv_obj_report_style_change`. См. [порядок и состояния](https://lvgl.io/docs/open/9.4/details/common-widget-features/styles/overview)
и [изменение общих стилей](https://lvgl.io/docs/open/9.4/details/common-widget-features/styles/style_sheets.html).
Указанное руководство — версии 9.4; фактическое поведение дополнительно сверено
с исходниками и испытано на целевом LVGL 9.6.0, не принято только по документации.

JSON на ПК остаётся входным форматом общих кодеков. Нативный проигрыватель
получает CBOR и использует те же ProjectService, ScreenRuntime, StyleService,
DataRegistry и диспетчеры. Win32-окно, файловые диалоги и системный шрифт —
адаптеры Windows, а не альтернативная реализация UI/биндингов.

## Что обнаружено и проверено

| Вопрос | Результат и решение |
| --- | --- |
| DEFAULT не перекрывает более конкретное состояние темы | Подтверждено для ON-переключателя; исправлено явным INDICATOR/CHECKED. Прозрачность OFF сохранена. |
| Клавиатурный фокус отличается от обычного FOCUSED | Дополнительный тест воспроизвёл чужую обводку кнопок. Для кнопок добавлен FOCUS_KEY, для дуг — FOCUS_KEY/EDITED. Проверены сочетания с CHECKED/DISABLED и оформление остальных интерактивных типов. |
| Textarea управляет своим фокусом | Восстановление текста может вызвать событие фокуса; LVGL нормализует EDITED по состоянию группы. Тест проверяет эффективное состояние и цвет, не подменяет обработчики LVGL. |
| Popup не входит в авторское дерево страницы | Стандартный dropdown создаёт отдельный объект. Расширение темы приложения подключает к нему общие ресурсы и шрифт; проверены открытие, выбор и смена палитры при уже открытом списке. |
| Нет прокрутки, но длинные значения выходят за край | У счётчика и строки схемы заданы размеры и штатное многоточие, у скорости внутри дуги — постоянная область. Проверены 180.0 km/h, большой счётчик и 32 кириллических символа без изменения bounds. |
| Внутренняя прокрутка поля отличается от прокрутки страницы | Страница помещается между статусбаром и меню. Длинный введённый текст прокручивается внутри ограниченного textarea; обещания показать любые 32 символа целиком в двух строках нет. |
| Стиль должен жить дольше потребителей | Проект уничтожается до Appearance, тема — до шрифта. Общие адреса StyleValue сохраняются; копирование владельца темы запрещено. Перезагрузки и завершение скрытых процессов проверены. |
| Кэшированная страница получает старую палитру | Подключённые роли остаются общими по адресу. Проверены cache/retain, возврат на страницу, данные и instance IDs после выбора схемы. |
| Невалидный документ ломает рабочий экран | Проверены плохой JSON/CBOR, отсутствующий ресурс, отказ корня и отдельная ошибка дочерней страницы. Используются существующие механизмы сохранения предыдущего корня/заглушки. |

Для испытания фокуса используются обычные common-команды в временном проекте,
для действий — события внутри LVGL. Мышь/клавиатура ОС не отправляются; окна
испытаний скрыты, отсутствие их активации проверяется программно.

## Границы, которые нельзя скрывать

- Роли — явная договорённость приложения и проекта. Чужая страница без ссылок
  `global-static:ui.*` автоматически оформляться не начнёт. Локальное свойство
  перекрывает подключённую роль; `copy/merge` создают снимок, а не живую ссылку.
  Нативный компонент со своими константами цвета должен явно поддержать роли.
- `global-static` обозначает внешний ресурс приложения. Это не обещание
  неизменности его содержимого: владелец меняет StyleValue по прежнему адресу,
  потребитель получает заимствованный `const lv_style_t *`.
- Проверены 12 типов нашего контракта и перечисленные состояния. Это не весь
  каталог LVGL и не все возможные комбинации. Новые виджеты, scrollbar, placeholder
  и дополнительные части требуют своей проверки. Например, отдельная часть
  TEXTAREA_PLACEHOLDER пока не представлена в нашем контракте; ABI ради примера
  не расширялся.
- Сейчас разрешён один биндинг на метод одного узла. Два правила `state` с
  разными масками также отвергаются: дополнительная проверка это подтвердила.
  Нельзя обещать произвольные независимые биндинги CHECKED/DISABLED тем же методом.
  Если это понадобится, сначала уточнить идентичность цели для постоянной маски
  и согласовать PC/native-валидацию; не вводить обход в одном редакторе.
- Подготовка каталога предшествует применению. Выбор выполняется в одном
  сериализованном UI-контексте, поэтому кадр не рисуется посередине смены ролей.
  Это не транзакция с гарантированным откатом при исчерпании памяти:
  `lv_style_copy` сбрасывает и заново наполняет стиль. Гарантии OOM не заявлены.
- Все варианты заранее подготовлены: сейчас 4 × 15 ролей плюс 15 активных
  значений. На Windows это проверенный простой путь; RAM, фрагментация и время
  обновления на конкретном МК ещё не измерены. Автоматическая политика памяти
  и оптимизатор обновлений не добавлялись; смена схемы — редкое действие.
- Меню схем в Windows-каталоге сейчас передаётся метаданными маленьких
  технических screen-записей обычного project-envelope. Это локальная
  договорённость примера, не новый публичный формат тем проекта.
- Segoe UI берётся из установленной Windows и не распространяется. Нельзя
  просто положить этот системный файл в прошивку. Для кириллицы на другой
  платформе нужен подходящий лицензированный шрифтовой ресурс.

## Минимальное дальнейшее развитие

Цвет и форму следует задавать раздельно. Для угловатого/округлого оформления
достаточно небольшого набора геометрических ролей: radius, padding, gap,
толщина рамки. Локальные значения этих свойств нужно оставлять только там,
где они намеренно фиксированы. Смену формы проверять отдельно: в отличие от
цвета она может вызвать новую компоновку и переполнение.

Flex/Grid и структура страниц остаются частью проекта. Переносимость движка
не превращает макет 800×480 в читаемый макет маленького дисплея. Для другой
площади нужен подходящий проект/компоновка и его собственный size; недопустимо
объявить уменьшенную картинку доказательством пригодности интерфейса.

При переносе схем на МК сначала выделить переносимую часть Appearance без
filesystem/Win32/системных шрифтов и переиспользовать её в двух примерах.
Не копировать второй обработчик ролей и не добавлять тему в ScreenRuntime.
Общий публичный раздел тем стоит формализовать после такой аппаратной проверки,
когда известны реальные потребности, а не расширять ABI заранее.

Источники продолжают принадлежать приложению: пауза биндинга скрытой страницы
не останавливает сбор данных. Последнее значение даёт DataRegistry, историю
графика — ограниченный буфер источника. Текущий генератор скорости использует
абсолютную фазу времени; `demo.running=false` останавливает публикации скорости,
а после включения он возвращается к текущей фазе. Это отдельная семантика
демоисточника, не свойство паузы биндинга или выбора схемы.
