# Аппаратная проверка порций предпросмотра, 2026-11-11

S3 обслуживает `GET /api/view/frame?packets=1` через NaWServer. Один и тот же
поток LVF1 используется для первого экрана, циклического прохода и частичного
обновления. `since` — последняя полностью принятая ревизия. Ответ 204 означает,
что обновлять нечего. Старые клиенты могут продолжать запрашивать обычный BMP.
Обе формы читают одну рабочую память дисплея, без отдельного снимка.

Каждая порция имеет 32-байтный LE-заголовок: сигнатура LVF1, длина пикселей,
ревизия, идентификатор экрана, x/y/w/h, ширина/высота холста, формат и флаги.
Код 1 обозначает плотные строки RGB565 LE, бит 0 помечает последнюю порцию
ответа. Максимум пикселей на порцию — 4096 байт. HTTP Content-Length сообщает
объём всего обновления, X-Frame-Crop-Height — высоту его области. Декодер
проверяет границы, последовательность и длины до показа завершённой порции.

На 7″ S3 FULL и DIRECT используют фактические буферы RGB-контроллера. При
передаче читаются только очередные байты готового буфера. Задержка Wi-Fi не
удерживает буфер за клиентом. В одном буфере чтение сериализуется с рисованием.
В двух буферах LVGL рисует в другой буфер и публикует новый указатель после
синхронизации LCD. DIRTY накапливает координаты из flush в ограниченной истории.
Хеширование пикселей отсутствует. При потере истории нужен полный проход.
Циклический режим и полный проход используют те же порции.

`GET /api/display/config` показывает активные и сохранённые параметры.
`POST /api/display/config` принимает CBOR `{mode:"full"|"direct",buffers:1|2,
transfer:"dirty"|"cyclic"}`, сохраняет их в NVS и возвращает 202 перед
перезапуском. Встроенный редактор показывает параметры на странице «Устройство».
Настройки выбора в физическом Setup используют тот же механизм сохранения.
Флаги сборки `LVGL_CBOR_TRANSFER_DIRTY` и `LVGL_CBOR_TRANSFER_CYCLIC` выбирают
доступные режимы, в этой сборке включены оба.

## T-Display-S3 PARTIAL

ST7789 подключён по i80, хранит кадр в собственной GRAM. LVGL использует две
рабочие полосы по 20 строк, полного буфера на МК нет. Перехват flush держит
одну порцию до 4128 байт и 256 байт маски покрытия. Данные уходят через
существующий USB-адаптер с тем же заголовком LVF1. Пассивный режим на неподвижном
экране добавил 0 flush. Ленивый запрос дорисовал по одной недостающей полосе.
Из 29 порций собран реальный RGB565 кадр 320×170, 108800 байт на принимающей
стороне. Сборка сообщает 25976 байт статической RAM. SPI-устройство для этого
испытания не требуется.

## Клиенты и Setup

Встроенный редактор проверен на S3 в отдельном Chromium. Получены два
законченных ответа LVF1. Оба режима показали 3232 из 775680 байт на первом
шаге. В атомарном режиме до завершения новый холст был скрыт. В постепенном
режиме холст был виден в ходе передачи. Проект при просмотре не записывался.

Windows MAUI проверен отдельно на реальном потоке S3. В обоих состояниях
галочки был промежуточный прогресс. В атомарном режиме число промежуточных
записей на видимый canvas было 0, в постепенном — больше 0. Тестовый экземпляр
закрыт. Последующая сборка с идемпотентной отменой прошла 388 JS-тестов и
собралась без ошибок и предупреждений.

Физический Setup сохранил кнопку Night и прежние схемы, получил строку
Active/Draft и компактные кнопки конфигурации. Через обычный LVGL pointer
проверены изменение черновика и Save and restart. После рестарта активны
FULL, 2, RGB565, Dirty. Проект прочитан обратно и сверён по CBOR. Первый
тап навигации сразу после старта не успел сменить экран, повтор после
готовности успешно вернул Setup.

В приватном local/ сохранены снимки, байты и результаты измерений.
