# Редактор и выбор компонента на настоящей S3

Дата: 2026-10-22. Проект: `../lvgl-cbor`. После прямого разрешения владельца прошивка записана на Waveshare ESP32-S3-Touch-LCD-7 Rev1.2.

## Изменения интерфейса

- Дерево экрана находится слева на всю рабочую высоту. Свойства — в следующей колонке, предпросмотр — справа. Прокрутка панелей независима, есть два разделителя ширины: дерево/свойства и редактор/предпросмотр.
- Данные виджета, флаги, размеры и layout используют общие визуальные уровни `CornerFrame`. Специальные редакторы размеров и layout сохраняются при фильтрации обычных стилей.
- `PreviewActions` содержит единственную панель применения, автоприменения и проверки для обоих режимов. Автоприменение экранов по умолчанию выключено; накопленные правки отправляются после ACK.
- Колесо работает и в размерностях с `%`: 60 → 61 и 50% → 51% проверены через настоящий ввод в браузере. Позиция прокрутки свойств осталась 0. Shift задаёт шаг 10. `content` и неполный ввод не преобразуются в случайное число.
- Подписи, выводимые примерами и новыми виджетами на LCD, используют латиницу. Сохранённые пользовательские документы не переписывались. Метаданные примеров в редакторе остаются русскими.
- В справочнике объединяются семейство и тип/роль; объединения пересчитываются при фильтрации. Для констант ширины в проверенном viewport: 100 / 125 / 340 px и оставшаяся ширина для пояснения. Пустые Setter/Getter скрыты вне вкладки свойств.
- Константы получили русские пояснения. Для функций добавлена краткая русская памятка по операции и параметру; это не дословный перевод полного комментария LVGL. Исходный английский комментарий сохранён в JSON-инвентаре, точная сигнатура и ссылка на исходник доступны в таблице.

## Переход от CSS к виджету на МК

`/component-ws` принимает тот же числовой screen CBOR. Общая очередь `/screen-ws` и `/component-ws` остаётся ограниченной двумя пакетами, LVGL вызывается только в UI-контексте. Дополнительной большой очереди для предпросмотра нет.

`component_preview.cpp` создаёт экземпляр через `ScreenRuntime.mount()`, переносит привязку `StyleRuntime` к узлу `sample` и сохраняет именованные стили, copy/merge и слоты. Неудачная замена возвращает прежнюю привязку. Удаление объекта обнуляет слабый handle StyleRuntime.

Браузер ожидает создания последнего выбранного вида перед отправкой его стиля. ACK другого редактора и переподключение сбрасывают локальную отметку актуальности физического объекта; следующая правка сначала восстанавливает выбранный в этой вкладке вид. Это не механизм совместного редактирования: у физического LCD один текущий объект предпросмотра.

## Проверки

| Проверка | Результат |
|---|---|
| JS | 184 теста PASS, включая `%`, ожидание последнего типа, проверку id/ABI, отмену и замену другим редактором |
| Нативный LVGL | StyleRuntime и ScreenRuntime PASS; все 12 классов компонента, сохранение стиля, отказ с откатом и удаление внешнего родителя |
| Frontend | Production build PASS |
| S3 | Release build PASS; записано только приложение от `0x10000`, hash проверен esptool |
| Настоящие экраны | Все шесть MVP + 20 замен; неверный ABI намеренно отклонён; перезапуска во время прогона не было |
| Настоящие компоненты | Все 12 типов и возврат label → slider; ACK содержит фактические bounds после LVGL layout и счётчик отрисованных кадров |
| Браузер → МК | Переключатель «Вид» создал slider через реальный сайт устройства; статус «МК создал slider», кадр 2550 |

Пример readback при смене классов: у label `[132,135,96,98]`, у slider `[132,135,260,98]`. Сохранены X/Y и минимальная высота из редактируемого именованного стиля; собственный размер класса может различаться. Это также показывает, почему CSS-приближение не обещает точного воспроизведения темы LVGL.

Серийный порт и MAC повторно сверялись перед записью: COMx, `02:00:00:00:00:01`. Префикс таблицы разделов совпал с собранным; дополнение считанного сектора — `0xFF`. До первой записи сохранено прежнее приложение, SHA-256 совпал с предыдущим deployment manifest. Многоблочное чтение USB обрывалось, резервная копия получена чтением отдельных секторов. Bootloader, таблица разделов и NVS не перепрошивались; другая плата не затрагивалась.

Логи и данные находятся в игнорируемом `local/`: `component-preview-native-final.log`, `screen-layout-js-tests.log`, `screen-hardware-smoke.json`, `component-preview-hardware.json`, `component-preview-final-flash.log`, `component-preview-info-final.json`. Аппаратные прогоны исполнялись на этом же C++ ядре; последующие записи обновляли встроенный сайт. `screen_received/applied` в стенде учитывают общую очередь экранов и отдельных компонентов; одно отклонение в тестовом прогоне вызвано намеренно неверным ABI.

Реальный адрес устройства: `http://192.0.2.1/`. Портал содержит ссылки на локальный редактор и S3. `LV_USE_OBJ_PROPERTY_NAME` выключен, биндинги не реализованы; INFO возвращает обе capability как false. Проверены протокол, объекты LVGL и вызов refresh; снимки ниже показывают веб-интерфейс, а не фотографию физического LCD. Визуальную точность всех виджетов и длительную стабильность панели не заявляем.
