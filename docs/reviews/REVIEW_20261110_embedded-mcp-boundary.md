# Удаление посредников MCP и граница target

Дата: 10.11.2026. По прямому указанию владельца удалены отдельные MCP-посредники
на ПК. В руководствах убраны команды их установки/запуска, конфигурации клиентов,
перенаправление телефона на такой посредник и действующие ссылки на его исходники.

MCP должен работать непосредственно в выбранной демке или прошивке поверх
NaWServer и общих ProjectService/DataRegistry/StyleService. На момент этой правки
встроенный endpoint ещё не реализован. HTTP/WS API, просмотр и общий редактор
продолжают быть самостоятельными интерфейсами и не объявляются MCP сервером.
HTTP MCP-клиент SPLA в MAUI остаётся клиентом совместимого target.

Датированные результаты прежних MCP-проверок помечены как история удалённых
посредников. Они не являются инструкцией повторного запуска или приёмкой нового
встроенного MCP. Прежние ADR не переписаны; относящаяся к посредникам часть
заменена [новым решением](../adr/ADR_20261110_embedded-mcp-only.md).

SeMaps MCP в текущем наборе инструментов отсутствует. Registry/views вручную
не менялись; [руководство карты](../readme_semaps.ru.md) явно отмечает, что старые
описания узлов обновлены через MCP SeMaps; semaps check прошёл.
Новая аппаратная или native MCP-приёмка этой документационной правкой не заявляется.

## Выполненные проверки

Windows MAUI Debug (.NET 10): сборка без ошибок/предупреждений.
SPLA Core tests: PASS, HTTP client/orchestration/queue/Markdown сохранены.
Frontend build, contract:check: PASS. JS suite: 358/358 PASS, включая запрет
возврата внешнего MCP adapter и его launch configs. Шесть native API/runtime
регрессий переведены на shared direct clients и прошли. Процессы посредников
остановлены; listeners на прежних портах отсутствуют. Плата этим удалением
не прошивалась, ранее сохранённый Setup остаётся на устройстве.
