# OpenRouter: реальное соединение и ограничение бесплатного провайдера

Проверка 08.11.2026 выполнена из запущенной Windows-демки через обычные
DataRegistry/CBOR команды. Ключ не извлекался и не передавался в тестовые файлы.

`google/gemma-4-31b-it:free` возвращала HTTP 429. Точная диагностика провайдера:
`temporarily rate-limited upstream`, Google AI Studio,
`limit_source=upstream_provider_shared_pool`. Это отказ общего бесплатного пула,
а не отсутствие соединения с OpenRouter и не ошибка ключа.

Диагностика теперь извлекает только текст причины из `error.metadata.raw`
(обычный текст либо JSON error.message), имя провайдера, limit_source и числовой
Retry-After. Полный metadata/body не публикуется, ключ скрывается до ограничения
сообщения прежними 512 UTF-8 байтами. Проверены plaintext/JSON raw, redaction,
игнорирование остальных metadata и Retry-After: assistant unit **24/24 PASS**.

Для рабочего варианта выбрана и сохранена
`nvidia/nemotron-3.5-super-vl:free`, поддерживающая инструменты и изображения.
Реальный контрольный запрос с PNG красного квадрата прошёл через тот же
chunked CBOR upload → HostAgent → OpenRouter; модель ответила «Красный».
Free-only и provider.max_price=0 оставлены включёнными. Автоматического
переключения на платную модель или скрытых повторных запросов не добавлено.
Доступность внешних бесплатных моделей меняется; результаты относятся к этой
приёмке. Настройки провайдера, ключ и пользовательский проект не публикуются.
