  исполняет action через существующий API, получает настоящий кадр. На тестовом
  кадре обнаружены 91 182 пурпурных пикселя; при выключении BMP совпадает с исходным
  побайтово. Геометрия и ревизия проекта не меняются. После refresh режим сохраняется.
- Кадр просмотрен: цифры глубины различимы на светлом и тёмном фоне;
  корень вложенной страницы продолжает нумерацию дерева.
- Запущенный Windows-проигрыватель обновлён. Прежняя выбранная вложенная страница
  восстановлена штатным навигационным событием MCP, размер окна восстановлен,
  ревизия сохранённого проекта осталась прежней. Диагностика оставлена выключенной.
- Проверены Uncrustify 0.83.0_f для затронутых C/C++ и `git diff --check`.
- SeMaps e_runtime обновлён через MCP, модель сохранена; `semaps check` без замечаний.

В сборке присутствовали предупреждения прежнего общего sample_image.hpp о

Физические платы и монохромный/RGB565 дисплей не проверялись и не прошивались.

Ограничения приоритетов обычных LVGL-стилей, перекрытия объектов, фоновых изображений

## Галочка в MAUI-предпросмотре

Добавлена по уточнению владельца в заголовок предпросмотра, рядом с разворачиванием
и обновлением. Проверена в настоящих Windows WebView2 и Android WebView эмулятора:
MCP discovery → SPLA invoke_action → подтверждение исполнения → новый кадр.
Включение в Windows и выключение в Android прошли; обновление читает состояние,
установленное другим клиентом. Размеры и координаты preview-stage в Windows до/после
совпали; Android checkbox виден и заголовок помещается в ширину 412 CSS px.

Сборки Windows и Android x64: 0 ошибок/предупреждений. Core regression: 40 проверок
SPLA/MCP/очереди/Stop/учёта токенов/Markdown прошли. Реальный LLM-запрос для этой
галочки не нужен и не выполнялся. Скриншоты — ignored local/maui_designer/.
MAUI Windows перезапущен после явного разрешения владельца на сброс RAM-истории;
остался один экземпляр. Данные провайдера остались в SecureStorage.

## Копирование кадра и замечание о читаемости

В заголовке MAUI-предпросмотра добавлен самостоятельный значок копирования.
Windows: нажатие в настоящем WebView → системный clipboard содержит bitmap,
его размеры совпали с показанным PNG. Android emulator: нажатие прошло без ошибки,
ClipData с PNG URI создан через штатный MAUI FileProvider, кэш-файл существует;
заголовок с дополнительным значком помещается в 412 CSS px. Сборки Windows и Android
x64 прошли без предупреждений/ошибок. Внешняя вставка на физическом Android не проверялась.

Владелец обнаружил непригодность прозрачного заполнения на настоящем сложном экране.
Это ограничивает раннюю приёмку простого тестового кадра: видимость цифр в простом
примере не доказывала читаемость на произвольной композиции. Прозрачные участки масок
пропускают все паттерны предков, создавая плотное наложение; уменьшение кадра дополнительно
разрушает знакоместо 5×6. По прямому указанию владельца диагностические стили оставлены
без изменений. Предложение, ещё НЕ реализация: только outline для просмотра исходного
дизайна; отдельный режим разбора дерева с непрозрачным фоном, контрастной технической
палитрой и более крупными/редкими цифрами. Фон bg_opa/bg_color штатный и не меняет layout.

Финальный APK Android ARM64 также собран без предупреждений/ошибок; ARM64 и x64
копии для установки обновлены в ignored local/maui_designer/release. Физический
телефон этим не считается проверенным.

## 16×16 A1 и независимые параметры

После уточнения владельца реализованы прозрачные 16×16 A1-тайлы, цифры 10×12,
отдельные обводки/цифры, opacity и индивидуальные глубины. Старое описание A8/8×8
выше относится к предыдущей итерации. Размер новых масок ровно 320 байт (static_assert),
дескрипторы/стили/LVGL runtime отдельно; внутренний декодер не менялся и не профилировался.

Native composition/screen/project tests прошли. Сквозной MCP/NaWServer тест подтвердил
реальную отрисовку A1, независимые режимы, выбранную глубину, opacity=0, пустой набор,
refresh и точное восстановление BMP без изменения ревизии. Windows и Android x64
собраны без предупреждений/ошибок; native Windows сохранил прежнее предупреждение
sample_image.hpp. В живом Windows UI выбраны outlines=true, digits=true, opacity=128,
allDepths=false, depths=[2]; чтение через MCP подтвердило те же параметры. В Android
панель открыта, прочитала состояние с Windows и просмотрена визуально. Сдвига
геометрии preview-stage нет. Canvas и ревизия проекта сохранены при обновлении.

Новый источник не добавлялся: прежний ui.layout_debug стал объектом, action с bool
сохранилась; action ui.layout_debug_options использует обычную схему реестра. Лимит
32 источника не повышался. Публичный API/кодеки не получили отдельный сетевой стек.
Снимки и данные среды — только ignored local/. МК не прошивались.

Финальная сборка Android ARM64 также завершилась без предупреждений/ошибок; установочные ARM64/x64 APK и manifest SHA256 обновлены в ignored local/maui_designer/release. Проверена Android-запись: глубина 3 включилась и выключилась, итоговый набор [2] подтверждён MCP; панель целиком помещается в viewport.

## Два постоянных ряда, независимые цвета и толщина

По исправлению владельца убраны меню и общие галочки. Теперь постоянно видны два
выровненных ряда уровней/цветовых квадратиков: обводки и цифры. Цвета независимы
между типами и глубинами, по умолчанию КОЖЗГСФ. Толщина настраивается 1–16 px,
по умолчанию 3 px. Маски остались A1/320 байт, стиль ленивый только на активной глубине.

Native tests подтвердили разные цвета outline/bg_image_recolor, толщины 3/5 px,
неизменность геометрии, cache/mount/refresh/teardown. Настоящий MCP/NaWServer тест
проверил независимые цвета и толщину, точное восстановление BMP и ревизию проекта.
В Windows UI установлены разные наборы: outlines [4,5], digits [5,6], зелёная обводка
и красные цифры уровня 5, толщина 5; MCP подтвердил значения. Координаты/размер
preview-stage до/после совпали. Затем возвращены исходный уровень 5, палитра и 3 px.
Страница «Пульт» и сохранённая ревизия проекта восстановлены после обновления.
Windows/Android x64 сборки прошли без предупреждений/ошибок; интерфейсы просмотрены.

Отдельный read-only repro на скрытом target подтвердил выход крайнего тайла за
метку 37×29: 126 пикселей внутри, 76 снаружи bounds. Причина — A8 fast path LVGL 9.6,
игнорирующий clipped_img_area. Vendor LVGL и polygon_button не изменялись.
Отсутствие цифр на фигурных кнопках объяснено: их общий native renderer рисует
собственный векторный путь и поддерживает outline, но не bg_image.

Сырые снимки/параметры — ignored local/. МК и физический Android не затрагивались.

Клиент после подтверждённой команды теперь сохраняет подтверждённые параметры и
обновляет только кадр. Раньше следующее чтение read snapshot могло перезаписать их;
этот лишний путь чтения убран. Подключение и явное обновление по-прежнему читают
актуальные настройки. Windows/Android x64/ARM64 исправленной версии собраны без
предупреждений/ошибок. Текущие пользовательские параметры LVGL target при последнем
обновлении MAUI не сбрасывались. Проект, vendor LVGL и polygon_button не менялись.

По следующему вопросу владельца фактическая Grid/Flex-инспекция и G/F остаются
только анализом: см. PLAN_20261109_layout-inspection.md. Рисование сетки не реализовано.

## Номер / тип и штатный Designer

По уточнению владельца добавлена постоянно видимая строка «Номер / тип»
с независимой галочкой каждой глубины. Она выбирает большую цифру либо большую
G/F, без сочетания двух мелких символов. Обводки, включение меток, RGB и opacity
остаются независимыми. Без Grid/Flex в режиме типа буква отсутствует.

Runtime читает действующее `lv_obj_get_style_layout` только при применении
включённой диагностики. Ленивые стили общие по глубине/фактическому типу.
Две маски добавили 64 байта: всего двенадцать масок A1 = 384 байта данных.
Новых объектов, overlay, draw callback и принудительного layout update нет.

Приложение перенесено целиком в `tools/designer`: App, SPLA Core, тесты, SDK pin,
скрипты сборки/установки и инструкции. Исправлены embedded-resource пути общих
промптов, ссылки руководств и SeMaps через MCP. ApplicationId и SecureStorage
остались прежними; старой исходной директории в examples нет. Временные сборки
и APK — ignored `local/designer`, bin/obj и signing material исключены gitignore.

Проверки:
- Native composition: Grid/Flex/none на одной глубине; разные маски, правильный
  большой глиф, исходный layout сохранён; прежние geometry/cache/refresh проверки прошли.
- Изолированный Windows NaWServer + MCP: передача layoutType, тип вместо номера,
  неизменность geometry/revision, refresh и точное восстановление исходных пикселей.
- SPLA Core: полный существующий набор из 40 утверждений прошёл из нового пути.
- Финальные Windows, Android x64 и ARM64 сборки без warnings/errors. Windows
  запущен; x64 установлен в эмулятор. Переключатель проверен в обоих клиентах,
  включая подтверждённое значение из MCP и возврат в номер. Физический телефон
  этой проверкой не подтверждён.
- Визуальная проверка: три строки совпадают по X checkbox; фиксированные места
  для цифры/G/F, при необходимости горизонтальная прокрутка. На узком экране
  увеличена минимальная высота области предпросмотра после добавления третьего ряда.
- Текущий проект не сохранялся/не менялся; после обновления native возвращены
  выбранная страница и пользовательские параметры. MCU не трогался.

Настоящая grid-сетка и отдельный read-only инспектор не добавлялись; остаются
в плане диагностики. Артефакты проверки и установочные APK сохранены только локально.

## Финальное упрощение: одна общая галочка

Последующее указание владельца заменяет per-depth выбор режима одной галочкой
«Тип вместо номера» рядом с общими настройками толщины/opacity. Отдельный третий
ряд удалён. По уровням остались только «Обводки» и «Метки» со своими RGB.
Режим перенесён из LayoutDebugLevel в LayoutDebugOptions и в корень
ui.layout_debug / ui.layout_debug_options как layoutType. Он действует и на вновь
загруженные страницы. Чтение фактического layout и общие маски не изменились.
Native composition и изолированный Windows NaWServer/MCP тест проходят с новым
общим аргументом, сохраняя геометрию, ревизию проекта и восстановление пикселей.

Финальные сборки Windows/Android x64/ARM64 завершились без предупреждений и ошибок. В Windows и эмуляторе подтверждены ровно два ряда уровней и один общий переключатель. Из Windows выполнено выключение/включение через SPLA/MCP с подтверждением layoutType источником; флаги уровней сохранились. Windows-приложение обновлено и запущено, APK и SHA256 обновлены локально. Документация и SeMaps приведены к общему режиму, проверки карты и diff --check прошли.
