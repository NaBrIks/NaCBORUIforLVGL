# Проверка веб-студии и помощника Windows — 08.11.2026

> Результаты MCP в этом отчёте относятся к прежней реализации.
> Актуальные способы подключения описаны в [руководстве MCP](../readme_mcp.ru.md).


## Результат

Графический `/editor/` содержит «Работа» и «Настройки». В работе строка запроса
на всю ширину находится сверху, настоящий LVGL — снизу. API, ключ, модель,
free-only и текстовый фильтр находятся в настройках. Один контроллер переживает
переход между страницами; новый ключ и черновик запроса не теряются.
Ручной универсальный редактор доступен из настроек отдельной ссылкой.

Процесс имеет видимые этапы и локальный таймер. Для состояния/ошибки заранее
выделена компактная строка: её появление не сдвигает просмотр. Ответ и подробности
открываются по ⓘ; исправлен отсутствовавший glyph этого значка. Ошибка завершения
читается из фактического status после completion, что исключает гонку отдельных
WS-сообщений busy/completion/status. HTTP-код и ограниченная причина провайдера
передаются без полного тела ответа и без ключа.

Каталог модели фильтруется до разбиения на страницы. Каждая выдача ограничена
64 моделями и отдельными бюджетами байтов; `assistant.model_page` сообщает
`{offset,total,shown}`, writable `assistant.model_offset` выбирает следующую часть.
«Назад»/«Далее» доступны через существующий DataRegistry/API. Полные title и ID
выбранной модели видны и копируются; title и ID показаны и в каждом option,
поскольку название провайдера само по себе может не содержать размер модели; отсутствие на текущей странице не выдаётся
за недоступность модели. ID новой конфигурации по умолчанию —
`qwen/qwen3.8-27b:free`; существующий выбор пользователя сохраняется.

Host сообщает промежуточные этапы по прежнему private CBOR bridge. Progress не
удаляет pending job, не увеличивает completion generation и не выдаёт операцию
за завершённую. Подтверждение cancel не снимает busy, пока исходный job не закончен.
Фактические значения и ошибки идут в браузер по существующему CBOR WS.

Общие инструкции и описания MCP-инструментов находятся на host. На runtime
остаются актуальные capabilities, каталог и проект; устройство не хранит весь
справочник для модели. См. [разделение знаний](../readme_graphics.ru.md#как-агент-получает-знания).
«Справочник C API LVGL» — генерируемые C-сигнатуры закреплённой библиотеки,
не список HTTP/MCP-вызовов приложения.

## Сохранность проекта

Windows-обёртка над FileProjectStore сохраняет compiled базу по её revision.
После обновления authored JSON эффективный пользовательский проект переносится
тем же ProjectService; его документы и revision сохраняются точно. Durable changes
публикуются после успешной загрузки LVGL-экрана. Старый store без cache допускает
однократную точную `--base-recovery`; ошибочная база не сбрасывает изменения.
Нативная проверка base fingerprint не ослаблена. Это дисковая host-функция,
не кэш экранных экземпляров и не изменение памяти микроконтроллера.

## Ограничения

Текущий вид экрана передаётся bounded BMP до пяти кадров/с, а не видеокодеком
или WebAssembly. Это online-зеркало настоящего Windows LVGL; ввод pointer
обрабатывает тот же runtime. Для МК протокол передачи изображения и agent host
требуют отдельного выбора. Каталог реальных данных уже выбирается на API,
части capabilities пока фильтруются host после полного получения capabilities.
Доступность и качество внешней модели зависят от провайдера; free-only не
подменяет отсутствующую модель платной.

## Уточнение: меню, изображения и маршрутизация провайдера

Вернуто постоянное левое меню с двумя пунктами «Работа» / «Настройки» на общей
app-shell/sidebar. Prompt многострочный, Enter добавляет строку, Ctrl+Enter
отправляет. Изображения вставляются из буфера или выбираются файлом; есть
миниатюры и удаление, черновики переживают переключение страниц. Ошибки имеют
переносы без многоточия в заранее предусмотренных трёх строках с внутренней
прокруткой. Preview не сдвигается от сообщения.

Изображения передаются существующими DataRegistry actions и CBOR API частями
по 2048 base64 символов; общие HTTP/registry лимиты не увеличены. Данные находятся
в ограниченном private HostAgent buffer, затем в multimodal user content
image_url; в проект, DPAPI config, snapshots и WS содержимое изображений не входит.
До четырёх изображений, по 96 KiB после обработки, длинная сторона до 1024 px.
Модель с известным текстовым входом отвергается до completion. См.
[путь изображений и проверки](../readme_display_feedback.ru.md).

Причина проверенного HTTP 404: при provider.require_parameters=true передавался
неподдерживаемый parallel_tool_calls=false. Параметр удалён; локальное выполнение
инструментов остаётся последовательным. Free-only проверка и max_price=0 сохранены.
Реальный бесплатный контрольный запрос через запущенное приложение завершился
ответом OK; прежний prompt восстановлен, проект и выбранная модель сохранены.
