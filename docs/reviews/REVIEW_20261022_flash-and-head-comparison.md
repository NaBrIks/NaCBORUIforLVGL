# Прошивка S3 и сравнение с HEAD — 2026-10-22

База сравнения: `5370cf9ae2fb2bbe60cb12843523d10737187516` (`Initial commit`). Текущий вариант — рабочее дерево с экранным ABI v3, стилями v2 и регистрацией пользовательских компонентов во время работы. Это сравнение всего рабочего дерева с HEAD, не только последней правки.

## Сборки и размер

HEAD экспортирован в `local/compare/lvgl-cbor`, собран со своими web-assets. Обе сборки используют одинаковые зависимости, toolchain, LVGL 9.6.0 и sdkconfig (различий наборов строк не найдено). Старая прошивка на устройство не записывалась.

| Показатель, байт | HEAD | Текущий | Изменение |
|---|---:|---:|---:|
| Flash, отчёт PlatformIO | 1 476 592 | 1 450 216 | −26 376 (−1,79%) |
| Файл firmware.bin | 1 476 992 | 1 450 624 | −26 368 |
| Статическая RAM | 140 512 | 140 584 | +72 |
| Код и rodata из liblvgl-cbor.a | 87 415 | 66 619 | −20 796 (−23,79%) |
| Таблицы диспетчеризации | 4 648 | 552 | −4 096 (−88,12%) |
| Встроенные сжатые HTTP assets | 139 750 | 141 105 | +1 355 |

Вклад библиотеки рассчитан по входным секциям linker map без отладочных секций и выравнивания. Это не размер всей прошивки. Таблицы измерены по ELF-символам: раньше 3 864 байта описателей стилей, 640 байт описателей методов компонентов и 144 байта таблицы классов; теперь 552 байта указателей стилей. Диспетчеризация компонентов осталась в машинном коде switch, её стоимость не равна нулю. Сам `style_dispatch.cpp.o` сократился с 20 445 до 7 553 байт кода и rodata (−63,1%).

## Исходники и сложность

Размер текста нормализован к LF. Строки кода посчитаны без пустых строк и комментариев; это не метрика цикломатической сложности.

| Группа | HEAD | Текущий |
|---|---:|---:|
| Ручной C++ ядра, байт | 57 150 | 56 534 |
| Ручной C++ ядра, строки кода | 1 516 | 1 493 |
| Сгенерированные style_methods.inc + widget_methods.inc, байт | 60 012 | 16 806 |
| Ручной C++ демонстрационной прошивки, байт | 25 453 | 26 951 |
| Ручной JS кодеков ПК, байт | 29 280 | 35 717 |

Ручной C++ ядра почти не уменьшился; вместе с демо вырос на 882 байта (+1,07%). Сгенерированная диспетчеризация уменьшилась на 72%. Демо получило адаптацию предпросмотра к потоку команд, кодеки ПК — дополнительную обработку и проверки.

Раньше исполнитель хранил описатели с сигнатурами, типами аргументов, именами, валидаторами и фазами; предварительно собирал WidgetCall и универсальные WidgetArguments, проверял допустимость операций и layout на МК. Теперь стили вызываются через массивы указателей по сигнатурам, обработчик компонента выбирается при создании, а вложенные команды исполняются по курсору. Универсальные модели вызовов и векторы предварительно разобранных команд удалены. Семантические проверки и порядок операций формирует ПК. На МК остаются ограничения парсинга, ABI, ресурсов и памяти.

Появилась runtime-регистрация пользовательских нативных компонентов. Управление временем жизни объектов, строк, точек, ресурсов и откат при ошибке по-прежнему нужны. Поэтому сокращение промежуточных стадий не означает пропорциональное сокращение всех исходников. Скорость и динамическая heap-память в парном эксперименте не измерялись; численного ускорения или экономии heap этот отчёт не утверждает.

## Запись и проверка устройства

Перед записью заново определены COMx, ESP32-S3 rev v0.2, MAC `02:00:00:00:00:01`, flash 16 MB. Прочитанная таблица разделов совпала с собранной; приложение начинается с `0x10000`, слот `0x500000` байт. Записано только приложение, bootloader, таблица разделов и NVS не перезаписывались. Esptool подтвердил hash данных.

Текущий firmware.bin: 1 450 624 байта, SHA-256 `3545722df80a7dd50bdc575e46207980467e1fcf04f83d6ca3c4ddb3bba42a4c`.

После перезапуска устройство доступно по http://192.0.2.1, LVGL 9.6.0, экранный ABI 3, стиль ABI 2. Проверены 14 переключений компонентов и 26 загрузок/замен экранов; один пакет с неверным ABI ожидаемо отклонён. Перезагрузок в ходе smoke не было. Все три HTTP assets побайтно совпали с текущей сборкой.

Физическое изображение LCD в этой проверке визуально не оценивалось.
