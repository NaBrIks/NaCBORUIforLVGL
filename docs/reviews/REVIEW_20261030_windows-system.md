# Windows-демка: реальные CPU, RAM и GPU, 2026-10-30

По поручению владельца Windows/LilyGO с общей документацией сначала сохранены
в коммите `87e5028` и отправлены в `origin/master`. Затем Windows-пример расширен
системным обзором. Прошивки и платы на этом этапе не использовались.

## Реализация и границы

- Один прикладной адаптер SystemMetrics: PDH собирает CPU/GPU и память GPU,
  GlobalMemoryStatusEx — физическую RAM, DXGI — имена/ёмкость адаптеров.
- Четыре фиксированных типизированных источника. Один фоновый сборщик, один
  заменяемый снимок. Только UI-поток публикует CBOR в общий DataRegistry.
- По 32 отсчёта истории, начальные/недоступные отсчёты — разрывы. История
  накапливается вне экрана, выключение генератора скорости её не останавливает.
- Обычная вложенная JSON-страница, четыре нижних пункта навигации. Компоновка
  встроенной демки подстраивается под обнаруженное число процессоров/адаптеров.
- Один необязательный native-компонент `demo:history_plot`, метод `series` с
  ограниченными `{label, history}`. Метаданные и CBOR проходят существующий
  каталог и диспетчер. Ядро, ABI, редактор, LilyGO и общие модули не расширялись.
- SDK Windows даёт `pdh` и `dxgi`; новых пакетов, WMI или vendor SDK нет.

Общая CPU — `% Processor Time`, а не частотно-взвешенная Processor Utility.
Процессоры логические, включая SMT, сортировка числовая по группе/индексу.
GPU: сумма процессов одного физического движка, затем максимум по движкам;
параллельные движки не суммируются. Выделенная/общая память — всего адаптера,
ёмкость — DXGI, не процессный бюджет. Shared GPU memory уже входит в RAM.

Лимиты примера: до 64 логических процессоров и четырёх аппаратных GPU; общая
CPU учитывает всё устройство, а `count`/`displayed` показывают ограничение списка.
Для больших топологий есть локальная прокрутка. Горячее изменение топологии
требует перезапуска. Массив одного PDH-счётчика ограничен 4 МиБ, не более трёх
попыток чтения при изменении списка процессов. Частота номинально 1 Гц.

## Подтверждённая приёмка

- Release-сборка на настоящем LVGL 9.6.0 — PASS.
- Настоящий компьютер: **32 логических процессора, два GPU**. У всех процессоров
  приходят показания, у обоих GPU — загрузка, выделенная и общая память.
- Все 32 отсчёта общей CPU получены реальным сбором; история увеличивается при
  открытых Настройках и остановленном demo.running.
- CPU/RAM в диапазонах; used + available = total, RAM % соответствует байтам.
- Ошибок биндингов и потерь очереди нет. Источники доступны через общий каталог.
- Четыре схемы сохраняют экземпляр и геометрию; линии читают соответствующие
  цвета из общих стилей. Все видимые компоненты 32/2 внутри 800×408.
- Недоступные отсчёты дают пустой график с сеткой, без сдвига геометрии.
  Неверное значение 101% отвергается, предыдущая страница сохраняется.
- Подписи всех процессоров при 100.0% не переносятся, геометрия постоянна.
- Скрытая интеграционная проверка прежних 12 типов, событий, writeback,
  вложенности, JSON/CBOR, повторного открытия и сохранения схемы — PASS.
- Общие JS-тесты: **309/309**; `contract:check` — PASS, ABI без изменений.
  Компиляция топологий 0/0, 32/2 и 64/4 укладывается в существующие лимиты.
- Production-сборка браузерного редактора — PASS.
- Новая Release EXE установлена и запущена обычным launcher без активации окна;
  проверено совпадение хеша сборки/установки и сообщение успешной загрузки.
  Существующий пользовательский выбор схемы сохранён.
- Описание Windows-модуля в SeMaps обновлено через настоящий MCP, сохранение
  подтверждено; `semaps check` — без замечаний. Геометрия карты не менялась;
  новый рендер карты не получен: MCP требует открытый редактор SeMaps.
- Программные события остаются внутри LVGL. OS-клавиатура, мышь и активация
  пользовательских окон не использовались.

В ходе визуальной приёмки исправлены перенос подписей небольших графиков,
отсутствующие символы компактного шрифта и обрезанная строка памяти GPU.
Сверены настоящие LVGL-снимки: CPU/RAM/GPU и все 32 мини-графика видны совместно.
Выбор GPU по LUID сделан без учёта регистра: PDH и DXGI используют разный регистр
шестнадцатеричных цифр. Отсутствие значения остаётся отличимым от нулевой нагрузки.

Команды: `npm test`, `npm run contract:check`, `npm run player:test`,
`npm run player:test-system`. Последняя проверка может принимать путь к Release
EXE и `--require-gpu`, чтобы отдельно требовать наличие GPU-счётчиков.
Измерения, реальные имена адаптеров и снимки окружения остаются в ignored
`local/windows-system`, сборочные и диагностические журналы также не публикуются.
