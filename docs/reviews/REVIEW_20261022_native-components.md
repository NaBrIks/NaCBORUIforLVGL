# Проверка трёх именованных нативных компонентов — 2026-10-22

Историческая проверка первой версии с составными панелями. После просмотра фотографии владелец уточнил требование к сложной собственной графике. Текущие примеры: `lab:signal`, `lab:speedometer`, `lab:radar`; см. [новую проверку](REVIEW_20261022_native-graphics.md). Приведённые ниже размеры, SHA и фотография относятся к первой версии.

Запрос владельца: три разных компонента с обработчиками, обнаружение и вставка из браузера по каталогу S3, вывод на LCD и фотография. Изменения не закоммичены и не опубликованы в Git.

## Реализация

`lab:signal` (256, `signal-1`), `lab:reservoir` (257, `reservoir-1`), `lab:process` (258, `process-1`). Каталог и фабрики находятся в `examples/s3_style_lab/main/native_widgets/`. Примеры регистрируются приложением через общий runtime-реестр; у каждого экземпляра собственное состояние и внутреннее дерево LVGL.

Общий экранный ABI v3 и стилевой ABI v2 не менялись. На МК нет новых таблиц методов или разбора JSON-схем: выбранный обработчик читает скаляр, кортеж либо массив вложенных кортежей непосредственно из CBOR. Метаданные предназначены компилятору/редактору на ПК.

В браузере имена, подписи, ABI, ID и параметры методов взяты из `/api/capabilities` платы. Добавлены универсальные визуальные поля аргументов, рамка нативного компонента с размером и сохранение каталога для офлайн-восстановления черновика. Отправка всё равно проверяет актуальные capabilities. Визуальная проверка обнаружила растяжение категории длинным текстом; исправлено. Поля стадий и все числа видны без горизонтального сдвига нативной категории при её ширине 433 px.

## Плата и прошивка

Повторно определены COMx, ESP32-S3 rev0.2, MAC `02:00:00:00:00:01`, Flash 16 MB и PSRAM 8 MB. Живая таблица разделов считана и сравнена с текущей сборкой, включая хвост `0xFF`. Записано только приложение с `0x10000`, hash проверен esptool.

Финальный BIN: **1 479 200 B**, SHA-256 `634ab1102217120e9da3aca8f80ccdc923d63a912ae2807e235bf47678656c68`.

| Метрика | До этой задачи | С тремя компонентами и UI |
|---|---:|---:|
| Flash по PlatformIO | 1 465 392 B | 1 478 796 B |
| Статическая RAM по PlatformIO | 140 584 B | 141 144 B |
| Web-assets, gzip во Flash | 155 901 B | 159 642 B |
| Web-assets, исходные байты | 444 026 B | 455 516 B |

Это сравнение двух локальных сборок текущей ветки, а не HEAD. Динамическая память отдельных фабрик здесь не измерялась.

После финальной прошивки IP `192.0.2.1`, boot ID `s3-2c0a2147`. `check_embedded_assets.mjs`: все **8** отдаваемых файлов побайтно совпали с `frontend/dist`.

`native_widget_hardware.mjs`: **24 варианта + финальная демонстрация** через настоящий HTTP/capabilities/CBOR WebSocket; менялись все состояния лампы, диапазон/уровень/тревога прибора, общий режим и параметры каждой стадии. Перезапусков не было. Финальный ACK: 5 узлов описания, 5 стилей, 40 операций, границы 800×480. Внутренние нативные дети не входят в счётчик узлов описания.

## Проверка через браузер и LCD

На `127.0.0.1:5298` проверены получение трёх имён с платы, вставка каждого компонента, выбор enum, редактирование кортежа и вложенных bool/чисел, отклонение `min > max` и прогресса 101%, восстановление экрана после reload. JSON импортирован в новый тестовый экран; прежние документы сохранены. Экран применён на МК через кнопку редактора.

Из UI сохранён `native_components.cbor` (**693 B**); затем он загружен в отдельный новый экран редактора, открытого **непосредственно с S3**. Применение подтверждено ACK «5 объектов, 40 операций». В консоли обоих редакторов нет warnings/errors. Каталог методов и рамки видны в production-редакторе с платы.
