# Подключения Designer: API устройства, MCP и USB

Основной режим — **Прямой API**. Designer работает самостоятельно на Windows
и Android; Node.js на целевом телефоне/ПК для выполнения инструментов не нужен.
Чат, очередь, история, работа с моделью и исполнение инструментов остаются SPLA.

| Режим | Адрес | Где исполняются инструменты |
| --- | --- | --- |
| Прямой API | Origin устройства, например `http://127.0.0.1:5301` | В Designer, через общие JS-кодеки и HTTP/CBOR API |
| MCP устройства | Полный URL `/mcp` целевой программы | Внутри выбранной прошивки/демки на NaWServer |
| MCP-прокси | Полный URL явно выбранного совместимого MCP endpoint | На внешнем сервере, выбранном владельцем |
| USB (Windows) | COM-порт T-Display-S3 | Живой кадр и управление указателем через штатный USB CDC прошивки |

Адреса режимов сохраняются раздельно. Выбор режима не запускает сервер/процесс
и не создаёт посредника. Ошибка подключения не переключает транспорт молча.
Ключ модели по-прежнему хранится в SecureStorage, а не в проекте устройства.

## Вкладки настроек

«Модель» содержит провайдера, адрес API, ключ и выбор модели. «Устройства» —
каталог точек, режимы и адреса. На вкладке «Язык» выбор применяется сразу.
Кнопка сохранения модели или подключений действует только на текущую
вкладку и оставляет настройки открытыми; результат показан в строке диагностики.
Черновик другой вкладки сохраняется при переключении. «Закрыть» отбрасывает
оставшиеся несохранённые правки.

Сохранение модели не переключает устройство и не требует его переподключения;
если переподключение уже требовалось, это состояние не сбрасывается.
Сохранение устройств не меняет ключ/провайдера/модель и не запрашивает каталог LLM.

## Каталог точек

Настройки содержат таблицу «Имя / Режим / Адрес». `＋` добавляет пустую точку,
`⧉` копирует выбранную, `×` удаляет запись из каталога; последнюю удалить нельзя.
Имя, режим и адрес редактируются ниже таблицы. Все изменения пока локальны для
открытых настроек: «Закрыть» отменяет несохранённое, «Сохранить подключения» записывает каталог.

У каждой записи стабильный ID и собственные адреса трёх режимов. Таблица в
настройках выбирает строку для редактирования; сохранение каталога оставляет
активное подключение прежним, пока его запись существует. Если активную запись
удалили, выбирается оставшаяся и требуется переподключение.

Основную активную точку выбирают в выпадающем списке верхней строки.
Соседняя кнопка показывает состояние и запускает подключение. Такой выбор сохраняется сразу, очищает кадр старой точки и помечает
соединение для переподключения. Автоподключения нет: после выбора нужно нажать
«Подключить». Пока требуется переподключение, имя нового профиля не показывается
как имя работающего соединения. Старое одиночное подключение автоматически
переносится в первую запись, адреса сохраняются.

Каталог и выбранная запись хранятся в Preferences Windows/Android. Ключ модели
по-прежнему только в SecureStorage; провайдер и модель общие для каталога.
Удаление записи никак не удаляет страницы или данные самого устройства.

## T-Display-S3 по USB

В каталоге Windows Designer есть профиль T-Display-S3. В «Настройки →
Устройства» укажите его COM-порт и сохраните, затем выберите профиль в верхней
строке и нажмите «Подключить». Используется существующая автономная прошивка
с `inspect` и `frame_band`. Designer проверяет её ответ 320×170, PARTIAL,
RGB565. Кадр собирается из полос LVF1 на ПК, по одной полосе за запрос.
На прошивке с `view_state` Designer автоматически проверяет смену страницы и
обычные обновления LVGL через открытый USB-порт. Для одного экрана он
запрашивает только полосы, отмеченные PARTIAL flush после предыдущего
обновления. При смене страницы приходит полный кадр поверх предыдущего. Кнопка ↻ принудительно обновляет кадр.
Галочка «Управление» передаёт нажатия и отпускания в LVGL через `view_input`.
На прежней прошивке остаётся ручное обновление. USB-профиль предназначен для
просмотра и управления, редактирование проекта идёт через другие подключения.

Сборка T-Display-S3 с `-WebSocket` дополнительно раздаёт предпросмотр по
Wi-Fi через NaWServer. В каталоге заведите отдельный профиль «Прямой API»
с адресом платы. Designer автоматически использует WS для кадров, а
управление работает через общий CBOR API. Правила выбора полос и
восстановления полного кадра общие для WS и USB.

## Прямой API

Общий JS-код `ProjectClient`, `DataClient` и кодеки JSON/CBOR собираются в локальный
ES-модуль приложения. Он выполняется внутри BlazorWebView, а не в Node.js.
Сетевые запросы передаются HttpClient самого Designer. Это не CORS-прокси и не
новый listener: запрос уходит прямо в выбранный origin устройства.

Модель получает описания инструментов через SPLA IToolHost. Её JSON проверяется
существующими кодеками, затем устройство получает CBOR. JSON-парсер разметки и
JSON-RPC на микроконтроллере для такого подключения не требуются.
Сохранение и preview остаются отдельными операциями прежнего ProjectService.
Набор данных, действий и пользовательских компонентов берётся из capabilities.

Кадр берётся из реального API дисплея. Если устройство его не объявляет,
Designer сообщает об отсутствии просмотра, не подменяет его CSS-отрисовкой.
После подтверждения изменения диагностики разметки кадр обновляется в фоне:
контролы освобождаются по ACK, одновременно выполняется не более одного чтения
кадра, а повторные запросы сворачиваются до одного последнего. Преобразование
изображения для показа выполняется в приложении; не все платы имеют кадровый endpoint.

## MCP устройства

Опция Windows CMake `LVGL_CBOR_NATIVE_MCP` по умолчанию выключена. При включении
`/mcp` обслуживается тем же NaWServer внутри executable. Внешнего сервера нет.
Выключение исключает MCP-specific JSON parser, workspace и MCP-код из сборки.
Это proof of concept: цена JSON-RPC и буферов может быть неоправданной на MCU.

Каталог инструментов описывает фактические возможности конкретного endpoint.
Наличие MCP не обещает JSON-authoring компилятор на МК. В Windows PoC проверяются
metadata/catalog/data/actions и реальный кадр; отсутствующие операции не должны
рекламироваться как поддерживаемые.

## MCP-прокси

Это второй профиль адреса для того же HTTP MCP-клиента SPLA. Designer подключается
к совместимому endpoint, который владелец настроил явно. Режим не устанавливает
и не запускает такой сервер. Удалённые Node.js/MCP SDK мосты не возвращаются.

## Сборка

`npm run designer:tools` создаёт локальный модуль из общих исходников. Node.js/Vite
используются только на компьютере сборки. Полученное приложение выполняет кодеки
локально, без Node и без второго runtime отрисовки. Сборочные файлы и приватные
результаты проверок находятся в ignored `local/`.

Решение: [ADR](adr/ADR_20261110_designer-three-connection-modes.md).

Приёмка Windows и каталога: [отчёт](reviews/REVIEW_20261110_designer-three-modes.md).

## Проверенный S3

Для 7-дюймового S3 проверен режим Direct API: общий реестр диагностики, управление
рамками/метками из Designer и настоящий BMP16 RGB565 кадр с платы. Встроенный
редактор S3 расположен в корне адреса устройства `/`; `/editor/` — маршрут
Windows-демки. Страница и кадр обслуживаются самим NaWServer в прошивке.

Подробности и ограничения частоты/памяти: [аппаратный отчёт](reviews/REVIEW_20261110_s3-layout-diagnostics.md).

## Управление из предпросмотра

Флажок управления включён по умолчанию и доступен, когда подключённое
устройство объявляет `send_view_input` и известны размеры дисплея. Windows и S3 используют штатный LVGL input device:
hit-test, события и биндинги выполняются самим LVGL, без адресного вызова кнопок.

Координаты вычисляются по фактическому изображению с учётом letterbox и
`object-fit: contain`, исходное разрешение берётся из метаданных кадра. Указатель
имеет capture, движения объединяются, отпускание посылается при отмене и потере
фокуса; аппаратный watchdog ограничивает зависшее нажатие. Ввод передаётся через
тот же SPLA `IToolHost` и capability-gated tool, без дополнительного серверного
или JSON runtime на MCU. После отпускания запускается один фоновый запрос кадра;
постоянного polling нет. Настройки диагностики остаются доступны, пока кадр
обновляется в фоне.

Проверка асинхронных кадров и ввода:
[REVIEW_20261110_async-input.md](reviews/REVIEW_20261110_async-input.md).

Обновление кадра и ручная диагностика доступны во время ответа модели. При
перезапуске устройства старые квитанции команд недействительны; Direct API
сравнивает boot_id и сообщает interrupted вместо подтверждения переиспользованного
номера. Unknown нельзя бесконечно опрашивать или считать доказательством отказа.
Разбор сбоя и ограничения: [отчёт](reviews/REVIEW_20261110_designer-preview-stall.md).
