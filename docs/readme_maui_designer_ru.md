# MAUI-конструктор: SPLA + Windows/Android

[Реальная проверка OpenRouter на Windows/Android и исправление потока UI — 09.11.2026](reviews/REVIEW_20261109_maui-real-chat.md).

Первая версия — приложение MAUI Blazor Hybrid. Интерфейс отображается локально
в BlazorWebView, C#-код работает внутри приложения, а не на веб-сервере.
Историей, запросами OpenAI-compatible/OpenRouter, потоковым ответом, tool loop
и MCP занимается SPLA. Собственные компоненты отвечают за отображение чата,
настройки, выбор файлов и получение кадра через уже обнаруженный MCP-инструмент.
Встроенные три английских файла инструкций взяты из общих оригиналов ссылками.

## Почему такое отображение

В исследованном SPLA нет готовой Razor/MAUI-библиотеки чата. Его ChatSurface,
ChatLog и Composer написаны на Vue и связаны с общим store и сервисным протоколом
SPLA. Avalonia-оболочка тоже показывает веб-интерфейс и запускает CLI-службу.
Подключить эти компоненты непосредственно в Razor без нового слоя сервиса нельзя.

Для первой версии выбран небольшой интерфейс Blazor Hybrid: общая разметка
Windows/Android, Markdown, изображения, многострочный ввод и просмотр дисплея.
Внутренний агент повторно не реализуется: ConversationOrchestrator,
OpenAiCompatibleClient/OpenRouterProvider, McpServerSession и McpProxyTool остаются
из SPLA. Маленький IToolHost adapter только передаёт готовые proxy-инструменты
в готовый orchestrator. Каталог MCP не обрезается второй таблицей разрешений.
Upstream SPLA менять для этой интеграции не требуется.

Для дальнейшего переиспользования интерфейса самим SPLA разумно выделить
Vue ChatSurface в компонент с явными props/events и независимым state adapter.
Это отдельная работа в SPLA; здесь она не выполняется. Пока такая упаковка не
появилась, перенос готового Vue-чата в MAUI потребовал бы нового bridge-протокола.

## Где что работает

| Часть | Место исполнения |
|---|---|
| Разметка чата | Локальный BlazorWebView в Windows/Android |
| История, модель, tool loop, MCP-клиент | SPLA внутри того же приложения |
| Ключ модели | SecureStorage ОС; без ключа в исходниках и обычных настройках |
| API/проект/данные/отрисовка LVGL | Выбранный LVGL target |
| HTTP MCP первой проверки | NaWServer gateway к существующему Windows API |
| Браузерная демка | По-прежнему раздаётся настоящим NaWServer проигрывателя |

Gateway — временный мост прототипа к существующему stdio MCP: Native NaWServer
слушает HTTP, SDK и существующие обработчики инструментов работают через закрытый
канал процесса. Он не добавляет вторую реализацию проекта, кодеков или API.
Отдельный listener необходим: обработчик MCP обращается к синхронному API другого
процесса, поэтому ожидать его в callback того же listener нельзя.

Это пока не автономное подключение телефона к МК: в прошивку новый HTTP MCP
endpoint в этой итерации не добавлялся. Клиент уже принимает произвольный совместимый
Streamable HTTP MCP URL; для прямой работы с МК такой endpoint должен быть у target.
HTTP/SSE/OpenAI-код в приложении — существующий SPLA, свой протокол не написан.

## Запуск и проверка

Команды и зависимости: [tools/designer/README.md](../tools/designer/README.md).
Порты примера: API/редактор 5301, HTTP MCP 5302. Gateway по умолчанию loopback-only.
Android-эмулятор обращается к компьютеру через `10.0.2.2:5302`; телефон по USB может
использовать `adb reverse tcp:5302 tcp:5302` и MCP URL `http://127.0.0.1:5302/mcp`.
Для такого способа не требуется открывать LAN-порт или менять firewall.

Core проверяется с настоящими SPLA transports через ответы HttpMessageHandler
в памяти, без альтернативного HTTP-listener: история двух сообщений, изображения,
каталог моделей, JSON-RPC MCP, вызов инструмента, отмена и отсутствие blobs в логе.
Отдельная live-проверка получает каталог и кадр настоящего Windows LVGL через MCP.
Результат платформенной приёмки хранится в связанном отчёте проверки.

История первой версии живёт в памяти приложения. Перезапуск очищает чат;
настройки соединений сохраняются. Новый чат очищает контекст, но не проект target.
JSON прикладывается как текст к сообщению, картинки — нативные ImageAttachment SPLA.
Preview не является браузерной перерисовкой JSON: это кадр настоящего LVGL через MCP.
Сохранение проекта выполняется только соответствующими инструментами target.

Кнопка остановки отменяет ожидание/генерацию клиента. Уже выполненные операции
на target не откатываются. Если остановка попала на сетевой вызов записи, сервер
может завершить его после отмены клиента: сначала прочитайте текущее состояние,
а не повторяйте изменение вслепую. Автоматического повтора такой записи нет.

[Отчёт проверки Windows/Android и ограничения](reviews/REVIEW_20261108_maui-designer.md).
Сборки, APK, снимки и исходные замеры находятся только в ignored local.


Картинки можно вставлять Ctrl+V прямо в поле запроса; они становятся обычными
вложениями. [Проверка вставки и refresh композиции](reviews/REVIEW_20261109_paste-refresh.md).


## Диагностика компонентов в предпросмотре

Под заголовком постоянно видны два ряда уровней: **Обводки** и **Цифры**, каждый
со своими галочками и цветовыми квадратами. Меню/раскрытия и общие галочки отсутствуют.
Цвета по умолчанию КОЖЗГСФ, раздельно для каждого режима/глубины. Ниже — толщина
обводки (по умолчанию 3 px) и непрозрачность цифр. Тайлы 16×16 A1 общие, 320 байт масок.
UI вызывает обычную action ui.layout_debug_options через SPLA/MCP; проект не меняется.
[Контракт, стоимость и ограничения фигурных компонентов](readme_layout_debug_ru.md).


## Копирование кадра в буфер

Значок двух листов в заголовке предпросмотра копирует **показанный PNG-кадр**,
а не снимок рабочего стола или текстовую ссылку. До получения кадра значок недоступен.
Копирование не делает нового запроса к устройству и не вызывает LLM; размер совпадает
с изображением предпросмотра (текущий MCP feedback — до 1024 px по длинной стороне).
Чтобы скопировать свежий кадр, сначала нажмите обновление.

Windows использует штатные DataPackage.SetBitmap и Clipboard.Flush; изображение
доступно другим приложениям. Android использует ClipData.NewUri и существующий
MAUI FileProvider: два чередующихся PNG-файла в cache/preview-clipboard ограничивают
расход места. Это очищаемый кэш, не проект и не публичные assets. При замене старых
слотов старые URI не являются архивом снимков. Поддержка вставки изображения зависит
от принимающего Android-приложения; физический телефон пока не проверен.

Ошибки показываются через имеющийся индикатор подробностей. Собственные toast/banner
и новые listeners/HTTP API не добавлялись.

Платформенная документация: [Windows SetBitmap](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.datatransfer.datapackage.setbitmap),
[Android copy/paste content URI](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste).

## Поставка приложения

Исходники штатного универсального конструктора находятся в `tools/designer`
(`App` — MAUI Blazor Hybrid, `Core` — интеграция SPLA). Это часть поставки библиотеки,
не пример конкретного устройства. SDK, команды сборки и установки перенесены вместе
с исходниками; идентификатор приложения и SecureStorage не меняются.
В диагностике добавлен одна общая галочка «Тип вместо номера»: большая
цифра либо большая G/F по действующему layout LVGL.

## Таблица диагностики, ширина панелей и RU/EN

Номера глубин показаны единожды в шапке. Под каждой колонкой четыре строки:
Рамка (галочка), RGB рамки, RGB фона, Фон (галочка). `Фон` — диагностическая
прозрачная маска цифры/G/F, исходный фон компонента не заменяется сплошной заливкой.
Общие подписи: G/F, px, α; подробности — в локализованных подсказках. Таблица
помещается в узкую панель для обычного числа уровней; большой набор глубин
прокручивается внутри таблицы, не расширяет окно приложения.

Между чатом и предпросмотром расположен разделитель: перетаскивание, стрелки
Left/Right при фокусе, Home или двойное нажатие возвращают исходное соотношение.
Пропорция сохраняется в Preferences. На узком экране панели располагаются
вертикально; десктопный разделитель скрыт. Он не меняет размер LVGL-дисплея.

Кнопка RU/EN в верхней строке переключает язык без переподключения и сброса
истории/вложений. Выбор сохраняется в Preferences. Стандартные .resx ресурсы:
App/Resources/Strings.resx (EN) и Strings.ru.resx (RU), сервис Services/UiText.cs.
Локализованы экран чата, настройки подключения, диагностика, подсказки и обычные
статусы. Тексты пользователя/модели, идентификаторы инструментов и исходные внешние
ошибки не переводятся автоматически. Системные промпты модели остаются английскими.
