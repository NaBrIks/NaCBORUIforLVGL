# Диагностика дерева штатными стилями LVGL

Под заголовком предпросмотра постоянно видна **таблица**. Номера глубин —
один раз в шапке. Четыре строки под ними в точном порядке:

1. Рамка — галочки обводки.
2. RGB рамки — индивидуальные цвета обводок.
3. RGB фона — индивидуальные цвета масок.
4. Фон — галочки масок.

Отдельных повторяющихся номеров рядом с галочками нет. Для обычного количества
уровней таблица компактна; большие наборы прокручиваются внутри своей области.
Цвета по умолчанию КОЖЗГСФ, с повторением палитры после фиолетового.

Рядом с общими настройками одна галочка **G/F**. Выключена — большая цифра
глубины, включена — большая G (Grid) или F (Flex). Без Grid/Flex буквы нет.
`α` — прозрачность диагностического фона, `px` — толщина рамки. Пояснения и
доступные имена локализованы; длинные пояснения только в tooltip.

Ниже — толщина обводки **3 px по умолчанию**, допустимо 1–16 px, и непрозрачность
цифр (0–255, показана процентами). Изменения отправляются после ввода/отпускания,
а не на каждом движении. Нулевой opacity снимает цифровой стиль.

Глубина 0 — корневой LVGL-объект. Учитываются настоящие родители, включая корни
вложенных страниц и внутренние дочерние объекты виджетов. Скрытые кэшированные
объекты тоже загружены. Список обновляется при получении свежего кадра кнопкой
обновления; новые уровни при явном наборе изначально выключены. Ограничение
публичного массива настроек — 256 уровней, в соответствии с DataRegistry.

Настройки временные, не входят в JSON/CBOR проекта, сохраняются через load/preview/
refresh, но не через перезапуск процесса. После подтверждённого MCP-действия
автоматически приходит новый кадр. При отсутствии соединения/поддержки или во время
ответа модели/изменения параметров контролы недоступны.

## Маски и память

Тайл — штатное LVGL-изображение **A1**, то есть сама однобитная маска: 0 прозрачно,
1 видимо. Цвет задаётся `bg_image_recolor`, общая непрозрачность — `bg_image_opa`.
Промежутки остаются полностью прозрачными. Глухая подложка не добавлялась.

**16×16 / 8 = 32 байта на тайл, десять цифровых тайлов = 320 байт данных масок; G и F добавляют 64 байта, итого 384 байта.**
Размер подтверждён compile-time static_assert. Это не размер всей функции и не
полный расход RAM: отдельно существуют дескрипторы, общие lv_style_t, ссылки у
объектов и небольшой набор выбранных глубин. Внутренние буферы декодирования/кэш
LVGL остаются ответственностью LVGL и в эту цифру не включаются. Они не переписывались
и специально не измерялись по решению владельца.

Все двенадцать масок и дескрипторов статические, общие; отдельная картинка на каждый
компонент не создаётся. На каждый активный уровень лениво создаются общие стили по фактически
встреченным вариантам layout: без раскладки, Grid, Flex, принадлежащий композиции. На выключенных уровнях стиль не создаётся. Рисует штатный LVGL: overlay, draw-callback и таймеров нет.

## Runtime, API и MCP

`ScreenRuntime` / `ProjectService` имеют общий выключатель `set_layout_debug(bool)`
и `set_layout_debug_options(LayoutDebugOptions)`. В options — общий layout_type, opacity, outline_width
и индексированный глубиной массив levels. Каждый элемент содержит outline/digit и
два цвета RGB в uint32_t. Цвета занимают **8 байт на уровень**; флаги, выравнивание,
контейнер, lv_style_t и свойства стилей учитываются отдельно. Маски не копируются.

Общий стиль активного уровня/варианта layout содержит только включённые свойства. При смене
опций старые стили сначала снимаются с живых объектов, затем освобождаются; новые
присоединяются тем же штатным механизмом. Никаких draw callbacks/overlay нет.
`outline_pad=-outline_width` рисует обычный outline внутрь границы без изменения
геометрии. Пользовательские компоненты могут трактовать outline иначе.

В существующем DataRegistry Windows:

- источник `ui.layout_debug`: opacity, outlineWidth, layoutType, levels и maxDepth;
- action `ui.layout_debug_options`: те же настройки без maxDepth;
- action `ui.layout_debug(bool)`: общий выключатель нативного меню; включение
  полностью выключенного набора включает обводки существующих уровней.

Каждый элемент levels (индекс = глубина):

```json
{"outline":true,"digit":false,"outlineColor":16724016,"digitColor":16724016}
```

Общий аргумент action:

```json
{"opacity":192,"outlineWidth":3,"layoutType":false,"levels":[{"outline":true,"digit":false,"outlineColor":16724016,"digitColor":16724016}]}
```

Цвета передаются числовым RGB 0–0xFFFFFF. Дополнительных источников, HTTP handlers,
MCP tools или кодеков нет: MAUI работает через существующий SPLA MCP. Исходный лимит
32 источника не увеличивался. Depth metadata обновляется при захвате кадра, не в
основном цикле рисования LVGL.

## Ограничения

Прозрачные родители просвечивают: одновременное включение многих глубин всё ещё
может создавать наложение. Сдвиги узора по глубине не обещаны: LVGL привязывает
начало тайла к каждому объекту, а не к общей системе координат. Рекомендуется выбрать
одну или несколько интересующих глубин. Обводки можно использовать без цифр.

Диагностический узор временно заменяет обычное фоновое изображение. Локальные свойства,
специфичные стили состояний и нативное рисование могут его перекрыть. Один цвет не
гарантирует контраст на всяком фоне; уменьшение кадра влияет на читаемость.
Объекты, созданные/переподчинённые прикладным кодом позже вне загрузки страниц,
не наблюдаются специальными callbacks: для повторного применения смените настройки.

Native composition/screen/project tests прошли: неизменность координат, размеров
содержимого и прокрутки, независимость режимов, opacity, выбор глубины, новые и
кэшированные страницы, флаг и опции через refresh.

```powershell
node examples/windows_player/test-layout-debug.mjs path/to/nacborui_player.exe
```

Настоящий Windows target на NaWServer и реальный MCP: A1 рисуется, доступны отдельные

в ignored local/. Физический телефон, МК и монохромный экран этой проверкой не заявляются.


## Фигурные кнопки и выход тайла за рамку

Фигурные кнопки пульта — общий native-компонент `examples/common/polygon_button`,
не стандартный lv_button. Форма/вложенность/параметры/события задаются JSON через
общие кодеки и MCP. Его C++ обработчик DRAW_MAIN рисует собственный векторный путь,
использует outline_color/outline_width, но не bg_image_src. Поэтому контур виден,
а цифрового фонового тайла на самой фигуре нет. Это не признак другого уровня.
Рамка такой фигуры идёт по пути; outline_pad не является смещением полигона.

Отдельный изолированный тест подтвердил дефект обрезания LVGL 9.6 software renderer:
при метке 37×29 и A1-тайле 16×16 обнаружено 76 пикселей цифр вне её bounds.
Tiled helper вычисляет clipped_img_area, но быстрый A8-путь img_draw_core использует
полный img_coords, не переданный clipped_img_area. A1 декодируется в A8, поэтому
попадает в эту ветку. Рамка остаётся на реальных границах, крайний тайл выходит
за них. Это не изменение ширины/высоты или padding компонента.

По просьбе владельца здесь дано объяснение; исходники LVGL и polygon_button не
исправлялись. Repro и исходные снимки находятся только в ignored local/layout-tile-repro.

Будущее обозначение G/F и read-only инспекция рассмотрены в [плане](plans/PLAN_20261109_layout-inspection.md); это не текущая реализованная функция.

## Номер или фактический тип раскладки

Общий `layoutType` переключает содержимое всех включённых меток; false —
цифра глубины modulo 10, true — G/F. При применении диагностики runtime читает
`lv_obj_get_style_layout(object, LV_PART_MAIN)`, без предположений по JSON/именам.
Никаких новых объектов, overlay, callbacks или принудительного расчёта layout нет.
Диагностические стили не задают layout. Изменение layout прикладным кодом после
применения не отслеживается отдельным наблюдателем: повторно примените настройки.
Настоящие линии ячеек Grid этим режимом не рисуются.

MAUI перенесён в `tools/designer`: это штатное приложение настройки библиотеки,
а не часть Windows-демки. Общий SPLA Core и платформенное App находятся внутри него.
