# Именованные нативные компоненты

В примере NaCBORUIforLVGL для ESP32-S3 зарегистрированы три примера. Сам исполнитель, реестр, каталог для ПК и браузерные формы остаются отдельными модулями.

| Имя / ID типа | Реализация | Локальные методы |
|---|---|---|
| `lab:signal` / 256 | Лампа и состояние STOP/RUN/WARN/FAULT | 256 `title`: text; 257 `state`: int32, варианты 0…3 |
| `lab:speedometer` / 259 | Собственная графика LVGL Draw: 61 риска, подписи, цветные зоны, треугольная стрелка и цифровое показание | 256 `title`; 257 `range`: [int32,int32]; 258 `reading`: [int32,text]; 259 `redline`: int32 |
| `lab:radar` / 260 | Собственная полярная развёртка, вращающийся луч, след и послесвечение контактов; собственный таймер | 256 `title`; 257 `running`: bool; 258 `targets`: массив 0…8 [text,азимут,дальность%,сигнал%]; 259 `sweep`: 0…359; 260 `range`: км |

Номер типа и локальный номер метода принадлежат разным пространствам. Значение 256 в нескольких обработчиках допустимо. ABI каждого примера: `signal-1`, `speedometer-1`, `radar-1`. Первые составные панели `lab:reservoir` / 257 и `lab:process` / 258 заменены после уточнения владельца: сложность должна быть в собственной графике. Их ID не переиспользованы.

## Каталог с платы и редактор

`GET /api/capabilities` публикует `extensions`: `id`, `name`, `abi`, `contract`. Метод содержит `alias`, `opcode`, `parameters`. Этого достаточно для вызова простого метода. Для составного аргумента нужна форма данных, например массив кортежей. Диапазоны, варианты и порядок setter-ов нужны компилятору на ПК. Они не становятся таблицами диспетчеризации на МК.

Каталог дополнен `title`, `description`, `defaults`, `preview: {width,height}`. Это начальный размер рамки и начальные аргументы при вставке. Размеры не обещают эмуляцию внутренней раскладки LVGL. Редактор не рисует внутренности нативного компонента: показывает подписанную рамку. Общие размеры, положение, стили и флаги корневого объекта доступны как обычно. Примеры рассчитаны на указанные начальные размеры; слишком маленький размер может обрезать внутреннее содержимое.

В редакторе экрана выберите компонент в общем списке над деревом и нажмите `＋`. Все стандартные и нативные типы используют один механизм добавления. Свойства выбранного экземпляра показывают имя, тип аргумента и числовой ID каждого метода. Числа, строки, bool, кортежи и массивы редактируются обычными полями. Ошибка составного значения остаётся рядом с полем; неверное значение не подменяет документ. `×` исключает setter из описания; останется начальное состояние фабрики.

Каталог последней подключённой платы сохраняется в браузере для восстановления собственных черновиков после перезагрузки. Офлайн явно помечен. Экраны с уже недоступным нативным типом сохраняются как неподтверждённые черновики и не сбрасывают остальные экраны. Применение на МК требует актуальных возможностей устройства; старый каталог не подтверждает совместимость. Для импорта JSON/CBOR с ранее неизвестными нативными типами сначала подключите соответствующую плату. Каталог не встроен в файл экрана.

## Код и расширение

- `examples/s3_style_lab/main/native_widgets/catalog.json` — единый источник метаданных. `tools/native_widget_catalog.mjs` создаёт компактный C++ заголовок регистрации.
- `signal.hpp`, `speedometer.hpp`, `radar.hpp` — фабрики, собственные состояния экземпляров и прямые switch-обработчики; `drawing.hpp` — общие примитивы LVGL Draw. Стрелка, риски, луч и сетка не собираются из дочерних стандартных виджетов.
- `registry.cpp` / `registry.hpp` — подключение модуля к `WidgetRegistry` приложения. `-DLVGL_CBOR_DEMO_NATIVE_WIDGETS=0` полностью исключает реализации и их каталог из прошивки; общий реестр остаётся.
- `packages/screen-codec/parameter-schema.js` — общие адаптеры и проверки ПК. Поддерживается ограниченная форма данных: скаляры, кортежи и массивы до 32 элементов, глубина описания до 4. Объекты со свободными ключами и вычисления не добавлялись.
- `frontend/src/modules/native-widgets/` — универсальные формы аргументов и офлайн-каталог. Имена трёх примеров в формулах браузера не зашиты.

При создании исполнитель выбирает фабрику/обработчик один раз. Простые методы используют `invoke_widget`, составной `radar::targets` самостоятельно читает массив вложенных кортежей и выходит через `cbor_value_leave_container`, оставляя курсор после одного аргумента. Никакой JSON-каталог исполнителем не разбирается. Радар обновляет угол через свой LVGL-таймер каждые 100 мс; `running=false` ставит таймер на паузу. Таймер удаляется вместе с экземпляром.

Внутренние LVGL-объекты принадлежат корню компонента; состояние освобождается по `LV_EVENT_DELETE`. Ссылки на аргументы не переживают своего владельца. Лимит числа узлов экрана считает узлы описания, а не внутренние объекты произвольного нативного кода; бюджет такой фабрики остаётся ответственностью приложения.

Runtime-регистрация `add/remove` сохранена. `revision()` позволяет приложению перепубликовать capabilities после изменений в UI-контексте. HTTP читает неизменяемый снимок через `shared_ptr`; живые экземпляры удерживают свою регистрацию после `remove`. Примеры регистрируются при старте; HTTP-загрузчик нативного машинного кода не вводился.

Пример экрана: `examples/native_widget/demo-screen.mjs`. Команда `node tools/native_widget_fixtures.mjs` создаёт готовые `local/native-widget-fixtures/demo.json` и `demo.cbor` для импорта.

## Общий полигональный элемент управления

Опциональный `examples/common/polygon_button` регистрирует `ui:polygon_button`.
В нём нет направлений пульта, ID клавиш или прикладных действий. Метод `points`
принимает 3–128 точек с координатами 0–1000, масштабируемыми к размеру объекта.
Контур хранится в Project JSON/CBOR и редактируется через обычный MCP/catalog.
Общий codec и координатная форма редактора учитывают min/max и cardinality
из metadata любого points-метода, без проверки имени компонента.

Один контур используется для LVGL Vector API и `LV_EVENT_HIT_TEST` с
`LV_OBJ_FLAG_ADV_HITTEST`. Заливка и hit-test используют even-odd правило;
внешние углы и отверстия не принадлежат кнопке. Остальные события, фокус и
состояния наследуются от `lv_button_class`. Обводка фокуса рисуется по тому же
контуру и не увеличивает активную область; outline_pad не смещает путь.
Дочерние объекты не обрезаются полигоном. Скругление сложной границы
описывается точками пути; это не загрузчик произвольного исполняемого кода.
