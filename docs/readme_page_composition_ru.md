# Страницы внутри страниц

## Модель

Описание страницы можно показать отдельно или вставить в контейнер другой страницы. Специальных типов «главная», «дочерняя» или «лист» нет. Стартовая страница задаётся manifest.entry проекта.

Экземпляр страницы содержит собственные LVGL-объекты, биндинги, события и дочерние экземпляры. Родитель владеет временем жизни потомков. При его удалении сначала завершаются дочерние экземпляры, затем сам родитель. Одинаковые локальные имена узлов в двух экземплярах допустимы: объекты различаются экземпляром. В работающей композиции экземпляры имеют числовые идентификаторы; имена страниц и данных остаются символическими.

Общий DataRegistry принадлежит приложению. Все страницы используют объявленные приложением именованные источники и действия. Наличие страницы на дисплее не определяет, должно ли приложение собирать данные или управлять оборудованием.

## Первое значение, пауза и история графика

Источник хранит последний опубликованный снимок. После создания или возобновления экземпляра его биндинги получают актуальные значения: нового внешнего события ждать не требуется. Если значение ещё не получено, показывается неизвестное состояние, например `--`.

Пауза биндинга останавливает обновление конкретного представления. Она не должна автоматически останавливать источник. Например, уход со страницы BLE не выключает сканирование.

Для непрерывного графика источник должен хранить ограниченную историю измерений, например кольцевой буфер, и предоставлять её снимок. Вновь открытая страница восстанавливает график из истории. Если источник предоставляет только последнее значение, восстановить пропущенные точки нельзя. Кэш виджета сам по себе эту задачу не решает: график, который накапливает точки только при вызове UI-setter, не получает их во время паузы. Размер истории, частота измерений и восстановление пропусков принадлежат приложению; универсальная база временных рядов в UI-ядро не добавляется.

## Хранение экземпляров

| Политика | После выбора другой страницы |
|---|---|
| Освобождать | Экземпляр удаляется; при возвращении создаётся заново |
| Кэшировать | Экземпляр приостанавливается и сохраняется в ограниченном кэше; давно неиспользованный может быть удалён |
| Удерживать | Экземпляр приостанавливается и сохраняется до уничтожения владеющей композиции |

Все политики создают страницу по требованию. Удерживание не означает предварительную загрузку всех страниц. Несохранённые пользовательские данные, которые должны пережить удаление экземпляра, хранит приложение.

Пауза распространяется на биндинги, отложенные события и поддерживающие её нативные компоненты. Возобновление применяет текущий снимок данных. События, отложенные до ухода со страницы, не должны исполняться после возвращения.

При явной загрузке или предпросмотре нового проекта старая композиция вместе с кэшем уничтожается целиком. Сложного согласования кэша по ревизиям нет. Само сохранение проекта не переключает отображение: сохраняется существующее разделение preview/save.

## Размеры

Контейнер задаёт доступную область. В режиме заполнения корень вложенной страницы получает эту область; Flex/Grid и размеры её объектов работают обычным образом. В режиме проектного размера сохраняется размер из описания страницы. Масштаб предпросмотра изменяет только изображение в редакторе.

Прокрутка задаётся обычными свойствами и флагами контейнеров. Вложенный просмотр помогает увидеть результат компоновки; отдельная сложная система автоматического исправления переполнения не вводится. Браузерный preview приближённый, особенно для нативной графики; окончательную проверку выполняют на LVGL/МК.

## Настройка в редакторе

В свойствах узла включите **Контейнер страниц**. Добавьте допустимые страницы, выберите для каждой политику хранения, начальную страницу и размер: **По контейнеру** или **Размер документа**. У кнопки в событиях выберите переход к странице этого контейнера. Вкладка получает `CHECKED`, когда её целевая страница выбрана; оформление задаётся обычным правилом стиля состояния.

На странице проекта отображается граф допустимых вставок. В просмотре экрана флажок **Переходы** позволяет переключать вложенные страницы только в браузере. Он не вызывает действия приложения. Флажок **В контейнере** превращает W/H в размер области просмотра, сохраняя проектный размер документа. Это позволяет заранее увидеть обрезание и прокрутку.

Проектный размер хранится в `screen.size.width/height` и передаётся вместе со страницей в JSON/CBOR. При обычном просмотре браузер автоматически использует размер выбранной страницы; изменение её размера обновляет просмотр сразу. В этом режиме W/H редактируют сам документ. Новое поле с разрешением устройства не требуется.

В панели просмотра есть общий для браузера и МК выбор **Отдельно** / **В контейнере: …**. Для второго режима редактор находит реальные пути от стартовой страницы до выбранной через `view.pages`. Если мест вставки несколько, они доступны отдельными вариантами; показывается вся цепочка родителей. Для ещё не включённой в стартовую композицию страницы доступны её объявленные непосредственные контейнеры. Список ограничен 32 путями и существующим пределом глубины композиции.

Для просмотра в контейнере меняется `view.initial` только во временной копии проекта вдоль выбранного пути. Размеры контейнеров, `sizing`, оформление, биндинги и события остаются обычными данными проекта. Дерево и свойства продолжают редактировать выбранную вложенную страницу. W/H относятся к её проектному размеру, а подпись холста — к размеру внешней композиции. Выбор страницы или режима ничего не отправляет на МК; **Посмотреть на МК** отправляет явно, **Автоприменение** — после правок выбранной страницы.

Отдельный аппаратный просмотр страницы, размер которой отличается от LCD, использует временную корневую страницу размера дисплея с `view.sizing: design`. Её содержимое сохраняет проектные размеры, переполнение прокручивается. Приложение S3 объявляет фактическое разрешение в `capabilities.display: {width,height}`; со старой прошивкой используется размер стартовой страницы проекта. Обёртка учитывается в общих лимитах экземпляров/глубины и не сохраняется на МК или в черновике.

В режиме **Отдельно** остаётся проверка произвольной области **Свой размер области**. Сначала она получает текущий размер страницы, далее W/H меняют только эту область. По умолчанию выбран **Размер документа**: переполнение видно. **По контейнеру** проверяет заполнение области корнем страницы; содержимое целиком не масштабируется. Кнопка **Размер страницы** и выбор другой страницы возвращают обычный просмотр. Это вспомогательная браузерная проверка; на МК используется выбранный общий режим. Масштаб «Авто» лишь вписывает изображение в панель редактора.

При открытии проекта из файла или с МК редактор выбирает его `manifest.entry`, даже если эта страница записана последней. Изменение поля стартового экрана само по себе не прерывает редактирование другой страницы. В проекте стенда оболочка с вкладками называется «Оболочка · время, сеть и страницы» (`shell`).

MCP читает живые экземпляры через `get_project_status`, а настроенный переход вызывает через `send_event` с локальным node и при необходимости числовым instance. См. [руководство MCP](readme_mcp_ru.md).

Минимальное описание узла и события:

```json
{
  "view": {
    "pages": [
      { "screen": "overview", "retention": "retain" },
      { "screen": "details", "retention": "release" }
    ],
    "initial": "overview",
    "sizing": "fill"
  }
}
```

```json
{ "event": "clicked", "navigate": { "view": "content", "screen": "details" } }
```

`content` — локальное имя узла с `view` в той же странице. Начальные рекурсивные вставки отвергаются при компиляции проекта; цикл, возникший при переходе, даёт заглушку. Текущие общие пределы: глубина 8, до 16 одновременно существующих экземпляров и 2 неактивных кэшируемых страницы. Удерживаемые и вложенные экземпляры тоже учитываются в общем пределе. Фактические возможности сообщает `capabilities.composition`.

Предел экземпляров относится к одной композиции. При замене целого проекта новый корень сначала подготавливается рядом со старым: это сохраняет текущий экран при неудачной загрузке. Поэтому в момент такой замены память временно требуется для обеих композиций.

В CBOR композиция передаётся метаданными `views_version: 1` и `views` рядом с существующим потоком команд screen v3. Командный ABI не заменяется. `/api/project?action=info` сообщает числовой `display.instance` и состояния контейнеров `display.views`; диагностическое событие `/api/data` может указать числовой `instance` вместе с локальным `node`.

## Обновление после редактирования

Сохранение проекта само по себе не меняет дисплей. `ProjectService::refresh()` и
`POST /api/project?action=refresh` с пустой CBOR-картой пересоздают отображаемый
корень из сохранённого проекта и восстанавливают выбранные вложенные страницы.
Путь определяется локальным ID контейнера и именем выбранной страницы на каждом
уровне. Поэтому одинаковые имена узлов и повторное использование одной страницы
в разных контейнерах не смешивают выбор; прежние числовые instance не переносятся.

Если контейнер переименован или выбранная страница больше не разрешена в нём,
используется новое `view.initial`. При удалении отображаемого корня или смене
идентичности проекта используется новая стартовая композиция. При неудачной
подготовке корня остаётся прежняя отображаемая композиция. Переносятся только
активные маршруты: объекты, состояние виджетов и неактивный кэш создаются заново.
Явные `load_screen` / `show` и preview сохраняют обычную семантику начальной
композиции. Обновление не сохраняет preview и не вводит кэш по ревизиям.

## Ошибка перехода

Выбранная вкладка остаётся выбранной. Если её страницу создать не удалось, область содержимого показывает простую заглушку с красным крестом. Старое содержимое не выдаётся за содержимое новой вкладки. Переход на другую страницу остаётся доступным.

## Верхняя строка состояния

Строка времени и IP — обычные компоненты страницы с биндингами. Именованные источники `system.clock` и `system.network` предоставляет приложение примера. Сеть, SNTP и часовой пояс не входят в переносимое ядро UI.

До первой подтверждённой синхронизации время неизвестно. После потери сети уже синхронизированные часы продолжают идти; состояние синхронизации и её возраст предоставляются отдельно. Экран не выполняет NTP-запросы каждый раз, когда обновляет время.

В примере используются штатный SNTP ESP-IDF/lwIP и три имени серверов с его встроенным переключением при недоступности. Список не опрашивается собственным циклом UI. Основной сервер задаётся `STYLE_LAB_NTP_SERVER`, часовой пояс — `STYLE_LAB_TIMEZONE`; это параметры приложения, а не страницы.

По последнему указанию владельца основной сервер по умолчанию — `ntp1.yandex.ru`, резервные — `pool.ntp.org` и `time.google.com`.

Локальные настройки стенда можно задать в игнорируемом `examples/s3_style_lab/main/system_status.local.hpp` через эти макросы. Подтверждение времени приходит от SNTP; наличие IP или правдоподобная дата RTC сами по себе не означают успешную синхронизацию. Используется [асинхронная служба времени ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v5.4/esp32s3/api-reference/system/system_time.html).

При длительном состоянии `syncing` проверяйте интернет-доступ с самого контроллера: Wi-Fi, IP и DNS могут работать при ограниченном внешнем доступе. Обычный HTTP-запрос поможет обнаружить страницу сетевой авторизации. [Методика и результат проверки](reviews/REVIEW_20261023_ntp.md).

## Проверки

Описание модели не является отчётом об аппаратной приёмке. Результаты тестов, браузерной проверки и прошивки записываются отдельно после завершения реализации.
