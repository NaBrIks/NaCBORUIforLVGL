# Данные, привязки и события

Реализовано по поручению владельца от 2026-10-22 в общем проекте после рефакторинга. Контракт — [binding-api-v1.json](../contracts/binding-api-v1.json), решение — [ADR](adr/ADR_20261022_data-bindings-events.md), подтверждённые проверки — [отчёт](reviews/REVIEW_20261023_bindings-events.md).

## Где это находится в общем проекте

Используются существующие `ProjectService`, редактор экранов и Project JSON/CBOR. На странице «Проект» подключитесь к МК и нажмите «Открыть проект с МК»: вместе с документами обновится фактический каталог. Затем откройте нужный экран, выберите узел дерева и раздел «Данные и события» в его свойствах. Источники, пути структур/массивов, методы, действия и типы аргументов выбираются общими визуальными формами.

«Посмотреть на МК» применяет черновик без сохранения. «Сохранить проект на МК» на странице «Проект» сохраняет весь проект, включая правила узлов; текущая картинка сама не меняется. JSON/CBOR-файлы и MCP используют те же кодеки. В приложении S3 один `DataRegistry` подключён к существующему `ProjectService` и прямому screen endpoint; Источники прикладных данных регистрирует приложение; проект UI не содержит реализации транспортов датчиков.

## Границы

```text
BLE / TPMS / GPS / сообщения приложения
  → адаптер приложения → DataRegistry → привязка → метод LVGL-компонента

Событие LVGL → отложенный вызов → разрешённое действие / setter
  → публикация фактических данных → привязка
```

Адаптер знает формат пакета, но не надписи и компоновку. Привязка знает имя источника, путь и метод, но не BLE-пакет. Проект хранит правила, а не текущие показания. CBOR данных и CBOR экрана — разные документы. Обычная очередь с конкурирующими читателями не обеспечивает рассылку; реестр не меняет её семантику.

## Каталог и публикация

Приложение владеет `DataRegistry` дольше экранов. До загрузки привязок оно регистрирует источники с именами, схемами и необязательными setter-ами; действия имеют имена, схемы аргумента и обработчики. Каталог передаётся в разделе `binding` ответа `/api/capabilities`. Измерение не становится записываемым из-за регистрации.

Схемы: `null`, `bool`, `integer`, конечный `number`, `text`, `object` с именованными `fields`, ограниченный `array` с `items`. Корень может быть простым значением, структурой или массивом. Для элементов массива новые имена реестра не нужны. Размер, вложенность и количество элементов ограничены. Необъявленные поля отвергаются; отсутствующее объявленное поле даёт неизвестность.

```cpp
lvgl_cbor::DataRegistry data;
std::string error;
data.add_source({"tpms", lvgl_cbor::DataSchema::object({
  {"pressure", lvgl_cbor::DataSchema::number(0, 20)},
  {"temperature", lvgl_cbor::DataSchema::number(-50, 150)}
})}, error);
data.publish("tpms", lvgl_cbor::DataValue::Object{
  {"pressure", 2.35}, {"temperature", 26.0}
}, error);
data.flush();
```

`publish` принимает принадлежащее реестру значение; `publish_cbor` ограниченно разбирает и копирует CBOR. Целый снимок заменяет прежний, включая исчезнувшие поля и уменьшившийся массив. `flush()` публикует накопленные изменения и пересчитывает зависимости пакетом: давление и порог используются из согласованного состояния.

Реестр и LVGL работают в сериализованном UI-контексте. Другие задачи копируют короткие записи в ограниченную очередь; UI-поток извлекает и публикует данные. Указатели в освобождённый payload не сохраняются.

Спрос суммируется по источнику. Экранные подписки исчезают с объектами; постоянный token приложения сохраняет спрос между экранами без скрытых виджетов. Адаптер может пропускать ненужное UI извлечение, но сигнализация и управление не зависят от экрана. Публиковать можно и без спроса. Постоянство не означает NVS.

| Данные | Привязка |
|---|---|
| Неизвестны | Текст `--`; числовой/логический setter пропускается |
| Известны | Используется значение, включая настоящий `0` и `false` |
| Явно устарели | Рассматриваются как неизвестные |

Кэш не доказывает свежесть. Timeout датчика и момент устаревания определяет приложение.

## Запись у узла

```json
{"id":"pressure","type":"label","props":{"text":"--"},
 "bindings":[
   {"method":"text","value":{"source":"tpms","path":["pressure"]},
    "format":{"precision":2,"suffix":" bar"}},
   {"scope":"common","method":"state","value":[
     {"literal":4096},
     {"op":"gt","args":[
       {"source":"tpms","path":["pressure"]},
       {"source":"settings","path":["pressureLimit"]}
     ]}
   ]}
 ]}
```

Маску состояния выбирают из текущего LVGL-каталога. Обычный selector `styleRules` или прикреплённого стиля меняет оформление при этом состоянии. Отдельный движок динамических стилей не нужен.

`method` — alias из каталога; без `scope` используется локальный метод компонента, с `scope:"common"` — общий метод объекта. Это различает одноимённые методы. Две привязки к одному числовому методу одного узла запрещены.

PC разрешает alias в opcode и собирает верхние wire-списки `bindings`/`events`. Целевой ID берётся из узла; в авторской привязке он не дублируется. Перенос сохраняет правила, удаление поддерева убирает их. `bindings_version:1` версионирует отдельный блок; курсорный screen ABI v3 и style ABI v2 сохраняются.

Аргументы каждой привязки сохраняются до следующего успешного вызова или удаления объекта. Частые обновления не дописывают строки/массивы в буфер инициализации. Подписки снимаются, отложенные вызовы отменяются; уничтоженный объект не получает setter.

## Выражения

| Форма | Назначение |
|---|---|
| `{"source":"имя","path":["поле",0]}` | Путь; без `path` — корень |
| `{"literal":значение}` | Константа |
| `[выражение,выражение]` | Составной аргумент/массив |
| `{"object":{"поле":выражение}}` | Структура с динамическими полями |
| `{"op":"gt","args":[выражение,выражение]}` | Операция |
| `{"event":"value"}` | Прочитанное значение события, только в обработчике |

Операторы: `eq/ne/lt/le/gt/ge`, `and/or/not`, `select`, `add/sub/mul/div/round`. `select` вычисляет выбранную ветвь. `round` округляет половины от нуля, включая отрицательные. Деление на ноль и неконечный результат не превращаются в ноль. JavaScript, циклы, пользовательские функции и таймеры не исполняются.

Литерал обёрнут явно: данные с ключами `source`, `op` или `event` не принимаются за программу. Его содержимое ограничено отдельно от количества узлов выражения. Путь — строки и индексы, а не разбор точек: `app.items` с `[0,"value"]` — поле первой структуры массива.

`format` даёт скалярный текст: `precision`, `prefix`, `suffix`, `unknown`. Произвольный printf-format не выполняется. По умолчанию неизвестность даёт ровно `--`, без единиц. Целочисленный метод не принимает дробь или переполнение; при необходимости задаётся `round`.

Первая версия поддерживает индексные пути и целый массив/объект как аргумент совместимого нативного метода. Автоматическое создание строк массива не реализуется. Параметры и формы общие для всех компонентов.

## События

```json
{"events":[{"event":"clicked","action":"app.items.clear","args":{"literal":null}}]}
```

```json
{"events":[{"event":"value_changed",
 "write":{"source":"app.collection.enabled","path":[]},
 "value":{"event":"value"}}]}
```

Адаптер виджета читает значение события: число slider, индекс dropdown, bool switch/checkbox или текст textarea. Нативный компонент предоставляет необязательный reader и метаданные. `clicked` с константами работает без reader. Ветки редактора по имени компонента не добавляются.

Callback копирует аргументы в ограниченную очередь; приложение вызывается после выхода из события LVGL. Обновления биндинга подавляют обратные события. После пользовательского изменения виджет согласуется с подтверждёнными данными даже при неизменившихся байтах аргумента: отказ не оставляет неподтверждённое положение.

Setter меняет реальную настройку/оборудование и публикует результат. Асинхронный BLE-запрос подтверждается GAP callback; ожидающая команда показывается отдельно. Сохранение настройки в NVS — политика приложения.

## Необязательный HTTP-адаптер

`integrations/nawserver/data_api.*` отделён от ядра. `GET /api/data` возвращает неизменяемый снимок источников, состояния, revision, диагностику и восемь последних результатов команд. HTTP-задача не вызывает LVGL и не читает изменяемый реестр.

`POST /api/data` принимает CBOR до 4096 B:

```js
encode({kind:'action',name:'app.items.clear',args:null});
encode({kind:'write',source:'app.collection.enabled',path:[],value:false});
encode({kind:'event',node:'clear',event:'clicked'}); // диагностика LVGL
```

`202 {queued:true,id}` подтверждает очередь. Результат команды появляется в `commands`, состояние оборудования — отдельно в источниках. Операции внешнего `publish` измерений нет: только разрешённое действие/setter. Диагностическое событие не подтверждает физическое касание сенсора.

## Совместимость и приёмка

Офлайн-файл сохраняет правила и доступен для структурной проверки. Отсутствующий каталог не выдумывает источники и не подтверждает совместимость. С МК используется фактический каталог; неизвестные источники, пути, действия и read-only запись дают явные ошибки.

Общие `state`/`flag` дописаны без перенумерации. При изменении строгого fingerprint сохранённый CBOR перекомпилируется из сохранённого JSON. Обычная прошивка приложения не должна незаметно заменять файловую систему.

Проверяются скаляр/структура/массив, неизвестность, уменьшение массива, пакетное сравнение, независимые экземпляры, удаление, неудачная замена, частые аргументы, отказ записи, подавление циклов и действие из события. Реальные BLE-данные, логическое событие LVGL и физическое касание описываются отдельно.

## Группы и выборочный каталог, 2026-11-07

DataRegistry расширен описаниями, группами, nullable-полями, отдельной ревизией
каталога и bounded DataView. MCP сначала читает группы/сводку и запрашивает нужную
ветку, а не весь набор источников. Необязательный DataHistory работает независимо
от подписок страницы; возврат получает последний снимок. Обратные события остаются
штатными, writable определяется источником. Подробности и ограничения —
[реестр и история](readme_data_catalog.ru.md).
