# Каталог независимых экранов и стилей

Стандарт `lvgl-project-catalog-1` — файловое представление **одного слоя изменений** ProjectService. База остаётся в прошивке либо другом `ProjectSource`. Каталог не создаёт дополнительных приоритетов, не меняет screen/style ABI и не является файловым менеджером.

Код приложения знает только имя: `projects.load_screen("radar", reply)`. Пути, раздел, монтирование и политика задаются приложением; браузер и MCP узнают состав через сервис.

## Где смотреть

- `GET /api/project?action=info`: `screens`, `styles`, `catalog.documents` — итоговый набор, включая базу и изменения. Для документа возвращаются `kind`, `name`, `origin` (`base`/`changes`), `location`, `bytes`.
- `GET /api/project?action=screen&name=radar` и `action=style&name=radar_grid`: один исполнимый CBOR-документ. `action=read` — полный итоговый проект.
- В редакторе: **Проект → Каталог экранов и стилей МК**. «Открыть с МК» загружает весь набор в обычные списки экранов и стилей. Подключение и чтение не переключают LCD.
- В коде: `ProjectService::status().documents`, `read_screen`, `read_style`. `base`/`changes`/`media` сообщают права и реальные настроенные носители. SD стенда не настроена; наличие карты не проверяется.

Наличие произвольного файла на носителе не добавляет его в проект. **Источником состава является индекс**. Добавление, удаление и изменение имени выполняются транзакцией проекта; каталог и соответствующие файлы публикует адаптер. Для подготовки начального образа используется PC-компилятор.

## Формат носителя

`CatalogProjectStore("/project")` использует следующую схему. Файловая система может быть плоской: все имена не длиннее десяти ASCII-символов.

| Имя | Назначение |
|---|---|
| `catalog.0`, `catalog.1` | Два проверяемых поколения индекса |
| `0s000.cbor` … `0s127.cbor` | Независимые экраны банка 0 |
| `1s000.cbor` … `1s127.cbor` | Независимые экраны банка 1 |
| `0t000.cbor` … `1t127.cbor` | Независимые общие стили обоих банков |

Номера файлов — внутренние слоты хранения, **не идентификаторы экранов/стилей**. Стабильное имя документа находится в индексе. Переупорядочивание может изменить физический путь.

Индекс имеет оболочку `LVPROJ01`: magic 8 B, generation uint64 BE, размер payload uint64 BE, payload CBOR, FNV-1a-64 uint64 BE от всех предыдущих байтов. Контрольные суммы обнаруживают повреждения; это не криптографическая аутентификация.

Форма payload (диагностическая запись; `manifest` здесь бинарный CBOR):

```text
{
  format: "lvgl-project-catalog-1",
  base: "<16 hex: fingerprint точного базового проекта>",
  manifest: h'<CBOR manifest>',
  screens: {radar: {file:"0s000.cbor", bytes:868, hash:"<16 hex>"}},
  styles: {radar_grid: {file:"0t000.cbor", bytes:98, hash:"<16 hex>"}},
  screenOrder: ["dashboard", "radar", "trip"],
  styleOrder: ["panel", "reading", "caption", "radar_grid"]
}
```

Пример иллюстрирует поля, а не готовый полный индекс. Карты содержат только отличия от базы: файл либо `null` для удаления. `manifest` полный, массивы порядка описывают итоговый проект; зависимости стилей упорядочены компилятором на ПК. Размер и FNV каждого файла проверяются. Допустимы только назначенные слоту имена: произвольные пути и `../` не принимаются. Бинарная оболочка проекта и каталог — разные форматы; UI JSON/CBOR открывает **полный проект**, а не служебный индекс.

При сохранении адаптер пишет документы неактивного банка, выполняет flush/sync и последним записывает его индекс. Действующий банк не изменяется. При старте выбирается старшее поколение с целым индексом **и всеми его файлами**; при оборванной записи используется предыдущее. Если обе копии повреждены или база изменилась — явная ошибка; автоматического форматирования и молчаливой потери изменений нет. Физическая стойкость к внезапному отключению питания зависит также от файловой системы/драйвера.

Слоты повторно используются; неиспользуемые слоты неактивного банка удаляются перед публикацией индекса. Посторонние файлы не удаляются. После прерванной записи возможны неиндексированные слоты, которые будут убраны при следующей записи того же банка. До 128 экранов и 128 стилей, общий исполнимый проект стенда — до 262144 B. Свободное место файловой системы и её служебный запас также ограничивают запись. Ошибка записи не публикует новое состояние в RAM.

## Стенд S3: ROM + последние 4 МиБ

`examples/s3_style_lab/main/project_config.hpp` монтирует встроенный SPIFFS `/project`, раздел `project`; `format_if_mount_failed=false`. При недоступном монтировании доступна только ROM-база, запись запрещена. Ядро и адаптер каталога не зависят от SPIFFS/ESP-IDF; для другого железа задаётся другой путь/носитель.

Раздел SPIFFS: `0xC00000`, размер `0x400000`, конец `0x1000000` (16 МиБ). NVS `0x9000`, PHY `0xF000` и приложение `0x10000`/5 МиБ сохранены. При этой миграции у заводского загрузчика обнаружен заголовок 8 МиБ; его существующий код сохранён, размер исправлен на 16 МиБ с пересчётом SHA средствами esptool. Обычные обновления этот заголовок не переписывают.

Образ интерфейса строится из `examples/s3_style_lab/project/demo.mjs`:

- ROM: `dashboard` — четыре давления/температуры, нативный GPS-спидометр, состояние GPS; общие `panel`, `reading`, `caption`.
- SPIFFS: `radar`, `trip`, независимый `radar_grid`.
- При подготовке с `--preserve` предыдущие пользовательские экраны сохраняются как `workbench-<имя>`, вместе с их стилями. Исходный полный проект дополнительно оставляется на ПК. Конфликты имён не замалчиваются.

Значения TPMS/GPS/радара демонстрационные и подписаны на LCD. Драйверы реальных датчиков, GNSS и привязки данных этим проектом не подключены.

```powershell
# Сборка приложения и подготовка файлов, без записи на устройство.
& tools/build_s3.ps1 -PreserveProject C:/absolute/previous-project.cbor
& tools/build_project_fs.ps1
# Явная первичная установка / замена всего содержимого FS!
& tools/deploy_s3.ps1 -Port COMx -ExpectedMac 02:00:00:00:00:01 -ProvisionFilesystem
# Последующие обновления: только приложение; файловая система сохраняется.
& tools/deploy_s3.ps1 -Port COMx -ExpectedMac 02:00:00:00:00:01
```

`-PreserveProject` необязателен. Устройство/порт/MAC всегда проверяются заново. `-ProvisionFilesystem` **заменяет весь файловый раздел** подготовленным образом; это не обычное сохранение проекта. Повседневные изменения записываются явной командой сервиса/редактора. Начальный образ и диагностический JSON индекса находятся в `local/project-image/`; `base.json/.cbor` и `project.json/.cbor` можно открыть в редакторе.

При изменении строгого screen ABI старый каталог сначала экспортируют целиком в JSON. `build_s3.ps1 -ProjectJson <экспорт.json>` перекомпилирует его текущим кодеком, сохраняя исходные имена, ID, entry и стили; опциональный BLE-пример добавляется отдельным экраном. После проверки подготовленного содержимого и `build_project_fs.ps1` используют явный `deploy_s3.ps1 -Port COMx -ExpectedMac MAC -UpdateFilesystem`. Этот режим требует идентичную живую таблицу разделов и пишет только приложение и SPIFFS; bootloader, NVS, PHY и таблица остаются на месте. Перед заменой FS проверяют, что текущая revision проекта не изменилась после экспорта. Для обычного обновления оба filesystem-флага опускаются.

Для других приложений экспортирована `compileCatalog(base, project, capabilities)` из `@lvgl-cbor/project-codec/catalog`. Она создаёт полный набор файлов начального банка. PC-функция `inspectCatalog` проверяет образ до упаковки. Файловая система и её размещение остаются выбором прошивки; формат каталога общий.
