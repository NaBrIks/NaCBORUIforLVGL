# Генерация интерфейса LVGL через JSON и MCP

Модель пишет разметку и стили в JSON-языке NaCBORUIforLVGL. Это декларативная
запись создания объектов LVGL, вызовов методов и вложенности. Визуальный дизайн
определяется запросом автора; Grid/Flex имеют приоритет без запрета других решений.
[Документация LVGL](https://docs.lvgl.io/) объясняет саму библиотеку; наш JSON-формат
объясняют документы ниже.

## Системная инструкция и два справочника

- [Основная инструкция](../tools/designer/prompts/assistant-system-prompt.ru.md):
  соответствие понятий LVGL JSON, данные/события, порядок работы с проектом;
  полный пример Grid 2×2 с двумя кнопками, чекбоксом и вводом значения.
- [Разметка](../tools/designer/prompts/assistant-layout-reference.ru.md): все
  встроенные типы и поддерживаемые методы, точные JSON-формы, параметры,
  перечисления, части/состояния/флаги, биндинги/события и вложенные страницы.
- [Стили](../tools/designer/prompts/assistant-styles-reference.ru.md): все
  действующие методы оформления и перечисления, локальные/именованные стили,
  наложение нескольких стилей и селекторы.

Русские файлы *.ru.md — редактируемые оригиналы владельца. Английские переводы
лежат рядом под теми же именами без .ru и именно они передаются модели.
Designer.Core встраивает три английских файла в сборку приложения и передаёт
их SPLA как системные инструкции. После изменения файлов приложение нужно
пересобрать. tools/designer/prompts/guide.mjs читает тот же комплект для проверки
документации; MCP отдаёт разделы справочников внешним клиентам. Перевод не
выполняется скрытым запросом к модели:
после правки русского оригинала соответствующий английский файл обновляется
при сопровождении инструкции. JSON-пример также лежит в
[agent-grid-controls.json](../examples/screens/agent-grid-controls.json).

Справочники — поддерживаемая документация JSON, не выдача внутреннего контракта.
tools/assistant_reference.mjs теперь только проверяет полноту методов/перечислений
и валидность примеров в обеих языковых версиях. Он не переписывает файлы и не
стирает ручные пояснения. contract/contract:check используют эту проверку.
Версия и фактический размер переданного текста видны в журнале. В инструкции
нет CBOR, ABI или числовых кодов команд конвертера.

## Что сообщает MCP

get_ui_reference возвращает нужный раздел этих же справочников, в том числе
внешним агентам, у которых нет встроенного системного контекста. topic:index
показывает список разделов. get_device выдаёт реальные возможности устройства
в терминах авторского JSON, без opcodes/ABI. get_data_catalog даёт фактические
источники и действия с типами, описаниями, путями и writable. Они не выдумываются
по примеру. validate_document проверяет JSON общими кодеками, не сохраняет и не
показывает его. get_contract, compile_document и decode_document из MCP удалены;
сами кодеки остаются общими для файлов, редактора и транспорта.

Источники example.* в примере учебные. Чекбокс читает bool и пишет его обратно;
textarea читает/пишет text. Ввод числа пока представлен текстом, проверка числового
формата выполняется приложением. Отдельного spinbox, accepted_chars и автоматического
преобразования text→number JSON API сейчас не предоставляет.

## Проверка результата

Модель передаёт JSON-объект инструменту записи, существующий ProjectService
сохраняет проект. Сохранение и показ разделены; сохранённая revision и отображаемая
revision проверяются отдельно. read_project_document поддерживает outline/node
для выборочного чтения и замены поддерева. Кадр get_display_frame — реальный LVGL,
преобразованный внешним MCP-хостом для модели. Вебка получает его через NaWServer.
Проверяющий не исправляет сгенерированную разметку руками.

Вызовы модели, чат, reasoning и tool loop исполняет SPLA в Designer.Core.
История и вложения сохраняются между отправками в памяти приложения; Новый чат
очищает разговор, но не проект на устройстве. Параметры модели задаются в Designer;
старых лимитов assistant.reply и отдельного Node-цикла в Windows-демке больше нет.

Designer использует полный каталог своего настроенного MCP, без второго
статического списка и фильтров имён demo/ui/assistant. Типы, writable, события
и результаты команд проверяют существующие API/DataRegistry. get_ui_reference
позволяет читать по разделам; источник инструкций общий с Designer.

Исходные промпты, ответы и снимки опытов остаются в ignored local/design-stages.
Референсы с неизвестной лицензией в публичные assets не включаются.
