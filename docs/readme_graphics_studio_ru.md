# Две Windows-демки и самостоятельная настройка UI

Обновлено 2026-11-08. Это две точки запуска одного Windows host и общего
C++ LVGL/ProjectService/StyleService/DataRegistry, с разными проектами,
портами, настройками и storage key. Дублирования UI-движка нет.

| Запуск | Назначение | Сайт / MCP |
|---|---|---|
| `npm run player` | Стандартные компоненты, биндинги, реальные системные счётчики | loopback:5300, `nacborui_windows` |
| `npm run player:graphics` | Только графика, пульт, чистый холст и настройки | loopback:5301, `nacborui_graphics` |

Графический профиль не создаёт SystemMetrics, его поток и CPU/GPU источники.
Обе программы используют один EXE с `--profile system` / `--profile graphics`.
Аргументы `--api-port` и `--api-store` могут явно переопределить порт и store.
Порт 443 запрещён. MCP использует stdio; отдельный MCP TCP-порт не придуман.
Фактический сайт и имя MCP публикуются обычным источником `host.connection`
и показаны в заголовке графического проекта.

## Графический проект

- Растр: RAW форматы, BIN, PNG, JPEG, BMP и GIF на одной шахматной подложке.
- Вектор: Tabler SVG, собственный цветной SVG, Bézier/ломаная/кэшированный растр.
- Пульт: общий polygon_button с контурами из Project, штатными событиями и биндингами.
- Холст: изначально только пустой корень, полностью для редактирования через MCP.
- Настройки LVGL: схемы оформления. Подключение LLM и выбор модели находятся в веб-меню «Настройки».

`Opaque` означает отсутствие прозрачности. Alpha задаёт непрозрачность пикселя:
0 — виден фон, 255 — фон закрыт, промежуточные значения смешивают цвета.
RGB565/RGB888 не имеют альфы; XRGB8888 использует четвёртый байт как padding,
а не alpha. ARGB8888 содержит alpha; A8 — только маску, её цвет задаётся отдельно.
Палитровый I4 может иметь прозрачные записи, но наш образец показывает
непрозрачную палитру. JPEG не содержит alpha; GIF поддерживает прозрачный
индекс палитры, а не плавную полупрозрачность каждого цвета.

Подробности: [галерея](readme_graphics_ru.md).

## Точный живой сайт

NaWServer раздаёт построенный frontend, API и WS. В graphics профиле корень
сайта открывает `/editor/`. Слева постоянное меню «Работа» / «Настройки».
В «Работе» сверху многострочный prompt с картинками, под ним вкладки
«Лог» и «Предпросмотр экрана». Лог показывает конкретные вызовы, документы,
результаты и ошибки. Предпросмотр показывает настоящий LVGL в рамке дисплея
на контрастном фоне с фактическим разрешением. Enter добавляет строку, Ctrl+Enter отправляет запрос. Настройки API, ключа
и модели находятся на отдельной странице; переход между страницами сохраняет
черновики. `/editor/?mode=manual` открывает
ручной редактор проекта; в его шапке есть возврат в студию. `/viewer`
показывает снимки настоящего запущенного LVGL, включая SVG/GIF и native-компоненты.
Нажатия передаются отдельному LVGL pointer input; курсор/клавиатура Windows
не эмулируются. Штатные LVGL hit-testing и события вызывают те же биндинги.

Это online-вид общей композиции: нажатие в браузере меняет запущенное приложение.
Он не является автономным offline-предпросмотром черновика. Существующий
приближённый предпросмотр редактора остаётся отдельной подсказкой компоновки.
Полная автономная сборка LVGL/runtime для WebAssembly пока не выполнена:
нужны Emscripten SDK и платформенные display/input/font адаптеры.

Frame выдаётся bounded BMP: максимум 2 Мпикселя / 8 МиБ пиксельного буфера до
выделения памяти; отдача владеет своими байтами. Видимый браузер запрашивает
последовательно до пяти кадров/с, скрытая вкладка приостанавливает кадры.
Это Windows-диагностика, не обещание такой частоты/протокола для слабого МК.
Pointer имеет ограниченную очередь, heartbeat и watchdog отпускания.

## Встроенный агент

Сценарий: открыть сайт или программу, выбрать endpoint/model, сохранить ключ,
ввести пожелание и нажать «Отправить». `assistant.mjs` исполняет небольшой
цикл model → существующие MCP tools → результаты → следующий шаг. Он использует
тот же stdio MCP adapter и те же HTTP/ProjectService операции; нового сервера,
второго набора project/style операций или движка отрисовки нет.

Поддержан OpenRouter-compatible Chat Completions API с tool calling.
По умолчанию выбрана `qwen/qwen3.8-27b:free`, включён флажок «Только
бесплатные». Это предустановка, а не обещание доступности провайдера. Если
точного ID нет в текущем каталоге, он не подменяется платной версией и не
добавляется в выдачу как якобы доступный.

Свободный текст ищет по имени и ID во всём полученном каталоге до ограничения
страницы 64 записями. Постраничный выбор показывает диапазон и полное число
совпадений; «Назад»/«Далее» позволяют увидеть оставшиеся модели. Полный ID
выбранной модели доступен отдельно от длинного отображаемого имени.
Варианты списка также содержат ID: сам title провайдера может не указывать
размер модели, например 550B. Флажок учитывает фактические цены prompt/completion/request,
а не только суффикс имени. Положительные или неизвестные цены исключаются.
Проверяется и отправка запроса: free-only не разрешает выполнить платную или
неподтверждённую модель; OpenRouter дополнительно получает max_price=0.

Ввод фильтра применяется через 350 мс, флажок — сразу; меняются только фильтры.
Недописанные endpoint/model/key от этого не сохраняются и промпт не отправляется.
Компактный полный каталог кэшируется на пять минут, явное обновление запрашивает
его заново. Во время другой операции запоминается последняя правка фильтра.
Фильтры сохраняются вместе с защищённой конфигурацией. ID модели можно ввести вручную. Совместимость конкретной модели с
инструментами зависит от провайдера. Во внешние запросы уходят промпт и
результаты выбранных инструментов проекта; модель не получает API-ключ
в контексте инструментов, shell или произвольный доступ к файлам.

Под запросом видны текущий этап и прошедшее время. Ошибки выводятся
с переносом строк без многоточия, длинный текст прокручивается внутри области. Состояние, ошибка и
успех занимают заранее предусмотренное место, не сдвигая экран. Ответ модели
и подробная диагностика открываются по ⓘ; автоматически окно не открывается.
Промежуточный этап поступает через тот же host bridge → DataRegistry → WS.
Он не является завершением операции и не увеличивает completion generation.

Один активный запрос, до 16 model rounds и 32 tool calls, лимиты
ответов и общее время, кнопка отмены. Нет фоновой платной генерации. Отмена
останавливает следующие действия; уже применённые операции не откатываются
автоматически. Без ключа реальная платная генерация не проверяется и не
считается выполненной. Тестовый провайдер подставляется только в тестах,
сами MCP/NaWServer/ProjectService/LVGL остаются настоящими.

Видимый и веб-интерфейсы используют одну группу DataRegistry `assistant`.
Долгая операция возвращает управление немедленно. Queue receipt означает
принятие команды; `assistant.completion {generation,ok}` подтверждает
завершение host-операции, `assistant.busy` — активность. Веб читает изменения
по WS, локальные правки полей не перетираются обновлениями.

## Где хранятся настройки

В системном каталоге LocalAppData приложения `NaCBORUIforLVGL`:
`graphics-player.json` хранит выбор схемы, `graphics-assistant.dpapi` —
зашифрованный Windows DPAPI документ endpoint/model/key. Он привязан к
учётной записи Windows; plaintext fallback нет. Нативные DPAPI операции
доступны только приватному stdio launcher bridge, не product HTTP/MCP API.
Для тестов есть явный `--assistant-store` с временным файлом.

В Project JSON/CBOR, registry snapshots и модельный контекст ключ не включается.
Нативное password-поле очищается после передачи host-запроса; диагностический
inspect маскирует password textarea. Браузер держит новый ключ только до
передачи и очищает поле. Промпты/ответы не входят в persistent config.

Изменения самого графического проекта хранятся прежним FileProjectStore в
отдельном profile-scoped key. Старые системные/галерейные stores не удаляются.
Сохранение через MCP остаётся явным; preview и save различаются.
Android-клиент и переносимый автономный renderer остаются планами, а не
готовыми Android-возможностями этого Windows host.

## Справочники и API

Ссылка «Справочник C API LVGL» в ручном редакторе открывает собственный
генерируемый каталог C-сигнатур из закреплённых публичных заголовков LVGL 9.6.
Это документация библиотеки для разработчика, не HTTP/MCP API приложения
и не обещание поддержки всех её функций в текущем runtime. В основной
графической студии эта ссылка не занимает рабочее меню. Для построения UI
агент получает фактические capabilities через существующий MCP.

## Как агент получает знания

Русский оригинал инструкции — `assistant-system-prompt.ru.md`, английский перевод для модели — `assistant-system-prompt.md`; host `assistant-guide.mjs`
читает их перед новым запросом, цикл исполняет `assistant.mjs`. Описания
инструментов приходят из `listTools` существующего stdio MCP; общие JSON/CBOR
контракты входят в host-пакеты кодеков. `get_device` узнаёт реальные возможности
приложения, `get_data_catalog` выбирает группы, источники, действия и поля,
`read_project_document` читает нужный документ проекта. Эти сведения поступают
модели по запросу, а не целой документацией в каждом сообщении.

Для МК сохраняется то же разделение: runtime, актуальный каталог и значения —
на устройстве; общие справочники, модель и исполнение агентного цикла — на
внешнем клиенте. Полный справочник C API не требуется хранить во flash.
Сейчас selective data discovery выполняется на стороне API, а выбор sections
из capabilities — на host после получения полного capabilities. Это уже
экономит контекст модели, но не весь сетевой трафик к МК. Browser/Android
agent host остаётся отдельным направлением; Node-host Windows не становится
прошивкой микроконтроллера.

## Возврат к полной раскладке

Кнопка с домиком в шапке показывает manifest.entry сохранённого проекта.
Это навигация: сохранённые изменения не сбрасываются. Отдельный показ дочерней
страницы (например, холста) не удаляет оболочку — домик возвращает её.

В «Настройках» кнопка «Восстановить исходную раскладку» после подтверждения
сбрасывает changes существующим API с проверкой revision и показывает entry
исходного проекта. База ProjectService доступна через API только для чтения:
save/preview изменяют overlay или отображение, не исходную полную раскладку.
Отдельного backup/store/движка восстановления не добавлено.
