# ADR: проект, слой изменений и независимый предпросмотр

Статус: принято владельцем 2026-10-22; уточнение размещения UI — управление в разделе «Проект».

## Решение

Проект объединяет именованные экраны, общие стили и manifest. Редактор целиком открывает/сохраняет JSON/CBOR-проект. Двоичный контейнер содержит готовые CBOR-документы, сохраняя style ABI v2 и screen ABI v3. Кодеки ПК проверяют ссылки и рассчитывают порядок стилей.

В прошивке application-owned ProjectService предоставляет высокоуровневый load_screen(name), чтение и явное сохранение. Источник базы и один необязательный слой изменений подключаются в коде приложения. Носители, пути, монтаж FS/SD и политика replace/add/remove принадлежат приложению. Перекрывается целый именованный документ; для удаления есть отметка, для возврата к базе — reset. Слой изменений привязан к отпечатку базы.

Предпросмотр исполняет отдельный снимок проекта. Он не сохраняет изменения. Сохранение не переключает дисплей. Автоприменение выполняет только предпросмотр. При ошибке создания текущий экран сохраняется.

HTTP API и host MCP — отключаемые адаптеры сервиса, использующие общую модель. Операции LVGL выполняет UI-задача. MCP разделяет разрешения показа и сохранения. Запись требует явной команды и проверки revision. Подключение не отправляет черновик и не заменяет рабочую копию автоматически.

## Следствия

Упаковка проекта в один файл не требует монолитного хранилища на всех устройствах. PROGMEM-база может читаться по представлениям; файлы и RAM используют соответствующих владельцев. Общие стили экземпляра проекта не смешиваются со стилями другого предпросмотра. Конкретные нативные примеры не вводят специальных правил редактора.

Ресурсные файлы, шаблоны и биндинги остаются отдельным будущим расширением. Этот ADR не вводит патчи узлов, произвольные скрипты или запись во flash при каждом изменении поля.
