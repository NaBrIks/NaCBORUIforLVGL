# Изменяемая область отображения без пересоздания UI

Дата: 2026-10-30. Статус: принято по поручению владельца о Windows-демке.

## Причина

Настольное окно меняет размер независимо от проектных размеров страницы.
Повторная компиляция/загрузка всего проекта на каждом WM_SIZE сбросила бы
экземпляры, фокус, локальные правки контролов и кэш страниц. Подгонка картинки
масштабированием не перераспределяет полезное место.

## Решение

- Хост выбирает `ScreenViewport::Declared` или `ScreenViewport::Display` при
  создании ScreenRuntime/ProjectService. По умолчанию Declared: прежнее требование
  совпадения размеров при загрузке standalone-экрана сохраняется.
- Display разрешает загрузку описания с иным проектным размером и задаёт корню
  текущие размеры LVGL display. Windows-приложение явно выбирает этот режим.
- Нормальный Win32 backend LVGL обрабатывает WM_SIZE, framebuffer и координаты
  ввода. Он изменяет разрешение в контексте LVGL. Хост не содержит второго
  обработчика рендеринга или глобальной политики размеров движка.
- Корневые экраны следуют штатному изменению LVGL display; вложенные страницы
  сохраняют существующую политику `fill`/`declared`. Grid/Flex, проценты и FR
  перераспределяют пространство без повторного исполнения CBOR.
- Размер `screen.size` остаётся размером проектирования/начального запуска,
  а не записью текущей геометрии окна. Wire ABI и документы не меняются;
  новые необязательные аргументы C++ требуют обычной пересборки библиотеки.

## Границы

Фиксированные координаты пользовательского проекта остаются фиксированными:
адаптивную компоновку задаёт автор. Движок не угадывает смысл объектов и не
масштабирует шрифты. Смена файла/проекта сохраняет прежний жизненный цикл;
изменение размера существующего окна не перезагружает проект и источники.
Размеры окна/ограничения Windows принадлежат приложению. Прошивки продолжают
использовать Declared, если их приложение явно не выберет другой режим.
