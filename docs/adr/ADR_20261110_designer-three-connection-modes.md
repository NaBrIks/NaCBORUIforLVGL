# ADR: три режима подключения Designer

Дата: 10.11.2026. Статус: принято владельцем.
Дополняет и частично замещает ADR_20261110_embedded-mcp-only: явно выбранный
внешний MCP endpoint разрешён, автоматическое создание посредников запрещено.

## Решение

Основной режим — прямой HTTP/CBOR API. Designer предоставляет модели инструменты
через SPLA IToolHost; JSON разметки/стилей проверяют и компилируют существующие
JS-кодеки внутри BlazorWebView. Node.js нужен только сборщику, не приложению.
Сеть выполняет ограниченный HttpClient самого приложения, без listener и CORS-прокси.
Микроконтроллер получает CBOR, JSON-компилятор UI ему не требуется.

Два других режима — встроенный MCP целевого приложения и явно заданный внешний
MCP-прокси. Они используют один HTTP MCP-клиент SPLA. Отличаются назначением и
сохранённым адресом, а не протоколом или вторым движком чата. Приложение не запускает
внешний сервер и не переключается на него при ошибке прямого API.

Встроенный MCP — опциональный proof of concept на NaWServer внутри executable.
JSON-RPC требует JSON-парсера; эта стоимость выключается вместе с MCP. Его наличие
не означает поддержку JSON-authoring операций: каталог объявляет только реально
реализованные инструменты. Для MCU стоимость MCP может перевесить пользу.

## Последствия

История, работа с LLM, очередь и выполнение инструментов принадлежат SPLA.
Палитры/биндинги/страницы и хранение исполняются прежними сервисами устройства.
Прямой режим использует общие кодеки, а не новую C# или C++ реализацию JSON→CBOR.
Адрес устройства, адрес встроенного MCP и адрес прокси сохраняются раздельно;
секреты модели остаются в SecureStorage. В этой итерации проверяется Windows;
S3 не прошивается.
