# Возможности устройства, общий сервис стилей и двусторонние кодеки

Дата: 2026-10-22. Статус: принято по прямому запросу владельца реализовать результаты анализа.

## Основание

Проверки редактора, JS-кодеков и C++ расходились. Глобальные стили старого StyleRuntime не были доступны ScreenRuntime. Обратное преобразование экранов отсутствовало, а App.vue одновременно управлял представлением, транспортом и состоянием.

Новое указание владельца о глобальных статических, глобальных динамических и экранных стилях уточняет прежнее ограничение областями global/screen. Оно не вводит универсальное наследование или автоматический сборщик мусора.

## Решение

- Прошивка публикует `/api/capabilities`: закреплённые каталоги операций и типов, реально скомпилированные фабрики, доступные layout ID, ресурсы приложения и действующие ограничения ядра/транспорта. Редактор получает этот снимок при подключении и после перезапуска устройства. Приложение должно перепубликовать снимок, если изменяет реестр ресурсов/layout во время работы.
- Возможности устройства сужают допустимые документы. Проверки устройства сохраняются: клиент не может заранее доказать существование любого внешнего стиля, отсутствие OOM или корректность состояния LVGL, изменённого приложением.
- Имеется один application-owned StyleService. Статические глобальные стили заимствуются у приложения; динамические глобальные имеют стабильные адреса; экземпляры экранов получают независимые StyleScope; локальные стили узлов принадлежат плану экземпляра.
- `global:name` выбирает динамический глобальный стиль, затем статический. `global-static:name` и `global-dynamic:name` выбирают конкретный уровень; `screen:name` — область текущего экземпляра. Неуточнённый поиск через C++ API сначала проверяет экранную область. Copy/merge по-прежнему создают снимок значений и сохраняют время жизни заимствованных массивов.
- Удаление дерева предшествует освобождению его стилей. При внешнем DELETE очистка плана переносится на следующий UI-turn, чтобы завершилось удаление дочерних объектов. Перенос объекта в другого родителя не передаёт владение: runtime удаляет и такие оставшиеся объекты при teardown.
- По умолчанию экранная область освобождается. Кэширование требует ScreenStyleRetention::Cache. Кэш содержит именованные стили, не дерево виджетов. `cached_scope()` позволяет приложению явно повторно использовать сохранённую область; автоматическое восстановление экрана или экономия времени разбора не обещаются. `trim_unused()` освобождает неприкреплённые записи; активные StyleHandle и области остаются живыми.
- Для свойств используются соседние encode/decode-адаптеры и общая проверка аргументов. JSON имеет каноническую форму: цвета lowercase hex, перечисления и составные операции нормализуются; проценты/content/FR сохраняют смысл. Название экрана передаётся как title. Метка caption восстанавливает Button.text без угадывания по имени дочернего Label. Common-операции сохраняются явно.
- App.vue собирает компоненты. Соединение с устройством, очередь команд, документ стиля, документ экрана, предпросмотр и изменение ширины панелей имеют отдельные модули. Смена адреса/boot ID отменяет запросы и готовность прежнего устройства.

## Оценка предложенных механизмов

Парные адаптеры — распространённый способ локализовать правила сериализации. Их преимущество — видимая симметрия; недостаток — необходимость отдельно определить каноническую форму для разных эквивалентных записей. Выбран этот подход с проверкой повторного кодирования и восстановлением значимой структуры.

Кэш экранных стилей полезен при повторном появлении экрана и достаточной памяти, но удерживает ресурсы и требует явного владения. Поэтому выбран release по умолчанию и опциональный кэш. Автоматические пороги нехватки памяти, LRU, профилирование и обработчик неудачного malloc не реализуются в этой задаче. Сервис предоставляет явный trim_unused для будущей политики приложения в UI-контексте.

## Совместимость

Существующие номера методов и сигнатур не переназначаются; lock-файлы не переписываются. Каталоги дополнены правилами значений и описанием авторского формата, поэтому fingerprints изменились. Редактор требует соответствующий каталог прошивки и не считает старое устройство совместимым только по HTTP 200.

## Проверка

JS-тесты двусторонних преобразований и возможностей, пересобранные native LVGL/TinyCBOR тесты, отдельные проверки StyleService и сборка S3. Проверка браузера использует эмулятор сайта; физическая прошивка и LCD этой версии требуют отдельного запроса владельца.
