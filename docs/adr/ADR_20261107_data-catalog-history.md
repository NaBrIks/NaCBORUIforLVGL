# ADR: группированный реестр и выборочный каталог данных

Статус: принято владельцем 2026-11-07, уточнено обратное направление и оформление.

## Решение

Расширить существующий application-owned DataRegistry группами и содержательными
описаниями источников, действий и полей. Сохранить глобальные символические имена,
схемы и committed/pending значения в одном реестре. Дерево групп — классификация,
не дерево владельцев и не «реестр реестров» с несколькими хранилищами.

Общая C++ реализация выдаёт ограниченные страницы groups/sources/actions/fields/values.
HTTP использует существующий GET /api/data с параметрами, host MCP оборачивает этот
API. По умолчанию выдаются сводки и небольшой объём; полная выбранная схема — явно.
Обрезанная схема не считается корректным ответом. Изменение состава каталога имеет
отдельную catalogRevision; конфликт ревизии требует повторить discovery.

Immutable DataView разделяет владение описаниями/снимками и переносится из UI-контекста
к HTTP. Mutable registry, setters и LVGL остаются в сериализованном UI-контексте.
Постраничные values не замораживают значения между разными запросами.

DataHistory — опциональный модуль с ограниченными кольцами, приложением-владельцем,
явным монотонным tick и обычными readonly выходами реестра. Его можно исключить из
сборки или выключить с освобождением колец. История принадлежит данным и продолжает
собираться при уходе со страницы. Binding pause относится к UI.

Обратные события остаются штатным механизмом; отдельного глобального флага отключения
не вводить. Запись определяется setter каждого источника, команды — зарегистрированными
actions. UI отображает подтверждённые приложением значения и подавляет обратную связь.

Дизайн не ограничивается каталогом данных. Через те же project API и кодеки агент
может создавать стили, менять целый проект и прикреплять несколько именованных стилей
с part/state к компоненту. Не создавать второй theme engine или отдельное MCP-хранилище.
Собственные схемы и три контрастных демо-варианта проверять на настоящем LVGL Windows.

## Последствия и границы

- Сохраняется один двигатель биндингов, один каталог и существующие API проекта.
- Discovery может ограничиваться доменом, префиксом, именем и веткой схемы.
- Проверки и лимиты выполняются до регистрации/экспорта, но логические byte budgets
  не заявляются полным пределом heap.
- Metadata пока копируется во владение реестра; ROM descriptors — будущая оптимизация.
- Динамическая регистрация поддержана, unregister/replace schema не добавлены.
- Передача styles/widgets/resources ограничивается на host после полного capabilities;
  выборочные data queries выполняются на стороне устройства.
- Универсальный скриптинг, event log всех измерений и новый транспорт не добавлены.
- Android voice designer остаётся планом; аппаратное исполнение этой итерацией не заявляется.
