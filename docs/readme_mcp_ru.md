# MCP: данные, события и вложенные страницы

MCP — необязательный Node.js stdio-адаптер существующего HTTP/CBOR API. Он не создаёт второй DataRegistry, executor, граф навигации или хранилище проекта. Ключи данных и страниц остаются символическими; идентификатор живого экземпляра — числовой.

В корне добавлены переносимые `.mcp.json` и `.codex/config.toml`: сервер
`nacborui` для этого адаптера и независимый `semaps` для архитектурной документации.
По умолчанию адрес МК не задан и изменяющие группы выключены. Подключение,
фактические проверки и отличие от HTTP/WS прошивки: [руководство SeMaps/MCP](readme_semaps_ru.md).

После сохранения через MCP HTTP-адаптер МК отправляет в существующий `/ws` событие `project_changed` с новой ревизией. Открытый редактор подхватывает проект по этому событию, при отсутствии локальных правок; таймера опроса проекта нет. После восстановления WS выполняется разовая сверка. Отдельного MCP-канала уведомлений или дублирующего API нет. Требуется прошивка с `capabilities.project.events:["project_changed"]`. Правила конфликта и границы слежения описаны в [руководстве проекта](readme_projects_ru.md#изменения-проекта-извне-без-перезагрузки-браузера). Показ на LCD остаётся отдельной операцией.

## Подключение и группы операций

Установите зависимости корня и `integrations/mcp`, запустите `node integrations/mcp/index.js` из MCP-клиента. Пример — `integrations/mcp/example.config.json`. `LVGL_CBOR_DEVICE` фиксирует один origin устройства. Аргументы инструментов не могут подменить адрес. TCP-сервер MCP не запускается, конфигурация клиента автоматически не изменяется.

После обновления кода перезапустите MCP-процесс в клиенте, чтобы он заново зарегистрировал инструменты и прочитал переменные окружения.

| Настройка | Что включает |
|---|---|
| Без адреса устройства | Офлайн-контракты, примеры, compile/decode и необязательный CSS |
| `LVGL_CBOR_DEVICE` | Метаданные, чтение проекта, живые данные и результаты команд |
| `LVGL_CBOR_ALLOW_PREVIEW=1` | Preview проекта и показ сохранённого корневого экрана |
| `LVGL_CBOR_ALLOW_SAVE=1` | Сохранение/reset проекта с проверкой revision |
| `LVGL_CBOR_ALLOW_DATA=1` | Вызов действий, запись данных и диагностические LVGL-события |

Группы независимы. Разрешение предпросмотра или сохранения не включает команды приложения. Разрешение данных не включает preview/save. По умолчанию все три группы изменений выключены; отсутствующие группы не регистрируют инструменты. `LVGL_CBOR_ALLOW_APPLY` остаётся алиасом только preview. Старые переключатели CSS/полного отключения MCP сохраняются.

## Инструменты

| Инструмент | Аргументы и результат |
|---|---|
| `get_contract` | `kind: screen/style/binding/composition`; общий встроенный контракт, не подтверждение совместимости с конкретным МК |
| `get_device` | Actual capabilities: `binding.sources/actions/events/limits`, `composition` и каталог компонентов |
| `get_data` | Снимок `/api/data`: значения, known/unknown, revisions, диагностика, ограниченная история команд |
| `get_data_command` | `id`; `completed` с исходным результатом МК либо `unknown` |
| `invoke_action` | `name`, необязательные `args` (по умолчанию null), `wait` (по умолчанию true) |
| `write_source` | `source`, `path` (по умолчанию []), JSON `value`, `wait` |
| `send_event` | Локальный `node`, `event`, необязательный числовой `instance`, `wait` |
| `get_project_status` | В том числе `display.instance` и `display.views`: владелец, pageInstance, контейнер, выбранная страница, ошибка |
| `read_project`, `read_project_document` | Сохранённые JSON-описания с биндингами, событиями и view |
| `compile_document`, `decode_document` | Общие кодеки screen/style/project, включая композицию; при подключении — проверка по возможностям МК |
| `preview_project`, `show_project_screen` | Существующие операции отображения; запись проекта не выполняется |
| `save_project`, `write_project_document`, `reset_project_changes` | Существующие операции сохранения с актуальной revision; дисплей не переключается |

`get_example` и необязательный `convert_css` также сохранены. Для данных нет специальных инструментов BLE, NTP или конкретного приложения.

## Данные и результаты команд

Сначала получите каталог через `get_device`. Общий DataClient использует уже существующие валидаторы схем, значений и путей; финальная проверка и выполнение остаются на МК. `write_source` разрешён только для `writable=true`; поддерживаются значение целиком, поля структуры и индексы массивов.

Примеры аргументов (имена условные, их нужно взять из каталога приложения):

```json
{"source":"app.settings","path":["channels",0,"enabled"],"value":true}
```

```json
{"name":"app.configure","args":{"values":[1,2,3]}}
```

Команды отправляются CBOR в `/api/data`. HTTP 202 означает только приём в очередь. По умолчанию адаптер ждёт опубликованный результат с тем же `id`:

- `state=completed`, `result.ok=true` — команда адаптера выполнена на UI-задаче;
- отрицательный результат МК возвращается как MCP `isError` с ID и причиной;
- `wait=false` возвращает `state=queued` сразу;
- если результат не удалось подтвердить, возвращается `state=unconfirmed` с ID, а при сетевом сбое чтения — также с причиной. Повторно отправлять такую команду автоматически нельзя;
- `get_data_command: unknown` означает, что результат ещё не наблюдался или уже вытеснен из ограниченной истории. Это не доказательство, что команда не исполнялась.

POST никогда не повторяется автоматически. При потере ответа на сам POST результат отправки может быть неизвестен; сообщение об ошибке прямо запрещает автоматический повтор. DataClient хранит только параметры транспорта и не заводит альтернативное состояние приложения.

Результаты относятся к текущему запуску МК: ID команд и экземпляров не следует повторно использовать после перезапуска. HTTP timeout MCP согласован с ProjectClient — 15 секунд, чтобы он не обрывал допустимое ожидание UI-задачи сервера раньше его собственного лимита.

Завершение команды не доказывает завершение асинхронной операции оборудования или всех отложенных реакций биндингов. Фактическое состояние смотрите в `get_data`, результат перехода — в `get_project_status`. Неизвестное значение остаётся unknown; нулём оно не подменяется.

## События и навигация

`send_event` использует существующий диагностический event `/api/data`, который вызывает реальный LVGL callback. Произвольный payload не вводится: для `value_changed` используется текущее значение контрола. Физическое касание этим не проверяется.

Для дочерней страницы укажите её актуальный `pageInstance` из статуса контейнера:

```json
{"node":"next-button","event":"clicked","instance":7}
```

Без instance событие адресуется корневой странице. Одинаковые локальные node в разных экземплярах различаются instance. Эти ID не следует сохранять в проект: они относятся к текущей живой композиции. Удалённая цель даёт ошибку; событие приостановленного экземпляра не обязано выполнять обработчик.

Чтобы переключить контейнер, отправьте событие кнопке, у которой в описании страницы задан `navigate`. Затем проверьте `display.views[].selected/error/pageInstance`. MCP не ищет кнопку за пользователя и не обходит допустимые переходы прямой загрузкой внутрь контейнера. Отдельный дублирующий `navigate_page` не нужен.

Биндинги, события, `view.pages/initial/sizing` и политики release/cache/retain редактируются существующими инструментами JSON-проекта. Эти операции используют те же codecs и ProjectClient, что и редактор; не требуется новый формат документа.

## Общие модули и проверки

`packages/project-codec/data-client.js` — общий браузерный/Node транспорт без зависимости от Vue, MCP, Node API или прошивки. Он разделяет валидаторы с редактором и не реализует предметные действия. MCP оборачивает его в инструменты. Проверки: `npm test`, `node --test integrations/mcp/test.mjs`, `npm run contract:check`, `npm run build`. Отдельно проверяется настоящий stdio с HTTP-стендом, адресация экземпляров и неопределённые результаты без повторного POST.
