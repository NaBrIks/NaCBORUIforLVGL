# Чат для поэтапного изменения интерфейса

Веб-страница «Работа» сохраняет контекст между нажатиями «Отправить»:
пожелания пользователя, ответы, выполненные MCP-вызовы и их результаты,
исходные картинки и JSON-вложения. Каждый следующий запрос содержит этот
диалог и одну актуальную английскую системную инструкцию. Повторно прикладывать
картинку для «теперь поменяй цвет» не требуется. Последний проверочный кадр LVGL
заменяет предыдущий проверочный кадр; пользовательские референсы сохраняются.

## Управление

- «Новый чат» очищает разговор, вложения и журнал; сохранённый/показанный проект
  и настройки модели остаются на месте. Во время операции сначала нужна остановка.
- История находится под вводом, кнопки — под многострочным полем. «Ранее»/«Далее»
  показывают страницы переписки. Подробные MCP-шаги остаются во вкладке «Лог».
- «Вложения» принимает PNG/JPEG/WebP и JSON. Изображения можно вставлять из буфера.
  JSON используется как материал разговора: например, предыдущая версия экрана.
  Прикрепление само не заменяет проект и не выполняет содержимое файла.
- После принятого успешного запроса поле и отправленные вложения освобождаются.
  Если пользователь уже пишет следующий текст, он не стирается. При ошибке черновик
  остаётся доступен для исправления.

JSON-файл: до 1 MiB исходного текста и до 64 KiB после удаления пробелов форматирования.
Это объект экрана/стиля/проекта; передаётся модели как текст и не требует vision.
До четырёх вложений в одном сообщении. Картинки используют прежнюю подготовку:
до 1024 px и 96 KiB на изображение, стандартные MIME-проверки. Если в разговоре
есть картинки, смена на модель без vision вызывает явную ошибку без потери истории.

## Где находится история

Историей владеет внешний Windows Node-host, модуль assistant-chat.mjs. Она живёт
в памяти процесса: переживает перезагрузку веб-страницы и переключение настроек,
но перезапуск Windows-проигрывателя начинает новый разговор. Сохранённый UI-проект
при этом остаётся в штатном ProjectStore. Дисковый архив чатов пока не реализован.

В DataRegistry передаётся только ограниченная страница assistant.chat (до восьми
сообщений и примерно 6 KiB), без base64 картинок или JSON-файлов. Фотографии и
документы хранятся в контексте host; в истории вебки видны имена файлов, а в текущей
вкладке также миниатюры отправленных картинок. После перезагрузки браузера имена
файлов остаются, картинки продолжают быть доступны модели, миниатюры не загружаются
через реестр повторно.

assistant.new_chat и assistant.chat_page используют существующие actions /api/data,
private host pipe и WS. JSON загружается через тот же ограниченный chunk-транспорт
вложений, отдельного HTTP-сервера/стека нет. В MCU не переносится хранилище диалогов.
Схемы, кодеки и ProjectService по-прежнему отвечают за создание/сохранение UI.

Сетевые/модельные ошибки не откатывают уже выполненные MCP-команды. При прерывании
пакета недостающие tool responses помечаются interrupted_unconfirmed; следующий
запрос может проверить фактический проект, не переигрывая действие автоматически.
Служебное «бюджет исчерпан» не переносится как запрет в следующий пользовательский
ход. При заполнении контекста история не удаляется молча: нужна новая беседа.
API-ключ маскируется в публичной переписке и не включается в MCP-окружение.
