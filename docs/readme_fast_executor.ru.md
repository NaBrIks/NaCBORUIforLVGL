# Курсорный исполнитель экранов v3 и стили v2

Решение владельца от 2026-10-22: [ADR](adr/ADR_20261022_cursor-component-executor-v3.md). ПК проверяет описание и порядок операций; МК последовательно читает вложенный CBOR. Предыдущее решение об общих массивах сигнатур для компонентов заменено. Для стилей оно сохраняется.

## Команды

| Код | Значение | Аргумент |
|---|---|---|
| 0 | Создать дочерний компонент | Отдельная форма `[0, тип, тело]` |
| 1 | Назначить ID текущему объекту | Строка |
| 2 | Создать и подключить собственный стиль | `[селектор, CBOR-карта методов стиля]` |
| 3 | Подключить готовый стиль | `[селектор, ссылка]` |
| 4 / 5 | Добавить / убрать флаги | Маска |
| 6 / 7 | Добавить / убрать состояния | Маска |
| 8 | Режим полос прокрутки | Число |
| 9 | Направление прокрутки | Маска направлений |
| 10…255 | Резерв общих команд | Пока не исполняются |
| 256…65535 | Локальный метод компонента | Одно CBOR-значение: скаляр, массив или объект |

Обычная команда: `[код, аргумент]`. Тип объекта не повторяется в коде метода. Номер 256 у Label означает текст, у Bar — диапазон; выбирает смысл обработчик текущего компонента. В CBOR это целые числа переменной длины, не фиксированные двухбайтовые слова.

`root` в конверте экрана — команда создания. Например, контейнер → кнопка → надпись (диагностическая запись CBOR):

```text
[0, 0, [
  [1, "root"],
  [0, 2, [
    [1, "button"],
    [0, 1, [
      [1, "caption"],
      [256, "Открыть"]
    ]]
  ]]
]]
```

Здесь типы 0 = obj, 2 = button, 1 = label. Число в позиции типа и код команды находятся в разных пространствах.

## Проход курсора

`execute_screen` читает внешнюю команду создания. `execute_create` читает тип, выбирает фабрику и обработчик, создаёт объект с текущим родителем и запускает `execute_body`. Тело содержит последовательность команд. При коде 0 происходит рекурсивное создание ребёнка; по концу его массива исполнение возвращается к следующей команде родителя. Команды после детей поддерживаются самим исполнителем.

Контракт курсора: диспетчер читает opcode; выбранный обработчик потребляет ровно одно значение аргументов и оставляет курсор после него. Диспетчер завершает массив команды. Для создания обработчик потребляет тип и тело. `cbor_value_leave_container` продвигает родительский курсор без повторного обхода выполненного дочернего тела.

`src/widget_methods.inc` содержит отдельные switch-обработчики стандартных компонентов и выбор фабрики/обработчика при создании. Массивов методов и дескрипторов методов больше нет. `invoke_widget` — необязательный шаблон прямого вызова конкретной C-функции после чтения типизированных аргументов. Сложный обработчик может самостоятельно читать CBOR.

## Проверка входного CBOR

Обычный ScreenRuntime перед исполнением одним обходом проверяет
структуру и глубину CBOR, отсутствие тегов, точный конец пакета и
допустимость полей конверта. Повтор имени поля в конверте отклоняется.
Этот обход запоминает курсоры полей, которые понадобятся декодеру.
Составные аргументы стандартных методов и встроенные карты стилей
передают наружу уже продвинутый курсор TinyCBOR.

Одна сборка поддерживает оба пути. Обычный `ScreenRuntime::load`
всегда выбирает `ScreenValidation::Checked`. Приложение может передать
`ScreenValidation::TrustedEmbedded` явным параметром загрузки для
неизменяемого пакета, встроенного в прошивку. В проекте это свойство
задаётся на `ConstProjectSource` и передаётся отдельно для каждого
экрана, включая вложенные. Загрузка редактора, предпросмотр проекта и
файловые изменения используют `Checked`, даже если заменяют экран с
тем же именем. Сохранение и сетевой протокол не переносят признак доверия.

Доверенный путь пропускает предварительный обход в ScreenRuntime.
Целые аргументы вызовов через `invoke_widget` из встроенного экрана
приводятся к типу параметра без проверки диапазона. Для аргументов
из биндингов и внешних экранов проверка диапазона сохраняется. Тип
CBOR, структура команд, ABI, лимиты и ссылки на ресурсы проверяются
в обоих режимах. ProjectService при открытии контейнера проверяет
структуру проекта и идентичность документов. Отдельные пакеты
стилей также проверяются.

Для текстовых аргументов `invoke_widget` берёт длину из заголовка
строки с известным размером. TinyCBOR при копировании возвращает
следующий курсор, а LVGL получает C-строку с завершающим нулём.

Дубликаты верхнеуровневых ключей в доверенном режиме отдельно не
ищутся. Поиск TinyCBOR возвращает первое совпадение. В других
декодерах выбор может отличаться, поэтому дубли в исходном документе
делают смысл пакета неоднозначным. Для генерируемого пакета ключи
однозначны ещё до прошивки.

### Экспериментальная загрузка из прошивки

Для явно доверенного экрана `-DLVGL_CBOR_NAIVE_EMBEDDED=ON`
пропускает предварительную проверку длины массива команды и
проверку набора ключей определения именованного стиля.
Оба доверенных режима находят поля штатным поиском TinyCBOR.
Курсор `root` передаётся исполнителю без отдельного полного
обхода дерева. Ошибки чтения, конец массива, версии ABI,
индексы обработчиков и ссылки на ресурсы проверяются.
Флаг по умолчанию выключен.

Для сравнения на S3 соберите ту же сцену `phases-os` трижды.
Обычная сборка использует полную проверку. Для штатного доверенного
режима задайте `NACBOR_BENCH_TRUSTED_CBOR=1`. Для облегчённого
режима дополнительно задайте `NACBOR_BENCH_NAIVE_EMBEDDED=1`.
[Замеры на S3](../examples/memory_bench/results-s3.ru.md#три-режима-после-удаления-предварительного-обхода-root).

## Стили и владение

Собственный стиль в исходном JSON остаётся объектом `style`, дополнительные селекторы — `styleRules`. ПК компилирует их в отдельные блоки команды 2. МК передаёт карту методов в `apply_style_methods`, затем подключает полученный `lv_style_t` к текущему объекту. Содержимое общего диспетчера компонентов не интересует. Стили по ссылке подключает команда 3; определения именованных стилей остаются в конверте экрана.

Стилевой ABI v2 не меняется: 138 указателей в 28 массивах по сигнатурам. Свойства стиля не расходуют коды 1…255.

Входной пакет не копируется. Промежуточного дерева команд на МК нет. Дерево владения хранит живые объекты, ID, детей и владельцев стилей/регистраций. Строки и точки, которые могут заимствоваться нативным кодом, хранятся до удаления экземпляра. Курсор и parser сбрасываются после синхронного load/mount. При ошибке частично созданное дерево удаляется, прежний экран сохраняется.

## Пользовательские компоненты

```cpp
lvgl_cbor::WidgetRegistry registry;
lvgl_cbor::ScreenRuntime screen(resources, count, {}, &styles,
    lvgl_cbor::ScreenStyleRetention::Release, &registry);
registry.add({256, "my:meter", "meter-1", create_meter, execute_meter,
              compiler_catalog_json});
```

Регистрация возможна во время работы. ID нативных типов — 256…65535, имя содержит namespace и двоеточие. Тип в команде создания: `[256, "meter-1"]` или `["my:meter", "meter-1"]`. Поиск имени выполняется только при создании. Живой экземпляр удерживает неизменяемую регистрацию; `remove` запрещает новые создания, но не ломает существующие объекты. Нативный код должен оставаться доступным до их удаления. Все действия сериализуются в UI-контексте.

Обработчик: `bool execute_meter(lv_obj_t*, uint16_t method, CborValue& cursor, WidgetContext&)`. Локальные методы от 256 описываются на ПК в `methods` с `opcode`, `alias`, `parameters` и при необходимости `phase`. Сигнатурных индексов больше нет. Пример: `examples/native_widget/meter.hpp` и `meter.json`. Его составной метод `reading` принимает `[42, "kPa"]`.

Capabilities публикуют каталог для `encodeScreen/decodeScreen/normalizeScreen`. Общие команды исполняются и для пользовательских объектов. Универсальные поля аргументов и три нативных примера описаны в [руководстве компонентов](readme_native_components.ru.md). Внутреннюю графику нативного кода браузер не эмулирует.

## Компиляция, обратимость и миграция

Исходный декларативный JSON стандартных экранов сохраняется. ПК валидирует его и порядок setter-ов, затем `command-stream.js` преобразует внутреннее представление в команды. Порядок задаётся массивами, поэтому сортировка ключей CBOR-карт его больше не меняет.

Декодер восстанавливает декларативный JSON из потока, произведённого компилятором. Произвольный вручную составленный поток с повторными методами или командами родителя после детей может быть корректным для МК, но не выражаться прежним JSON-форматом. В таком случае decode сообщает об ошибке, а не переставляет операции молча. Необязательное поле конверта `captions` сохраняет происхождение сгенерированных Button.text; МК его не исполняет.

Текущие контракты: `style-api-v2.json` и `screen-api-v3.json`. Пакеты экранов v1/v2 отклоняются; их нужно перекомпилировать и согласованно обновить браузер и прошивку. Старые контракты остаются историей.

Проверки: `npm test`, `npm run contract:check`, `tools/test_native.ps1`. Нативные тесты выполняют реальные LVGL-вызовы, возврат к родителю и соседу, пустое тело, предельную глубину, ошибки границ с rollback, блоки стилей, регистрацию по ID/имени и сохранность заимствованных буферов.
