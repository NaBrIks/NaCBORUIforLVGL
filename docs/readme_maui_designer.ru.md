# MAUI-конструктор: SPLA + Windows/Android

[Подключения Designer](readme_designer_connections.ru.md): прямой API по
умолчанию, два профиля MCP и USB для T-Display-S3 на Windows.
[Реальная проверка OpenRouter на Windows/Android и исправление потока UI — 09.11.2026](reviews/REVIEW_20261109_maui-real-chat.md).

Первая версия — приложение MAUI Blazor Hybrid. Интерфейс отображается локально
в BlazorWebView, C#-код работает внутри приложения, а не на веб-сервере.
Историей, запросами OpenAI-compatible/OpenRouter, потоковым ответом, tool loop
и MCP занимается SPLA. Собственные компоненты отвечают за отображение чата,
настройки, выбор файлов и получение кадра от совместимого MCP target.
Основной режим — прямой API: общие JS-кодеки работают локально без Node.
Для двух MCP-профилей используется один клиент SPLA. Полное редактирование
JSON доступно в прямом режиме. [Опциональный встроенный MCP проигрывателя
Windows](readme_windows_native_mcp.ru.md) предоставляет свой каталог инструментов.

HTTP/SSE/OpenAI-код клиента остаётся существующим SPLA.

## Запуск и проверка

Команды и зависимости: [tools/designer/README.md](../tools/designer/README.md).
В настройках по умолчанию выберите прямой API и origin устройства. Для встроенного
MCP укажите полный `/mcp` URL приложения, собранного с соответствующей опцией.

Core проверяется с настоящими SPLA transports через ответы HttpMessageHandler
в памяти, без альтернативного HTTP-listener: история двух сообщений, изображения,
каталог моделей, JSON-RPC MCP, вызов инструмента, отмена и отсутствие blobs в логе.
Прежняя live-проверка использовала удалённый посредник и не подтверждает текущий native MCP.
Результат платформенной приёмки хранится в связанном отчёте проверки.

История первой версии живёт в памяти приложения. Перезапуск очищает чат;
настройки соединений сохраняются. Новый чат очищает контекст, но не проект target.
JSON прикладывается как текст к сообщению, картинки — нативные ImageAttachment SPLA.
При прямом подключении предпросмотр получает настоящий кадр LVGL из API
устройства. В профиле MCP кадр доступен, если endpoint поддерживает
`get_display_frame`. Сохранение проекта выполняется соответствующими
инструментами выбранного режима.

Кнопка остановки отменяет ожидание/генерацию клиента. Уже выполненные операции
на target не откатываются. Если остановка попала на сетевой вызов записи, сервер
может завершить его после отмены клиента: сначала прочитайте текущее состояние,
а не повторяйте изменение вслепую. Автоматического повтора такой записи нет.

[Отчёт проверки Windows/Android и ограничения](reviews/REVIEW_20261108_maui-designer.md).
Сборки, APK, снимки и исходные замеры находятся только в ignored local.

Картинки можно вставлять Ctrl+V прямо в поле запроса; они становятся обычными
вложениями. [Проверка вставки и refresh композиции](reviews/REVIEW_20261109_paste-refresh.md).

## Диагностика компонентов в предпросмотре

Под заголовком постоянно видны два ряда уровней: **Обводки** и **Цифры**, каждый
со своими галочками и цветовыми квадратами. Меню/раскрытия и общие галочки отсутствуют.
Цвета по умолчанию КОЖЗГСФ, раздельно для каждого режима/глубины. Ниже — толщина
обводки (по умолчанию 3 px) и непрозрачность цифр. Тайлы 16×16 A1 общие, 320 байт масок.
Контракт действия `ui.layout_debug_options` принадлежит устройству.
Designer вызывает его через прямой API, если действие объявлено в каталоге.
Настройка диагностики не меняет сохранённый проект.
[Контракт, стоимость и ограничения фигурных компонентов](readme_layout_debug.ru.md).

## Копирование кадра в буфер

Значок двух листов в заголовке предпросмотра копирует **показанный PNG-кадр**,
а не снимок рабочего стола или текстовую ссылку. До получения кадра значок недоступен.
Копирование не делает нового запроса к устройству и не вызывает LLM; размер совпадает
с изображением предпросмотра (текущий MCP feedback — до 1024 px по длинной стороне).
Чтобы скопировать свежий кадр, сначала нажмите обновление.

Windows использует штатные DataPackage.SetBitmap и Clipboard.Flush; изображение
доступно другим приложениям. Android использует ClipData.NewUri и существующий
MAUI FileProvider: два чередующихся PNG-файла в cache/preview-clipboard ограничивают
расход места. Это очищаемый кэш, не проект и не публичные assets. При замене старых
слотов старые URI не являются архивом снимков. Поддержка вставки изображения зависит
от принимающего Android-приложения; физический телефон пока не проверен.

Ошибки показываются через имеющийся индикатор подробностей. Собственные toast/banner
и новые listeners/HTTP API не добавлялись.

Платформенная документация: [Windows SetBitmap](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.datatransfer.datapackage.setbitmap),
[Android copy/paste content URI](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste).

## Поставка приложения

Исходники штатного универсального конструктора находятся в `tools/designer`
(`App` — MAUI Blazor Hybrid, `Core` — интеграция SPLA). Это часть поставки библиотеки,
не пример конкретного устройства. SDK, команды сборки и установки перенесены вместе
с исходниками; идентификатор приложения и SecureStorage не меняются.
В диагностике добавлен одна общая галочка «Тип вместо номера»: большая
цифра либо большая G/F по действующему layout LVGL.

## Предпросмотр и управление

Над таблицей глубин расположены две строки: «Управлять» (Control) и
«Постепенно» (Progressive). Обе галочки включены по умолчанию, если устройство
поддерживает соответствующую функцию. Индикатор сразу справа от Progressive
показывает загрузку в обоих режимах. Когда Direct API сообщает объём, рядом
виден прогресс передачи. У LVF2 с RLE длина HTTP-ответа заранее неизвестна,
поэтому прогресс считается в распакованных байтах обновления.

Direct API автоматически обновляет предпросмотр на целях, которые объявляют
порции, дельты или интервал обновления. Designer запрашивает изменения после
последней принятой ревизии, включая переходы от физического тача и перерисовки
часов. При активной передаче следующий запрос ждёт её завершения, скрытое окно
приостанавливает автоматическую загрузку. Кнопка ↻ запрашивает обновление сразу,
если передача свободна.

Control отправляет нажатия в координатах дисплея, даже пока область кадра пуста.
Для этого нужны поддержка удалённого ввода и размеры дисплея. Direct API получает
их из `/api/capabilities`, MCP — из `get_device`, если инструмент их возвращает.
Для старых целей без этих метаданных используются размеры первого кадра.

## Снимок через MCP Designer

При прямом подключении `get_display_frame` возвращает PNG последнего
завершённого кадра из живого предпросмотра. В ответе `source: "preview"`,
`frameRevision`, `scene` (если её передаёт протокол) и `capturedAt`
(время получения в миллисекундах Unix). Даже при включённом Progressive
частично нарисованный кадр в MCP не попадёт. Дополнительного запроса кадра
к устройству нет. Если предпросмотр вообще отсутствует, инструмент
запрашивает кадр у цели и помечает его `source: "device"`.

- `{"fresh":true}` ждёт следующее завершённое обновление. Если экран статичен
  или окно скрыто и обновления нет, ожидание завершается через 15 секунд.
- Для снимка после навигации сначала запомните `scene` из текущего кадра,
  выполните обычное действие навигации и вызовите
  `get_display_frame({"afterScene": <предыдущая scene>})`. Ответ придёт
  только после завершения более новой сцены. Если она уже собрана,
  инструмент вернёт её сразу. Номер сцены действует в текущем подключении.
  Для проверки названия вложенной страницы используйте `get_project_status`.
  Вызов снимка сам экран не переключает.
- Внешний MCP Designer по умолчанию уменьшает снимок до `maxEdge:256`.
  Явный `maxEdge` задаёт верхнюю границу размеров PNG.

На 7″ S3 готовый кадр 800 × 480 вернулся через MCP за 63 мс, следующее
обновление за 819 мс, кадр после перехода Radar → Trip за 880 мс.
Во всех трёх ответах указан `source: "preview"`. Исходная страница
восстановлена, схема и сохранённая ревизия проекта сохранились.

Проверка инструкции `2026-11-12.4` внешним Codex CLI. Модель получила
инструкцию через MCP, самостоятельно прочитала исходную сцену Dashboard,
нашла кнопку Trip в сохранённой оболочке и отправила штатный `clicked`.
Затем вызвала `get_display_frame` с `afterScene` исходного кадра,
получила PNG новой сцены и подтвердила страницу Trip через
`get_project_status`. Ревизия до и после её действий совпала.

## Журнал сессии

Вкладка «События сессии» рядом с предпросмотром занимает всю правую панель.
Её можно развернуть той же кнопкой, что и предпросмотр. Журнал показывает до
200 последних событий. После возврата на вкладку LVGL остаётся предыдущий кадр.

## Таблица диагностики, ширина панелей и RU/EN

Номера глубин показаны единожды в шапке. Под каждой колонкой четыре строки:
Рамка (галочка), RGB рамки, RGB фона, Фон (галочка). `Фон` — диагностическая
прозрачная маска цифры/G/F, исходный фон компонента не заменяется сплошной заливкой.
Общие подписи: G/F, px, α; подробности — в локализованных подсказках. Таблица
помещается в узкую панель для обычного числа уровней; большой набор глубин
прокручивается внутри таблицы, не расширяет окно приложения.

Между чатом и предпросмотром расположен разделитель: перетаскивание, стрелки
Left/Right при фокусе, Home или двойное нажатие возвращают исходное соотношение.
Пропорция сохраняется в Preferences. На узком экране панели располагаются
вертикально; десктопный разделитель скрыт. Он не меняет размер LVGL-дисплея.

Вкладка «Язык» в настройках переключает интерфейс без переподключения и сброса
истории/вложений. Выбор сохраняется в Preferences. Стандартные .resx ресурсы:
App/Resources/Strings.resx (EN) и Strings.ru.resx (RU), сервис Services/UiText.cs.
Локализованы экран чата, настройки подключения, диагностика, подсказки и обычные
статусы. Тексты пользователя/модели, идентификаторы инструментов и исходные внешние
ошибки не переводятся автоматически. Системные промпты модели остаются английскими.

## Пользовательские схемы на S3 и Windows

Встроенные схемы компилируются в ресурсы приложения. Пользовательская схема
сохраняется в хранилище проекта обычными документами стилей
`theme.<id>.<role>`. Схема с новым именем должна содержать роль `canvas`.
Стили накладываются на начальную палитру приложения. Можно также изменить
отдельные свойства одноимённой встроенной схемы. Общий исполнитель стилей
применяет все поддерживаемые свойства роли, включая размеры и форму.

Designer получает контракт из описания действия `ui.select_scheme`. После
сохранения с `refresh:true` действие принимает ID строкой, например
`{"name":"ui.select_scheme","args":"dusk"}`. Событие кнопки в разметке
передаёт ID выражением `{"literal":"dusk"}`. Выбор проверяется по
`ui.scheme.id`. Документы схемы сохраняются после перезапуска. При изменении
уже активной схемы выберите её снова. При старте действует штатная начальная
схема приложения.
