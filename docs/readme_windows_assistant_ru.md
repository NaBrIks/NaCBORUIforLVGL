# Помощник Windows: текстовый запрос → настоящий LVGL

Графическая демка использует host-модуль `examples/windows_player/assistant.mjs`.
Он обращается к совместимому с OpenRouter API через `fetch`, затем выполняет
выбранные моделью инструменты **реального stdio MCP**. MCP обращается к тому же
нативному NaWServer и общим ProjectService/DataRegistry. Дополнительного HTTP-сервера,
интерпретатора UI или альтернативного хранилища проекта здесь нет.

## Настройки и запуск запроса

В настройках графической демки задаются базовый endpoint, ID модели и API-ключ.
По умолчанию endpoint — `https://openrouter.ai/api/v1`, модель нового config —
`qwen/qwen3.8-27b:free`. Существующая сохранённая модель не переписывается.
Preset не означает текущую доступность провайдера: если ID отсутствует в реальном
каталоге, состояние сообщает об этом, модель не добавляется в список искусственно
и не заменяется платной. Перед отправкой выбранная модель проверяется повторно
по действующему каталогу.

`assistant.free_only` по умолчанию true; `assistant.model_filter` — пустая строка.
Оба поля сохраняются вместе с защищённой конфигурацией. Старый config без них
получает эти defaults, сохраняя свой прежний model ID. Поиск без учёта регистра
проверяет полный ID и полное название **до** усечения списка до 64 записей.
Порядок провайдера сохраняется; выбранная модель не переносится вперёд и не
добавляется в результаты искусственно.
Одна страница state.models ограничена 64 строками и 8192 байтами JSON, newline IDs для native dropdown —
4096. Обычный typed source `assistant.model_catalog` содержит тот же порядок
`{id,title,free}`; `free=false` включает и неизвестную цену.

В free-only проходят фактически нулевые `pricing.prompt` и `pricing.completion`.
Цены принимаются только документированными decimal strings: numeric JSON может
потерять исходную точность, поэтому считается неизвестной ценой. Отсутствующие,
отрицательные и некорректные цены не приравниваются к нулю; суффикс
`:free` сам по себе ничего не доказывает. Известная положительная request fee или
условная надбавка также исключает модель. Перед completion неизвестная/платная
модель блокируется; все OpenRouter-запросы этого режима несут
`provider.max_price={prompt:0,completion:0,request:0}`, без fallback-модели и без
автоматической платной повторной попытки. Для custom endpoint без проверяемого
pricing free-only завершается отказом. Ограничение max_price описано в
[официальном provider routing](https://openrouter.ai/docs/guides/routing/provider-selection#max-price),
поля и условные цены — в
[официальной схеме моделей](https://openrouter.ai/docs/guides/overview/models#pricing-object).

Постраничный просмотр использует обычные источники `assistant.model_offset`
(writable, 0..4095, не сохраняется) и `assistant.model_page` (`offset,total,shown`).
`total` — число совпадений после полного фильтра, `shown` учитывает также байтовые
лимиты. Следующая страница начинается с `offset+shown`; предыдущие смещения хранит
UI. Изменение фильтров возвращает offset = 0. Перебор страниц не требует повторной
загрузки provider API, пока cache действителен.

Host держит один компактный полный каталог на endpoint до 5 минут: не более
4096 моделей и 1 MiB ID/названий/флагов; provider response ограничен 8 MiB.
Фильтрация по мере ввода использует этот cache, а не скачивает API на каждую букву.
`assistant.list_models(false)` использует TTL, `true` принудительно обновляет.
Смена endpoint или ключа инвалидирует cache. Изменение фильтра вызывает только
metadata-запрос; draft endpoint/model/key применяются явным Save/Send.
Пустое поле ключа сохраняет прежний ключ. Внутренний host-протокол также
поддерживает clearKey; пустое публичное поле не является командой удаления.
Весь конфигурационный JSON, включая endpoint/model/key, проходит нативные
`protect_secret` / `unprotect_secret` на Windows DPAPI. На диск записывается только
защищённый результат, атомарной заменой. JSON перед шифрованием и ciphertext
перед нативным callback ограничены 4096 UTF-8 байтами: превышение возвращает обычную
ошибку и сохраняет прежний файл. Plaintext fallback отсутствует. Ключ
не передаётся в промпт модели, дочерний MCP-процесс, JSON-проект или публичное
состояние: там публикуется только `keyPresent`.

`load`, `configure` и `models` не вызывают completion. Модельный запрос выполняется
только для `prompt`; список моделей — отдельное чтение метаданных.
Запрос и выбранные через MCP сведения о проекте отправляются настроенному провайдеру.
Изменения проекта выполняются существующими versioned MCP-операциями:
preview не сохраняет проект, сохранение не переключает экран, показ выполняется
отдельно. Успех определяется результатом инструмента, а не обещанием модели.

Формат API соответствует официальным справочникам OpenRouter:
[chat completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request),
[client tool calls и ответы role=tool](https://openrouter.ai/docs/guides/features/tool-calling),
[список моделей](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties).

## Границы исполнения

Одновременно выполняется одна задача; повторный запрос получает busy. Cancel
прерывает запрос, а shutdown отменяет активную работу; её finally закрывает MCP-процесс. Общий deadline —
5 минут, ожидание completion — до 120 секунд, каталога моделей — до45 секунд,
MCP call — до20 секунд.

Промежуточные сообщения идут тем же private host pipe с `id,progress:true,state`:
«Проверка модели», «Подключение MCP», «Ожидание модели (шаг N/33)»,
«Инструмент NAME (N/32)». Это этапы, а не частые тики. Время рисует UI локально.
Progress меняет status, но не закрывает pending request и не меняет atomic
completion/generation. После cancel busy остаётся true, пока не пришёл final
исходной работы. Поздние и повторные ответы завершённого id игнорируются.

HTTP 401/429 и JSON error показывают короткую причину из `error.message` или
строкового `error`, максимум 512 UTF-8 байт. Ключи удаляются до усечения; весь body
провайдера не публикуется. Из metadata выбираются только upstream message,
provider_name и limit_source; числовой Retry-After добавляется как время ожидания. Финальная ошибка имеет okfalse.

На один prompt допускаются до 33 модельных раунда и 32 вызовов инструментов. Результат одного
инструмента, передаваемый модели, ограничен 16 KiB UTF-8: слишком большой результат
заменяется явной ошибкой с советом выбрать меньшую страницу/документ. JSON не режется
посередине. Полный read_project всё ещё может потребовать чтения целого проекта
на host; для небольшого контекста предпочтительнее read_project_document и
селективные запросы каталога. Входной prompt host-движка ограничен 4096 байтами, нативный источник
`assistant.prompt` — 3500 для запаса Data API packet; ответ — 4096.
Ответ провайдера и весь следующий запрос также имеют отдельные жёсткие пределы.
Некорректное название модели с NUL заменяется её ID; NUL в ответах/диагностике
не передаётся в нативный CBOR-поток.

Доступны каталог, чтение, preview, сохранение и показ проекта, обычные события,
а также действия `demo.*`/`ui.*` и записи `demo.*`. Прямые вызовы `assistant.*`,
события собственных `assistant_*` контролов и неизвестные инструменты отвергаются.
В наборе нет shell, файловых команд пользователя или произвольного исполнения кода.

## Проверка без платных запросов

```powershell
node --test tests/windows-assistant.test.mjs
node examples/windows_player/test-assistant.mjs PATH_TO_PLAYER_EXE
node examples/windows_player/test-host-progress.mjs PATH_TO_PLAYER_EXE
```

Unit-тест использует mock fetch и настоящий stdio MCP для локальных read-инструментов.
Проверяются границы, фильтрация инструментов, защищённый config callback, отмена и
закрытие процесса. Сам mock защищённого хранилища не является проверкой Windows DPAPI.

Скрытый native E2E использует provider целиком в памяти и настоящий NaWServer.
Модельный tool loop читает пустой canvas, сохраняет кнопку с обработчиком и подпись
с биндингом, показывает страницу, отправляет событие и проверяет реальный счётчик.
Проверяются пиксели LVGL, сохранённый документ и отсутствие SystemMetrics в графическом
профиле. Измерения и BMP остаются в ignored `local/windows-assistant`. Ни HTTP fixture,
ни платный completion для этой проверки не запускаются. Это проверка механизма,
а качество дизайна конкретной внешней модели проверяется отдельно пользовательским prompt.

Диагностика upstream 429 и проверка реального vision-запроса: [приёмка OpenRouter](reviews/REVIEW_20261108_openrouter.md).

## Бюджет инструментов

Бюджет увеличен до 32 вызовов и 33 model rounds, включая завершающий ответ.
Маленькая правка требует только соответствующих документов/метаданных; инструкция
не заставляет обходить весь каталог до начала работы. В строке прогресса виден
фактический счётчик. Неуспешные попытки тоже расходуют бюджет.

Если очередной batch превышает оставшийся бюджет, ни один его вызов не
исполняется. Модели возвращаются ошибки для всех его tool_call IDs; следующий
запрос имеет tool_choice=none для итогового ответа о подтверждённом результате
и оставшейся работе. Такой же итоговый шаг используется после 32 вызовов или
на последнем model round. Если провайдер игнорирует запрет новых инструментов,
показывается понятная ошибка со счётчиком. Уже применённые изменения не откатываются.

Это завершение по бюджету вызовов, а не гарантия ответа при сетевой ошибке,
тайм-ауте или превышении отдельного hard limit запроса 1 MiB. Общий deadline
5 минут, byte limits, allowlist, отмена и free-only сохранены.

Проверено: assistant unit 26/26; реальный stdio MCP batch из девяти вызовов
успешен; oversized batch полностью отклоняется и получает итоговый ответ.

Общие правила компоновки, канал полного JSON, бюджеты генерации и порядок проверки
без ручных подсказок: [генерация UI моделью](readme_assistant_design_ru.md).

Системная инструкция: [assistant-system-prompt.ru.md](../examples/windows_player/assistant-system-prompt.ru.md) (русский оригинал; модель получает английский файл без .ru),
подгружается в role:system перед каждым prompt. [Снимок через MCP](readme_display_feedback_ru.md)
кодируется PNG на внешнем host; на MCU код агента/PNG encoder не переносится.

Общий бюджет host и browser задаёт assistant-budget.js: 33 rounds,32 tool calls,
до5 минут на задачу, до120 секунд на completion; у клиента ещё10 секунд на final.
Host не переопределяет reasoning: действуют настройки модели/провайдера по умолчанию.
Журнал содержит usage counters output/reasoning без текста рассуждений.
