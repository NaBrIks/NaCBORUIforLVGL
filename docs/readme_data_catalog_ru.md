# Реестр данных, выборочный каталог и история

Приложение владеет одним `DataRegistry`. Он содержит описания источников и действий,
последние подтверждённые значения и группы для поиска. Страницы владеют подписками,
биндингами и событиями. Переписывать движок привязок ради нового каталога не требуется.
Решение: [ADR](adr/ADR_20261107_data-catalog-history.md),
проверка: [отчёт](reviews/REVIEW_20261107_data-catalog-history.md).

## Описание и публикация

```cpp
using namespace lvgl_cbor;
DataRegistry data;
std::string error;
data.add_group({"climate", "Climate", "Indoor measurements", {}}, error);
data.add_group({"room", "Room", "Room sensor values", "climate"}, error);
auto temperature = DataSchema::number(-40, 125);
temperature.title = "Temperature";
temperature.description = "Latest measured room temperature";
temperature.unit = "C";
temperature.nullable = true;
data.add_source({"room.sensor", DataSchema::object({{"temperature", temperature}}),
    {}, "Room sensor", "Application-owned sensor snapshot", "room"}, error);
data.publish("room.sensor", DataValue::Object{{"temperature", 21.5}}, error);
data.flush();
```

В рабочем приложении проверяйте каждый возвращаемый `bool` и `error`.
`add_group()` вызывается до регистрации её потомков и источников. Пустая группа
допустима для старых регистраций. Имена источников остаются глобально уникальными,
плоскими и символьными; дерево групп — классификация, не второй реестр значений.
`DataAction` имеет те же `title`, `description`, `group` и схему аргумента.
У полей схемы доступны `title`, `description`, `unit`, `nullable`.
Setter источника определяет `writable`; описание не даёт права записи само по себе.

Добавлять источники/группы/действия после запуска можно в том же UI-контексте.
Их успешная регистрация увеличивает `catalogRevision`. Схема зарегистрированного
имени неизменна: удаления и замены описания этим API нет. Отключённый датчик можно
инвалидировать или отметить stale; значительный пересмотр конфигурации выполняется
пересозданием реестра и зависящих от него runtime. Ссылки приложения на реестр должны
жить дольше страниц, history и адаптеров.

Описания сейчас принадлежат реестру и размещаются в памяти. ROM-дескрипторы без
копирования не реализованы. Это отдельная возможная оптимизация, не обещание текущего API.

## Типы и состояния

| Тип | Содержание и применение |
| --- | --- |
| `bool` | Состояние, разрешение, флажок, выключатель |
| `integer` | Счётчик, индекс, enum как ограниченный индекс; общий диапазон безопасных целых JSON ±(2^53−1) |
| `number` | Конечное число с min/max: температура, скорость, напряжение, загрузка |
| `text` | Ограниченный UTF-8: имя, IP как текст, время, строковый идентификатор |
| `object` | Именованные объявленные поля; схемы не принимают посторонние поля |
| `array` | Однородные ограниченные массивы, в том числе объектов и массивов |
| `null`, `nullable` | Самостоятельный null либо разрешённый пропуск внутри типизированного значения |

Числа NaN/Infinity не являются передаваемыми значениями. Точные большие идентификаторы
передавайте строками. Файлы/изображения/потоки не складывайте в DataValue: используйте
обычные ресурсы приложения и их идентификаторы. Драйверы UART/BLE/MQTT/датчиков находятся
в прикладных адаптерах; реестр не зависит от способа получения измерений.

`Known + null` у nullable-поля — известный пропуск. `Unknown` означает отсутствие
подтверждённого значения, `Stale` — устаревший снимок. Отсутствующее необязательное поле
или индекс за текущей длиной массива также возвращается как unknown. Выборочная выдача
stale/unknown отправляет `value:null` вместе с состоянием. Она не выдаёт старое число
как актуальное. Nullable-значение нельзя без обработки передать нативному методу,
который требует обязательное число. См. [биндинги](readme_bindings_ru.md).

`publish()` ставит полную замену pending, `flush()` сначала коммитит весь пакет,
затем уведомляет подписчиков. Это последнее состояние, не журнал всех publish.
При повторе того же значения новая ревизия измерения не создаётся.

## Выборочный HTTP API

Используется существующий `GET /api/data`, без нового сервера или хранилища.
Без `kind` он сохраняет старый полный снимок с диагностикой/результатами команд.
Для выборочных запросов нужна версия приложения с `dataQuery` в capabilities;
старый firmware без этого протокола не поддерживается скрытым fallback.
С `kind` работает единая реализация `DataView::query_json()`:

| Параметр | Значение |
| --- | --- |
| `kind` | `groups`, `sources`, `actions`, `fields`, `values` |
| `group` | Для groups — дочерние группы; для остальных — точная группа источника/действия |
| `descendants` | Добавить подгруппы; по умолчанию false |
| `prefix` | Начало символического имени |
| `name` | Точный источник/действие; обязателен для fields и непустого path |
| `path` | JSON Pointer в схеме/значении: `/temperature`, `/devices/0/name`; пустой путь — корень |
| `detail` | Полная выбранная схема либо выбранное составное значение; по умолчанию false |
| `offset`, `limit` | Смещение и максимум записей; limit по умолчанию 16, диапазон 1…64 |
| `maxBytes` | Максимум JSON-ответа в байтах UTF-8, включая оболочку; 4096 по умолчанию, 512…16384 |
| `catalogRevision` | Ревизия предыдущего ответа для согласованного обхода каталога |

Сводка источника содержит тип/ограничения/единицы и число полей без ложной неполной
`schema`. Сводка значения передаёт скаляр непосредственно, у структуры/массива — размер.
`fields` перечисляет непосредственные дочерние поля выбранной схемы источника;
для массива — один шаблон `[]` с путём `/0`, для скаляра — пустой список.
`~` и `/` в имени поля кодируются `~0` и `~1`. Это путь запроса;
`write_source.path` и пути выражений по-прежнему массивы ключей/индексов.

Пример нейтрального адреса:

```text
GET http://device.example:5299/api/data?kind=groups
GET http://device.example:5299/api/data?kind=sources&group=climate&descendants=true
GET http://device.example:5299/api/data?kind=fields&name=room.sensor
GET http://device.example:5299/api/data?kind=values&name=room.sensor&path=/temperature
```

Формат ответа — `lvgl-data-page-1`: `catalogRevision`, `revision`, `total`, `offset`,
`nextOffset`, `hasMore`, `items`. Ответ может содержать меньше limit из-за maxBytes.
Продолжайте с возвращёнными nextOffset и catalogRevision. При изменении состава
каталога ответ 409 `data_catalog_revision` требует начать его обход заново.
Значения между разными запросами продолжают меняться: catalogRevision не делает
весь многостраничный обход values атомарным снимком.

Если даже первая целая запись не помещается — 413 `data_query_record_limit`.
Уточните name/path, уберите detail либо увеличьте допустимый бюджет.
Схема и строка никогда не обрезаются молча. Ошибка параметра — 400.

На UI-задаче создаётся неизменяемый `DataView`; HTTP читает его общие owned records.
Он остаётся валиден после flush и даже после завершения реестра, но не позволяет
вызвать setter. Адаптер заменяет последний view вместе со своим обычным снимком.
В S3 изменение каталога также отправляет CBOR `data_catalog_changed` через имеющийся
WS; редактор обновляет метаданные, не заменяя проект и не сбрасывая локальные правки.

## MCP: сначала обзор, затем нужная часть

```json
{}
```

Это аргументы `get_device`: краткая сводка, число компонентов и разделы discovery.
Дальнейшие вызовы, каждый — отдельный инструмент:

```json
{"kind":"groups"}
```

`get_data_catalog`, затем:

```json
{"kind":"sources","group":"climate","descendants":true,"limit":8,"maxBytes":2048}
```

```json
{"kind":"fields","name":"room.sensor"}
```

```json
{"name":"room.sensor","path":"/temperature"}
```

Последний пример — `get_data`. Он теперь по умолчанию возвращает выборочные values,
а не весь старый snapshot. Для диагностики старый снимок запрашивается явно:
`get_data({"snapshot":true,"maxBytes":16384})`; в этом режиме остальные фильтры запрещены.
Результат отдельной команды — `get_data_command({"id":...})`.

`get_device` предлагает разделы `widgets`, `styles`, `resources`, `limits`, `data`.
Без name компоненты/стилевые методы краткие; с name возвращается полное определение,
в том числе opcode и параметры, нужные компилятору. `offset/limit/maxBytes` ограничивают
контекст модели. `section:all` — явный полный каталог в том же бюджете; большой
каталог вернёт 413. Для типов/стилей/ресурсов фильтрация пока происходит на host
после загрузки целого `/api/capabilities`; для каталога данных фильтрация происходит
на стороне реестра до передачи. Это разные ограничения трафика и контекста.
`get_contract` остаётся явным полным техническим контрактом; ограничение не распространяется
автоматически на произвольные чтения проекта/результаты компиляции.

### Полный редизайн и стек стилей

Данные — лишь один раздел discovery. Агент также получает размеры/компоновки,
компоненты, стилевые методы и ресурсы. Именованные стили — документы `project.styles`;
узел может иметь упорядоченный `styles[]` с selector part/state, плюс локальные свойства.
Несколько стилей подключаются существующим LVGL-механизмом. `copy/merge` создают снимок,
а прикреплённые стили образуют живой стек; это разные операции. Учитывайте приоритет
селекторов и локального стиля: inline-цвет способен перекрыть общую схему.

Новая схема через MCP должна использовать существующие `read_project_document`,
`write_project_document`/`preview_project`/`save_project` и общие кодеки. Данные не
ограничивают редактируемый дизайн текущим видом экрана; нативный список компонентов
и зарегистрированные ресурсы всё же определяют исполнимые возможности. Preview
и save остаются раздельными. См. [MCP](readme_mcp_ru.md),
[стили и runtime](readme_runtime_services_ru.md), [Windows](readme_windows_player_ru.md).

## Необязательная история

`data_history.hpp` — отдельный модуль, приложение владеет его объектом и явно вызывает tick.
Флаг CMake `LVGL_CBOR_HISTORY`: в корневом ESP-IDF компоненте по умолчанию OFF,
в Windows-демо ON. Публичный `LVGL_CBOR_HAS_HISTORY` равен 0/1; при OFF исходник sampler
не компилируется/не линкуется. Без истории обычные значения, кнопки, флажки и события работают.
Глобального выключателя обратных событий не добавлялось.

```cpp
#if LVGL_CBOR_HAS_HISTORY
DataHistory history(data, {2, 128}); // max channels, total points
DataHistoryConfig channel;
channel.source = "room.sensor";
channel.path = {std::string("temperature")};
channel.output = "room.temperature_history";
channel.group = "room";
channel.title = "Room temperature / 1 s";
channel.unit = "C";
channel.capacity = 60;
channel.period_ms = 1000;
history.add(channel, error);
history.set_enabled(true, error);
// In the serialized UI tick, after publishing latest inputs:
data.flush();
history.tick(monotonic_ms, error);
data.flush();
#endif
```

Проверяйте ошибки add/set_enabled/tick. Конструктор не запускает сбор автоматически.
Максимум 8 каналов, 1024 double-точки суммарно, 256 точек на канал; приложение может
задать меньшие пределы. Массив history имеет фиксированную capacity и хронологический
порядок, в начале — null до заполнения. Выход — обычный readonly источник:
`{label,history,timeMs,periodMs,count,mean}`. `count` — заполненные временные позиции,
включая пропуски; `mean` учитывает только валидные точки, null при их отсутствии.
Значение timeMs основано на переданном монотонном времени, не календарной дате.

Постоянное значение сэмплируется по времени. При задержке tick пропущенные периоды
становятся null; последнее значение попадает лишь в последнюю наступившую позицию.
Unknown/Stale/нечисловой вход — разрыв; приложение не получает выдуманную интерполяцию.
Невозрастающий назад timestamp отвергается. Произвольные reducers/подписки на каждый
publish/восстановление прошлых измерений не реализованы.

`set_enabled(false)` освобождает кольца и ставит выходы Unknown. Нормальный flush
освобождает старые committed-значения; удержанные извне DataView могут продлить их жизнь.
Повторное включение начинает новую историю. Демка использует 32 точки с периодом 200 мс,
источник `demo.level_history`, переключатель `demo.history_enabled` и примерный адаптер
`demo.level_plot` к нативному percent plot. Это обычные биндинги и события.
Самостоятельная старая история `SystemMetrics` для CPU/RAM/GPU остаётся частью Windows-примера;
выключение нового sampler не отключает сбор системных показателей.

## Память и границы

По умолчанию до 32 источников, 32 действий, 32 групп; общие пределы метаданных —
32768 байт строк и 1024 узла схем. Заголовок до 128, описание до 512, unit до 32
байт UTF-8. Схема имеет максимум глубины 4, массив — до 256 элементов; остальные
пределы — в binding contract и реальных capabilities. Значение CBOR до 16 КиБ,
общий логический бюджет committed+pending payload — 64 КиБ. Unknown payload равен
нулю, поэтому инвалидирование не требует дополнительного байта при полном бюджете.

Эти бюджеты **не равны общей куче**. Контейнеры C++, строки, callbacks, control blocks,
дескрипторы и временный JSON имеют накладные расходы. Предварительная проверка размера
останавливает большой экспорт до копирования выбранного дерева, однако итоговый
maxBytes — предел ответа, не allocator. DataView закрепляет неизменяемые снимки;
не накапливайте неограниченный список старых view. Простой API не вводит фонового GC,
отдельных реестров на каждую страницу или отдельного storage для MCP.
