# Первый исполнитель общих стилей

Статус: реализованный эксперимент от 2026-10-21. Исполнитель работает с `lv_style_t` LVGL 9.6.0; создание деревьев экранов и биндинги пока остаются отдельным направлением. Пример ESP32-S3 показывает одну надпись и изменяет её оформление через бинарный WebSocket.

## Единый контракт

Источник истины — [contracts/style-api-v1.json](../contracts/style-api-v1.json). Это полезный машинный JSON-документ: одна версия нумерации используется генератором C++, переиспользуемым JS-кодеком и веб-редактором. [Читаемые таблицы индексов](readme_style_indices_ru.md) генерируются из него.

Сейчас закреплены 138 методов семейства **«Общий стиль · lv_style_t»** и 28 сигнатур. Другие семейства не объединяются с ним: контекст команды выбирает семейство, и у каждого семейства своя нумерация. В v1 реализовано только shared.

Номера методов и сигнатур неизменяемы: новые добавляются после максимального назначенного номера; удалённые остаются `retired` и никогда не переиспользуются. Смена сигнатуры создаёт новый метод. Генератор проверяет контракт по `contracts/style-abi-v1.lock.json`; [полное правило ABI](adr/ADR_20261021_lvgl-cbor_append-only-style-abi.md). При обновлении с 9.4 сохранены все старые коды. Стенд пока проверяет точный SHA256 контракта, поэтому совместимость номеров не отменяет синхронного обновления браузера и МК.

```c
uint16_t opcode = ((uint16_t)signature_id << 8) | method_index;
uint8_t signature_id = opcode >> 8;
uint8_t method_index = opcode & 0xff;
```

`method_index` сквозной внутри shared, а не внутри сигнатуры. Одна таблица дескрипторов указывает ожидаемую сигнатуру, число аргументов, проверку диапазона и типизированную обёртку вызова. Общая сигнатура обёрток не означает приведение исходных указателей функций LVGL к несовместимому типу.

Старший байт — часть числового значения, а не первый байт CBOR-последовательности. Ключи методов имеют CBOR major type 0, unsigned integer. Каноническая короткая запись числа использует 1 байт для 0…23, 2 для 24…255, 3 для 256…65535. Поэтому логическая инструкция из двух байтов часто занимает три байта вместе с заголовком CBOR. Ключи передаются числами, не строками с цифрами.

Нумерация v1 уже зафиксирована. Сортировка HTML-справочника её не меняет. `node tools/style_contract.mjs` обновляет производные файлы; `--init` — однократный импорт и откажется перезаписывать существующий контракт. Новый несовместимый набор требует новой версии. INFO отдаёт SHA256 контракта; веб-редактор блокирует отправку при несовпадении.

## Сравнение таблиц

| Вариант | Выбор метода | Следствие |
|---|---|---|
| По таблице на сигнатуру | Старший байт выбирает таблицу, младший — номер в ней | Естественные типы указателей; больше таблиц и их размеров, индексы повторяются между сигнатурами |
| Одна таблица на семейство — текущий опыт | Младший байт выбирает дескриптор, старший проверяется | 128 сквозных индексов shared, единый обход, обёртки сохраняют правильные C-типы |
| Только индекс метода | Дескриптор уже знает сигнатуру | Старший байт избыточен; можно уменьшить ключи, но это отдельное изменение формата |

По одному байту доступно 256 методов на семейство и 256 сигнатур. Выбран второй вариант, чтобы проверить предложенную владельцем модель в работе. Его превосходство по Flash или скорости не измерялось; он не объявляется окончательной оптимизацией. Для расширения за пределы 256 понадобится новая схема/версия.

## JSON для редактирования

```json
{
  "scope": "screen",
  "name": "demo",
  "copy": "global:base",
  "merge": [],
  "attach": true,
  "props": {
    "x": 60,
    "y": 100,
    "size": [420, 150],
    "bg_color": "#173344",
    "bg_opa": 255,
    "text_color": "#F6E9C8",
    "text_font": "montserrat_28",
    "border_width": 3,
    "border_color": "#36B58C",
    "radius": 12,
    "pad_all": 18
  }
}
```

Сокращённое имя свойства или полное имя `lv_style_set_*` выбирает один метод. Для одного аргумента значение скалярное, для `size` — массив `[width, height]`. Цвет — `#RRGGBB` или целое RGB. Булевы значения — JSON boolean. Перечисления допускают числовое значение или имя константы; `|` поддерживается только для допустимой комбинации битовых флагов. Это не язык выражений.

Указатели заменяются строковыми именами ресурсов приложения. Демка регистрирует только шрифты `default`, `montserrat_20`, `montserrat_28`. Методы изображений, градиентов, переходов, массивов grid и других ресурсов включены в контракт, но применять их можно после регистрации ресурса нужного C-типа. Передача адреса/произвольного указателя и `null` запрещена. Ресурс живёт дольше всех использующих его стилей; copy/merge не копируют содержимое ресурсов.

## Wire CBOR и последовательный обход

Оболочка имеет строковые ключи `v`, `id`, `scope`, `name`, `copy`, `merge`, `attach`, `methods`. В `methods` — map с unsigned числовыми opcode-ключами и уже преобразованными значениями. JS сохраняет её как `Map`, чтобы ключи не стали строками. Обычный JSON не умеет числовые ключи map; диагностическая печать такой map не является редактируемым исходным документом.

TinyCBOR обходит пары методов последовательно, без DOM и построения общего дерева. Для каждого opcode проверяются индекс, сигнатура, тип, диапазон и наличие ресурса; затем вызывается обёртка на временном стиле. Это последовательный обход **буфера целого WS-сообщения**, не декодирование произвольно порезанного транспортного потока. Поиск полей оболочки и валидация выполняют дополнительные проходы по тому же ограниченному буферу.

Порядок map не задаёт приоритет. Пересечения вроде `size` вместе с `width` или `pad_all` вместе с `pad_left` отклоняются. Удобные составные методы остаются настоящими вызовами LVGL через обёртки, а их пересечения перечислены в контракте.

## Имена, замена и время жизни

Два пространства имён: `global:name` и `screen:name`. Сначала `copy`, затем `merge` слева направо, затем собственные `props`. Каждый следующий шаг перекрывает совпадающие свойства. Глобальный стиль не может зависеть от экранного.

Команда — полная замена указанного именованного стиля. Старые пропущенные свойства удаляются. Новый вариант сначала собирается во временный `lv_style_t`; при ошибке временный стиль освобождается, существующий не заменяется. При успехе содержимое копируется в постоянный слот с сохранением адреса, после чего вызывается `lv_obj_report_style_change`. Это логическая атомарность по ошибкам формата/проверок, не гарантия восстановления после нехватки памяти внутри LVGL.

`copy`/`merge` создают снимок. Изменение источника не пересобирает производные стили автоматически. Если нужна новая композиция — прислать её заново. Самостоятельные стили можно добавлять объектам несколькими вызовами LVGL; в этой демке выбран ровно один подключённый именованный стиль на одной надписи, selector `LV_PART_MAIN | LV_STATE_DEFAULT`.

`attach: false` обновляет/создаёт запись без переключения надписи на неё. Если эта же запись уже подключена, её изменение всё равно видно. `attach: true` заменяет подключённый демо-стиль. Флаги part/state и множественное подключение не включены в эту первую wire-команду.

Глобальная динамическая область имеет 8 записей по умолчанию; базовый `global:base` находится в статическом уровне и не занимает динамический слот. Экранные области принадлежат экземплярам; исходный редактор по умолчанию имеет собственную область из 8 записей. Области экранов освобождаются после удаления дерева. Опциональный кэш и trim_unused описаны в readme_runtime_services_ru.md. Автоматического GC/порогов памяти нет. Поэтому текущую демку нельзя выдавать за готовый менеджер экранов. Приложение уничтожает runtime **до** удаления его целевого объекта и сохраняет все ресурсы живыми.

## Ограничения и транспорт

- LVGL вызывается только из GUI-контекста; HTTP/WS-задача копирует сообщения в очередь на 4 пакета.
- Ядро допускает вход до 8192 байт; текущая WS-демка ограничивает запрос 3584 байтами и ответ 4096 байтами из-за предела сервера. До 138 методов, до 8 merge-источников. Имена стилей до 31 байта UTF-8; id до 47, ресурсов до 63.
- Только определённые длины CBOR; дубликаты ключей, неизвестные поля, теги, хвостовые данные и недопустимые значения отклоняются. Глубина TinyCBOR ограничена 12.
- `/ws` принимает binary CBOR. Ответ binary CBOR содержит `id`, `ok`, `applied`, `error`, `methods`, `contract_sha256`, `observed`, `echo`, `v`.
- Успешный ответ формируется после применения и синхронного refresh на GUI-задаче. `observed` содержит фактические геометрию/цвета/border, счётчик кадров и контрольные RGB565-пиксели последнего отправленного framebuffer. `echo` — исходный принятый пакет; это не чтение вычисленных LVGL-свойств и не доказательство показанного LCD-кадра.
- Переполнение очереди или неправильный вид WS-сообщения сейчас дают текстовую ошибку; редактор показывает её, применение не подтверждается. Тайм-аут ожидания подтверждения — 5 секунд.
- Обработчики не требуют XML, Subject или скриптового языка. Биндинги не реализованы в этой итерации.

Демка рассчитана на локальный стенд: HTTP/WS без аутентификации, INFO разрешает CORS для отдельного dev-редактора. После отдельного разрешения владельца демка прошита на S3 и проверена через графические поля; владелец подтвердил физическое изменение LCD. См. аппаратный отчёт.
