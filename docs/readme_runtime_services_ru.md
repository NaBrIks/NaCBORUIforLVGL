# Возможности подключённой прошивки и общие сервисы

Реализация от 2026-10-22. [Принятое решение](adr/ADR_20261022_lvgl-cbor_capabilities-style-service-roundtrip.md).

## Возможности устройства

Редактор запрашивает INFO и `/api/capabilities`. Последний ответ содержит:

- style/screen-каталоги с fingerprints, операциями, типами аргументов и перечислениями;
- availableWidgets — ID фабрик, действительно включённых в сборку;
- layouts — доступные алгоритмы, включая добавленные приложением ID;
- resources — реальные имена и C-типы ресурсов приложения;
- limits — действующие ограничения объектов, глубины, текста, стилей и транспорта.

`runtime_capabilities_json(resources,count,limits)` использует скомпилированные таблицы фабрик. Размеры ядра генерируются из контрактов; стенд передаёт отдельные WS-пределы 3584 байта. Снимок стенда публикуется до запуска HTTP-сервера и далее остаётся неизменяемым, поскольку его реестры постоянны. Приложение с изменяемыми реестрами должно обновлять снимок согласованно с UI-контекстом.

Без устройства проверяется общий авторский формат. После подключения проверяются также ресурсы, фабрики, layout и лимиты выбранной прошивки. Редактор предлагает полученные шрифты, виджеты и варианты Flex. Известные только во время выполнения ссылки/состояние дополнительно проверяет C++.

Старое устройство без endpoint возможностей не получает команды от нового редактора. Ответ INFO сохраняется для диагностики; ошибка возможностей показана отдельно. Это не требует перепрошивать плату при работе с эмулятором сайта.

## StyleService

```cpp
lvgl_cbor::StyleService styles(resources, resource_count);
styles.register_static("theme", &application_static_style);
lvgl_cbor::StyleRuntime editor(target, resources, resource_count, &styles);
lvgl_cbor::ScreenRuntime screen(resources, resource_count, {}, &styles);
```

Один сервис должен жить дольше связанных исполнителей. Статические стили и ресурсы принадлежат приложению. Повторная регистрация статического имени отклоняется; динамическая запись может затенить статическую при обычном поиске global.

| Ссылка | Разрешение |
|---|---|
| global:name | dynamic, затем static |
| global-static:name | только static |
| global-dynamic:name | только dynamic |
| screen:name | только область текущего экземпляра |
| name, C++ API resolve | screen, затем dynamic, затем static |

Динамическая замена сохраняет адрес lv_style_t и уведомляет LVGL. Копирование/слияние создаёт самостоятельный снимок. При замене исходного массива Grid снимок удерживает прежнее хранилище, поэтому его указатели продолжают быть действительными.

Для редактирования экранного именованного стиля можно передать `editor.set_screen_scope(screen.style_scope())`. Приложение выбирает соответствующий target и область явно. Изначальная область редактора сохраняется между заменами его образца и освобождается вместе с владельцем/при смене области.

Возвращаемый C++ `StyleHandle` удерживает динамический стиль. Приложение, самостоятельно подключающее `handle.value` к LVGL-объекту, обязано сохранять handle до удаления подключения. Исполнители делают это автоматически.

## Удаление и кэш

Обычный ScreenRuntime освобождает область при unload/замене/уничтожении владельца. Внешнее удаление корня или его родителя запускает очистку на следующем обороте LVGL после завершения DELETE дочерних объектов. Все эти действия выполняются в UI-контексте.

```cpp
lvgl_cbor::ScreenRuntime cached(resources, resource_count, {}, &styles,
    lvgl_cbor::ScreenStyleRetention::Cache);
// После unload именованная область доступна приложению:
auto scope = styles.cached_scope("screen_id");
// Освободить только больше не удерживаемые записи:
styles.trim_unused();
```

Кэширование не сохраняет виджеты и не восстанавливает экран автоматически. Приложение может явно использовать сохранённые именованные стили. Никакой автоматический обработчик нехватки памяти не установлен; пороги, LRU и профилирование отложены.

## JSON ↔ CBOR

```js
import {encodeStyle,decodeStyle,normalizeStyle} from '@lvgl-cbor/style-codec';
import {encodeScreen,decodeScreen,normalizeScreen} from '@lvgl-cbor/screen-codec';
const bytes=encodeScreen(document,'request-id',deviceCapabilities);
const editable=decodeScreen(bytes);
```

Проверяемое правило: повторное кодирование восстановленного документа сохраняет операции и данные. Каноническая запись может отличаться оформлением от исходной: алиас функции, регистр цвета, символ перечисления или значения по умолчанию нормализуются. Имя/название экрана, текст кнопки, проценты/content/FR, ресурсы, состояния и общие операции не теряются.

Generic decodePacket/decodeScreenPacket возвращают wire Map для диагностики и ACK; они не заменяют проверяющие decodeStyle/decodeScreen.

CLI: `node tools/encode_screen.mjs input.json local/screen.cbor` и `node tools/decode_screen.mjs local/screen.cbor local/screen.json`.

## Модули сайта

| Модуль | Ответственность |
|---|---|
| state/lab.js | Сборка зависимостей и предоставление состояния компонентам |
| state/device-connection.js | INFO, возможности, смена устройства/boot ID, отмена прежней сессии |
| transport/command-channel.js | Один общий механизм запроса, тайм-аута и проверки ответа |
| state/style-controller.js | Команды и readback стилей |
| state/screen-controller.js | Компиляция и команды экранов |
| component-preview-link.js | Готовность образца в конкретной сессии |
| state/style-workspace.js, screen-workspace.js | Авторские документы и сохранение |
| state/preview-workspace.js, pane-resize.js | Настройки предпросмотра и размеры панелей |
| App.vue и компоненты оболочки | Представление и связывание действий |

Поля стилей остаются независимыми от соединения и хранения. Проверка импортируемого экрана использует тот же компилятор, что и отправка.
