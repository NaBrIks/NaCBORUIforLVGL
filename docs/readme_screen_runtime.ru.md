# Исполнитель экранов и компонентов: первый MVP

Дата: 2026-10-22. Реализованы C++ исполнитель на LVGL 9.6/TinyCBOR, компилятор JSON → CBOR, транспорт стенда и примеры. После отдельного разрешения владельца прошивка записана на S3; проверены загрузка экранов и смена всех 12 видов компонента через настоящий WS. Результаты и границы аппаратной проверки — в [отчёте](reviews/REVIEW_20261022_editor-component-hardware.md).

## Принятые границы

- `LV_USE_OBJ_PROPERTY_NAME=0`. Поиск setter по имени, таблицы имён Property API и `lv_obj_property_get_id()` не используются. Generic Property API целиком также выключен: `LV_USE_OBJ_PROPERTY=0`.
- На ПК остаются понятные имена типов/параметров. В CBOR тип виджета и операции числовые; отдельные таблицы common, Label, Bar, Slider и остальных классов имеют собственные номера сигнатур и методов. ID экранов/узлов, имена ресурсов и данные приложения остаются символьными UTF-8.
- Биндинги и события подключаются через принадлежащий приложению `DataRegistry`; без него непустые правила отклоняются. `bindings_version:1` версионирует блок отдельно от потока команд v3. Схемы, жизненный цикл, отложенные действия и возможности редактора описаны в [руководстве биндингов](readme_bindings.ru.md).
- Вложенность обычного дерева — до 12 уровней и 128 объявленных объектов на экземпляр. Шаблоны повторения можно раскрывать на ПК; готовое CBOR-описание можно независимо создать несколько раз через `mount()`.

## Два способа создания

```cpp
const lvgl_cbor::Resource resources[] = {
    {"montserrat_20", "const lv_font_t *", &lv_font_montserrat_20}
};
lvgl_cbor::ScreenRuntime screen(resources, 1);
lvgl_cbor::ScreenReply reply;
screen.load(packet, packet_size, reply);  // самостоятельный экран, активируется при успехе

lvgl_cbor::ScreenRuntime left(resources, 1), right(resources, 1);
left.mount(component_packet, component_size, left_parent, reply);
right.mount(component_packet, component_size, right_parent, reply);
auto *left_label = left.find("caption");
auto *right_label = right.find("caption"); // такой же ID, другой объект и владелец
```

`load()` требует корень obj и размер, совпадающий с разрешением дисплея по умолчанию. Документ экрана не перенастраивает LCD. `mount()` создаёт корень внутри переданного объекта и задаёт размер компонента из документа; активный экран не переключается. Один runtime владеет одним текущим экземпляром: повторный вызов заменяет его. Для двух копий нужны два владельца. Их корни могут быть вложены в любой другой контейнер, в том числе созданный другим runtime.

ID уникальны внутри экземпляра. Общей изменяемой карты ID или статического временного буфера декодера нет. Все вызовы, включая уничтожение, выполняются в согласованном UI-контексте LVGL. Сам LVGL не превращается в потокобезопасную библиотеку.

Реентерабельность проверена настоящим вложенным вызовом: LV_EVENT_CHILD_CREATED первого компонента вызывает mount второго владельца. Замена того же занятого владельца возвращает `runtime_busy`; unload во время его операции не выполняется. Владелец не должен уничтожаться из собственного callback. Это явная граница MVP, а не скрытая перезапись общего состояния.

`find()` не обещает вечного указателя. После замены старый объект удалён; запрашивать его заново. Если приложение удалило узел/родителя извне, DELETE callback обнуляет соответствующие handles; удаление внешнего родителя не оставляет работающую карту уничтоженных объектов. Память плана освобождается при unload/замене/деструкторе владельца. При удалении активного самостоятельного экрана runtime возвращает прежний живой экран; если тот уже уничтожен, создаётся пустой экран, принадлежащий дисплею LVGL.

## Массовые операции и исключения

Операция кодируется как `(signature_id << 8) | method_index` внутри выбранного семейства. Тип класса выбирает семейство widget, поле common — общее семейство объекта. Номера method/signature других семейств независимы. Старые операции не сортируются при добавлении новых. Retired-метод оставляет пустой слот и возвращает ошибку.

Обычные setter-ы генерируются по типам: integer, boolean, text, resource. C++ компилятор проверяет реальный вызов LVGL. Порядок CBOR-карты не диктует порядок выполнения: у методов есть phase. Например, range применяется перед value, options — перед selected, max_length/one_line — перед текстом Textarea. В документе задаётся конечное состояние, а не произвольная программа вызовов.

Особые случаи сейчас:

| Случай | Решение |
|---|---|
| `min/max` | Один range-вызов; проверка min ≤ max, отдельная фаза |
| Bar/Slider value | Аргумент LV_ANIM_OFF фиксируется адаптером; не передаётся лишним полем |
| Line.points | Типизированный массив точек хранится в плане; LVGL заимствует его адрес |
| Grid descriptors | Массивы px/content/FR компилируются, копируются в storage и получают терминатор |
| Процент / content | JSON хранит смысл; ПК переводит в закреплённое представление LVGL 9.6 |
| Button.text | На ПК раскрывается в дочерний Label с незанятым внутренним ID |
| Switch/Checkbox checked | Переводится в состояние CHECKED общего семейства |
| Image.src / font / другие указатели | Символьный типизированный ресурс приложения, не числовой адрес из пакета |

Новый обычный setter добавляется в каталог соответствующего класса в конец, затем генерируются таблицы и тест. Исключение получает небольшой адаптер, а не произвольный вызов C по строке. Существующие style opcodes/hash не менялись. Screen ABI имеет собственный hash; стенд и браузер сравнивают оба контракта.

## Память и отказ

Сначала проверяется весь пакет и готовятся типизированные вызовы и стили. Только затем создаётся новое дерево. Семантическая ошибка не меняет прежний активный экран. Строки setter-ов принадлежат плану до его удаления; обычные LVGL text-setter дополнительно копируют текст. Points и Grid tracks не ссылаются на входной пакет. Переданный CBOR-буфер после завершения load/mount можно освобождать.

При замене сначала готовится новое дерево, затем оно активируется, после чего удаляется старое. Объекты уничтожаются раньше их lv_style_t и заимствованных массивов. Одновременно могут существовать две версии дерева, поэтому пиковая память выше размера одного экрана. Бюджеты — не гарантия успешного malloc: невосстановимый OOM внутри LVGL/STL при assert/abort-конфигурации пока не превращён в транзакционную ошибку. Отказ по данным и лимитам проверен; инъекция OOM не выполнялась.

Ограничения ядра: 32 KiB CBOR, 128 узлов, 12 уровней, 256 стилей, 16 KiB widget-текста, 4096 сохранённых числовых элементов tracks/points. Ограничение конкретного WS стенда — **3584 байта**, независимо от большего бюджета ядра. При переходе на большой документ нужен другой транспорт/фрейминг, а не молчаливое обрезание.

Grid MVP требует собственные массивы строк и колонок, проверяет pos/span относительно родителя. Subgrid и изменение структуры Grid через state-стили пока отклоняются. Пользовательские layout-функции, экранные анимации перехода, patches и произвольные callbacks из JSON не поддерживаются. Для зарегистрированных источников и действий действуют отдельные [правила биндингов и событий](readme_bindings.ru.md).

В редакторе «Экраны» выбрать пример в MVP-списке и нажать «＋ MVP». Это создаёт новый документ, сохраняя существующие. Общая панель над предпросмотром содержит «Применить на МК», «Автоприменение», «Проверить». В эмуляторе проверяется компиляция CBOR; LVGL там не исполняется. Применение на настоящем устройстве доступно после совпадения screen ABI. Автоприменение экранов изначально выключено; при включении ожидается ACK и затем отправляется последнее накопленное состояние. ACK содержит результат, node/opcode ошибки, bounds и номер кадра после отрисовки.

Транспорт вынесен в `/screen-ws`. Входящие данные попадают в ограниченную очередь, а не вызывают LVGL из сетевого callback. Прежний `/ws` для стилей сохранён; успешное применение стиля возвращает демо-экран стилей. Физическая плата со старой прошивкой не становится совместимой от обновления сайта.

В режиме отдельного компонента `/component-ws` использует тот же кодек экранов и общую ограниченную очередь. `component_preview.cpp` проверяет форму описания, создаёт экземпляр через `ScreenRuntime.mount()` и перепривязывает `StyleRuntime` к узлу `sample`. Именованные стили, copy/merge и их слоты сохраняются. При неудаче возвращаются прежний объект и его привязка. `StyleRuntime.set_target()` поддерживает временное отсоединение и слабый handle на удаляемый объект. INFO capability `component_preview` позволяет новому сайту распознавать поддержку переключателя «Вид».

## Область отображения хоста

С 2026-10-30 ScreenRuntime и ProjectService принимают последний необязательный
аргумент `ScreenViewport`. `Declared` по умолчанию сохраняет проверку совпадения
размеров дисплея и описания при standalone-загрузке. `Display` позволяет открыть
описание в текущем размере дисплея, а корень получает фактическую область LVGL.
Вложенные страницы по-прежнему используют существующий `fill`/`declared`.

После изменения LVGL display его корневые экраны следуют новому разрешению;
авторские Grid/Flex, процентные размеры и FR пересчитываются самим LVGL.
Перезагрузка CBOR/пересоздание биндингов для этого не нужны. Пиксельные координаты
остаются авторскими пиксельными координатами. Выбор режима принадлежит хосту,
не является новым полем проекта и не меняет wire ABI. Для новых аргументов C++
библиотеку нужно пересобрать. См. [решение](adr/ADR_20261030_display-viewport.md)
и [приёмку Windows](reviews/REVIEW_20261030_windows-resize.md).
