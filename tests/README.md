# Проверки

Файлы и CSS: `document-io.test.mjs` проверяет JSON/CBOR roundtrip примеров, повреждённые/обрезанные пакеты и лимиты; `css-transfer.test.mjs` — каскад, значения, части/состояния, атомарный отказ, экспорт и 300 детерминированных некорректных вводов. `npm test --prefix integrations/mcp` проверяет настоящий stdio, отключение инструментов, ошибочные ACK, таймауты и повторный запуск после отказа. Аппаратный тест с явным изменением экрана: `node integrations/mcp/hardware-smoke.mjs http://DEVICE`.

`npm test` проверяет ABI и кодеки, проектную модель редактора, встраивание Vue и жизненный цикл WS. `tools/test_native.ps1` генерирует реальные CBOR fixtures и запускает C++ тесты с LVGL 9.6/TinyCBOR.

- `native/main.cpp`: исходный именованный стиль, типы, ресурсы, copy/merge, замена и отказы.
- `native/screens.cpp`: ручное/Flex/Grid размещение, состояния и классы виджетов, владение буферами, независимые и вложенно вызываемые экземпляры, rollback и teardown.
- `screen-codec.test.mjs`: числовые операции семейств, нормализация Button, размерности, неверные документы и неизменяемость ABI.

Нативные тесты не утверждают, что прошивка загружена в S3 или что физический LCD уже проверен. Текущие `native/bindings.cpp` и `native/compositions.cpp` проверяют биндинги, события и жизненный цикл вложенных страниц; прежний MVP без биндингов — исторический этап.

Для чистого checkout можно передать независимые официальные LVGL 9.6.0 и
TinyCBOR 0.6.1, не готовя S3 managed components:

```powershell
./tools/test_native.ps1 -LvglSource '<deps>/lvgl' -TinyCborSource '<deps>/tinycbor'
```

Порядок скачивания зависимостей и Windows-сборки приведён в [Readme](../Readme.md).
Параметры необязательны: существующие подготовленные S3-компоненты остаются
совместимым значением по умолчанию.

- `bidirectional-codecs.test.mjs`: каноническая обратимость всех примеров, common-операции, единицы, строгий decode и реальные ограничения возможностей.
- `command-channel.test.mjs`: чужие/некорректные ACK и отмена запроса при смене устройства.
- `native/services.cpp`: общий сервис между исполнителями, static/dynamic, стабильная замена, внешний DELETE, кэш и сохранение заимствованных массивов при copy.
- `npm run contract:check`: проверка производных JS/C++/документации без перезаписи.

ABI v2: семантические отказы (диапазоны, пересечения, Grid) проверяются на ПК в pointer-execution.test.mjs. Нативные тесты проверяют границы загрузки, реальные вызовы, владение, порядок и runtime-регистрацию example:meter. V1-пакеты отклоняются.

Screen ABI v3: `cursor-execution.test.mjs` проверяет реальные массивы команд, локальные номера, блоки стилей и отказы декларативного декодера при непредставимом порядке. Нативный тест проверяет исполнение команд после вложенного ребёнка, переход к соседу, пустое тело, глубину 12, ошибки после частичного создания и обработчик расширения, не потребляющий аргумент. Style ABI остаётся v2.
# Именованные нативные примеры

`native-widgets.test.mjs` проверяет каталог с формы данных, общие адаптеры аргументов, PC-границы и офлайн-восстановление. `tests/native/native_widgets.cpp` выполняет реальные фабрики и обработчики, 100 замен и teardown; отдельный disabled target проверяет исключение модуля. `tools/native_widget_hardware.mjs http://DEVICE` **меняет экран устройства**: исполняет 24 варианта и оставляет демонстрацию трёх компонентов. Запускать только на разрешённой тестовой плате.

## Проекты

`project-codec.test.mjs` проверяет полный JSON/CBOR roundtrip, общие стили, зависимости, ссылки и повреждённые оболочки. `project-client.test.mjs` — передачу частями, отмену, revision, лимит и привязку транзакции к исходному устройству. `project-workspace.test.mjs` — общую рабочую копию экранов/стилей и отсутствие отправки при подключении/открытии.

`native/projects.cpp` проверяет заимствование ROM-пакета, базу/перекрытия, фиксированную политику, удаления/сброс, изолированный preview, сохранение без изменения дисплея, отказ хранилища и восстановление предыдущего целого файлового поколения. Файловая проверка выполняется на ПК; физическая SD не подразумевается.

MCP-тест с реальным stdio и HTTP-стендом различает чтение, предпросмотр, сохранение и конфликт версии. Аппаратные проверки с разрешённой S3: `tools/project_hardware.mjs` и `integrations/mcp/hardware-smoke.mjs`.
