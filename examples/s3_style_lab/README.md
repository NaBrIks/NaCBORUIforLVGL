# NaCBORUIforLVGL: пример для ESP32-S3

Модули сайта, размеры Flash, JSON/CBOR, CSS, отдельный MCP на ПК и сборка без встроенного редактора: [актуальное руководство](../../docs/readme_modules_files_css_mcp_ru.md).

Первая аппаратная заготовка: Waveshare ESP32-S3-Touch-LCD-7 Rev1.2, RGB 800×480, Flash 16 MB, octal PSRAM. Параметры дисплея, пины и базовый интерфейс адаптированы из `../ESP32-yaidfws/examples/touch_lcd7`. Используется соседний компонент NaWServer (ранее ESP32-yaidfws), а не копия его сервера. Его пример использовал LVGL 8; здесь обработчик дисплея адаптирован к LVGL **9.6.0**. Аппаратный запуск и изменение LCD проверены 2026-10-21: [отчёт](../../docs/reviews/REVIEW_20261021_s3-hardware-visual.md).

При запуске `ProjectService` загружает `manifest.entry` (по умолчанию `dashboard`: четыре давления и GPS-спидометр). `main/project_config.hpp` задаёт ROM-базу и один постоянный слой изменений: каталог независимых экранов/стилей на SPIFFS в последних 4 МиБ Flash. Все показания демонстрационные, источники данных не подключены. На FS добавлены радар и маршрутный экран. [Каталог, пути и первичная установка](../../docs/readme_project_storage_ru.md); [проект, сервис, API](../../docs/readme_projects_ru.md). Старые диагностические каналы `/ws`, `/screen-ws`, `/component-ws` остаются доступны. Таблица задач показывается только на странице «Устройство»; в редакторах справа предпросмотр. Touch, OTA и файловый менеджер исходного примера не включены.

## Сборка

Из корня репозитория `NaCBORUIforLVGL`, Node.js 20.19+/22.12+ и PlatformIO:

```powershell
npm ci
npm run contract
node tools/screen_contract.mjs
npm test
npm run build
node tools/pack_assets.mjs
./tools/build_s3.ps1
```

Рекомендуемый каталог PlatformIO по умолчанию (другие пути допустимы):

```powershell
$env:PLATFORMIO_CORE_DIR=Join-Path $env:USERPROFILE '.platformio'
& ./tools/build_s3.ps1
```

Компоненты загружаются IDF Component Manager: LVGL 9.6.0, espressif/cbor 0.6.1~4. Общая ESP-IDF 5.5.6, espressif32 8.0.0. Базовый board PlatformIO называется devkitc N8, но пример явно переопределяет Flash в 16 MB и включает octal PSRAM; это настройки конкретного Waveshare, не универсального DevKitC.

Общая среда ESP-IDF 5.5.6 уже содержит совместимый IDF Component Manager. Локальный обход `local/idf-manager-libs` больше не используется. Официальный managed component LVGL не патчится.

Скопировать `main/wifi_secret.example.hpp` в игнорируемый `main/wifi_secret.hpp` и задать сеть самостоятельно. Без него проект собирается, LCD инициализируется, но Wi-Fi не подключается. При разрешённом аппаратном запуске локальная конфигурация перенесена из игнорируемого Wi-Fi header проверенного S3-примера; значения не выводились. Автоматического стирания NVS нет.

Сборка не прошивает устройство. Перед будущей прошивкой отдельно сверить ревизию платы, разводку, Flash/PSRAM и таблицу разделов. Текущая S3 уже прошита по отдельному запросу владельца; обычная команда build по-прежнему не выполняет upload.

## Работа редактора

```powershell
npm run dev --workspace @lvgl-cbor/playground
```

Открыть `http://127.0.0.1:5298/`. Первая страница «Проект» содержит настройки, файл JSON/CBOR и проект МК с правами/носителями. Для чтения платы указать реальный `http://<IP платы>` и нажать «Подключить», затем «Открыть с МК». Подключение не отправляет документ и не подменяет рабочую копию. «Посмотреть на МК» в редакторе показывает черновик без сохранения; «Сохранить на МК» на странице проекта записывает настроенный слой изменений без переключения LCD. Альтернатива — тот же интерфейс непосредственно по HTTP платы; сжатые assets встроены в прошивку.

Сервер: `/api/info`, `/api/capabilities`, необязательный `/api/project`, диагностические WS и встроенные assets. INFO возвращает реальные heap/PSRAM/uptime и задачи; при недоступности платы редактор не имитирует эти значения. Project API передаёт полные транзакции ограниченными частями, без адресных патчей объектов.

Про формат и ограничения см. [протокол](../../docs/readme_style_protocol_ru.md), про нумерацию — [контракт стилей v2](../../contracts/style-api-v2.json) и [экранов v3](../../contracts/screen-api-v3.json). Ресурсы с указателями регистрируются прошивкой; в стенде объявлены три шрифта. Нативные примеры можно полностью исключить отдельным модулем.

## Проверка исполнителя на компьютере

После загрузки managed_components первой ESP-сборкой:

```powershell
node tools/native_fixtures.mjs
cmake -S tests/native -B local/native-build -A x64
cmake --build local/native-build --config Release --parallel 8
& local/native-build/Release/style_runtime_tests.exe local/native-fixtures
```

На Windows используется MSVC/CMake. Это настоящее применение к объекту LVGL с TinyCBOR, без LCD. Проверяются setter-ы, ресурс шрифта, copy/merge, снимок композиции, полная замена и отклонение повреждённых команд с сохранением старого стиля. Тест не заменяет проверку LCD/PSRAM/Wi-Fi на плате.

Собственный код примера, включая перенесённый код платы из собственного ESP32-yaidfws, распространяется под MIT по прямому решению правообладателя от 2026-10-30. См. [LICENSE](LICENSE) и [реестр происхождения/исключений](../../LICENSES.md). Сторонние компоненты и их notices не перелицензируются.

## MVP экранов и компонентов

В меню «Экраны» создать пустой экран либо добавить пример, открыть его и выбрать компоненты в общем списке над деревом. Стандартные и нативные типы получаются из возможностей платы. «Посмотреть на МК» передаёт полный проект для предпросмотра выбранного экрана. Без платы CSS-приближение не исполняет LVGL.

В `examples/screens` находятся ручная, Flex, Grid, вложенная, shared/state и widget-раскладки, а также отдельный компонент 240×120. [Файлы реализации, API, ограничения и проверки](../../docs/readme_screen_runtime_ru.md). Типизированные привязки и события описаны в [руководстве](../../docs/readme_bindings_ru.md). LV_USE_OBJ_PROPERTY_NAME выключен.

Штатный образ SPIFFS стартует с оболочки `shell`: статусбар сверху, страницы в
контейнере и кнопки навигации снизу. Явный входной Project JSON сохраняет свой
entry. [Новый TCP HTTP/WS стек, полная прошивка и проверки](../../docs/readme_nawserver_tcp_ru.md).

Три вложенные страницы рассчитаны на 800×408 между панелями. Автономный
генератор скорости работает через CBOR event queue и DataRegistry; дробная
стрелка управляется биндингом. [Данные, размеры и live WS](../../docs/readme_demo_events_ru.md).

Серверная зависимость — отдельный [NaWServer](https://github.com/KOE73/NaWServer).
Разместите разрешённый checkout рядом с NaCBORUIforLVGL, в папке `NaWServer`.
Проверяйте LICENSE выбранной ревизии сервера: его лицензирование изменяется
отдельно от этой демки. Собственный код RGB-платы и оболочки редактора теперь MIT;
сторонние copyright и лицензии сохраняются. Перенос include/namespace описан в
[историческом отчёте миграции](../../docs/reviews/REVIEW_20261023_nawserver.md).
