# Waveshare ESP32-S3 Touch LCD 7

Аппаратный пример для Waveshare ESP32-S3-Touch-LCD-7 Rev1.2, RGB 800×480,
16 МБ Flash и octal PSRAM. LCD и сенсор GT911 работают через LVGL 9.6.0.
Параметры платы инициализируются на основе собственного примера
`touch_lcd7` из ESP32-yaidfws. См. [происхождение и лицензии](../../LICENSES.md).

Прошивка содержит резервный проект `dashboard` с симуляцией давления
и GPS. Полный демонстрационный каталог в SPIFFS добавляет оболочку
с панелью состояния и страницами Dashboard, Radar, Trip и Setup.
Для неё нужно подготовить и явно установить образ файловой системы. Пример
демонстрирует интерфейс, привязки и передачу экрана. Датчики не требуются.
В одной прошивке базовые экраны из `ConstProjectSource` загружаются в
явно доверенном режиме, а предпросмотр из редактора и замены из SPIFFS
проверяются. [Правила загрузки CBOR](../../docs/readme_fast_executor_ru.md#проверка-входного-cbor).

## Сборка

Установите Node.js `^20.19.0 || >=22.12.0` и подготовьте PlatformIO с ESP-IDF
5.5.6 по [руководству среды](../../docs/readme_development_environment_ru.md).
Разместите совместимый checkout [NaWServer](https://github.com/NaBrIks/NaWServer)
в папке `NaWServer` рядом с `NaCBORUIforLVGL`. Из корня репозитория:

```powershell
npm ci
npm run build
node tools/pack_assets.mjs
./tools/build_s3.ps1
./tools/build_project_fs.ps1
```

Последняя команда собирает отдельный образ полного каталога в `local/project-image`.
Устанавливайте его только при подготовке чистого раздела или осознанной замене
его содержимого. См. [первичную установку и обновление](../../docs/readme_project_storage_ru.md).

Рекомендуемый каталог PlatformIO по умолчанию (другие пути допустимы):

```powershell
$env:PLATFORMIO_CORE_DIR=Join-Path $env:USERPROFILE '.platformio'
& ./tools/build_s3.ps1
```

Компоненты загружаются IDF Component Manager: LVGL 9.6.0, espressif/cbor 0.6.1~4. Общая ESP-IDF 5.5.6, espressif32 8.0.0. Базовый board PlatformIO называется devkitc N8, но пример явно переопределяет Flash в 16 MB и включает octal PSRAM; это настройки конкретного Waveshare, не универсального DevKitC.

Общая среда ESP-IDF 5.5.6 уже содержит совместимый IDF Component Manager. Локальный обход `local/idf-manager-libs` больше не используется. Официальный managed component LVGL не патчится.

Для HTTP и WS скопируйте `main/wifi_secret.example.hpp` в игнорируемый
`main/wifi_secret.hpp` и задайте свою сеть. Пустая конфигурация позволяет
собрать и запустить LCD без подключения к сети.

Перед установкой сверяйте ревизию платы, разводку, объём Flash/PSRAM и таблицу
разделов. Команды сборки только создают артефакты.

## Работа редактора

После подключения Wi-Fi откройте `http://<адрес-платы>/`. NaWServer
раздаёт редактор из встроенных сжатых ресурсов. Для внешнего редактора
укажите тот же адрес и выберите «Подключить», затем «Открыть с МК».
«Посмотреть на МК» показывает черновик, а «Сохранить на МК» записывает
проект в доступный слой изменений. Нативный Designer подключается к этому
адресу в режиме Direct API. См. [варианты подключения](../../docs/readme_designer_connections_ru.md).

Сервер: `/api/info`, `/api/capabilities`, необязательный `/api/project`, диагностические WS и встроенные assets. INFO возвращает реальные heap/PSRAM/uptime и задачи; при недоступности платы редактор не имитирует эти значения. Project API передаёт полные транзакции ограниченными частями, без адресных патчей объектов.

Про формат и ограничения см. [протокол](../../docs/readme_style_protocol_ru.md), про нумерацию — [контракт стилей v2](../../contracts/style-api-v2.json) и [экранов v3](../../contracts/screen-api-v3.json). Ресурсы с указателями регистрируются прошивкой; в стенде объявлены три шрифта. Нативные примеры можно полностью исключить отдельным модулем.

## Проверка исполнителя на компьютере

После загрузки managed_components первой ESP-сборкой:

```powershell
node tools/native_fixtures.mjs
cmake -S tests/native -B local/native-build -A x64
cmake --build local/native-build --config Release --parallel 8
& local/native-build/Release/style_runtime_tests.exe local/native-fixtures
```

На Windows используется MSVC/CMake. Это настоящее применение к объекту LVGL с TinyCBOR, без LCD. Проверяются setter-ы, ресурс шрифта, copy/merge, снимок композиции, полная замена и отклонение повреждённых команд с сохранением старого стиля. Тест не заменяет проверку LCD/PSRAM/Wi-Fi на плате.

Собственный код примера, включая перенесённый код платы из собственного ESP32-yaidfws, распространяется под MIT по прямому решению правообладателя от 2026-10-30. См. [LICENSE](LICENSE) и [реестр происхождения/исключений](../../LICENSES.md). Сторонние компоненты и их notices не перелицензируются.

## Экраны и компоненты

В меню «Экраны» создать пустой экран либо добавить пример, открыть его и выбрать компоненты в общем списке над деревом. Стандартные и нативные типы получаются из возможностей платы. «Посмотреть на МК» передаёт полный проект для предпросмотра выбранного экрана. Без платы CSS-приближение не исполняет LVGL.

В `examples/screens` находятся ручная, Flex, Grid, вложенная, shared/state и widget-раскладки, а также отдельный компонент 240×120. [Файлы реализации, API, ограничения и проверки](../../docs/readme_screen_runtime_ru.md). Типизированные привязки и события описаны в [руководстве](../../docs/readme_bindings_ru.md). LV_USE_OBJ_PROPERTY_NAME выключен.

Явный входной Project JSON сохраняет свой экран входа и композицию.
Штатные страницы рассчитаны на 800×408 между панелями оболочки. Генератор скорости публикует
данные в DataRegistry через CBOR, стрелка получает дробное значение через
биндинг. См. [данные и размеры](../../docs/readme_demo_events_ru.md).

### Native Viewer: кадр и ввод

Designer получает реальные RGB565 кадры через HTTP или WS. LVF2 передаёт
полный кадр либо изменившиеся области. Источник — рабочие буферы LVGL.
Поддерживаются RAW, адаптивный RLE с временным буфером порции и потоковый RLE.
Сервер обслуживает одну активную передачу кадра; обычный
`GET /api/view/frame` также поддерживает BMP для совместимых клиентов.
См. [транспорт и ограничения](../../docs/readme_display_feedback_ru.md).

`POST /api/view/input`, Content-Type `application/cbor`, принимает `{x,y,pressed}`
в координатах дисплея. Проверяется размер до128байт и границы. Фиксированная
очередь16событий сохраняет начальные координаты нажатия/отпускания; только повторные
движения одного состояния объединяются. При переполнении503, автоматического повтора нет.
Исполнение происходит на UI-задаче через общий с Windows `native_view::Pointer`;
отдельный GT911 indev продолжает работать. Watchdog отпускает указатель через500мс.
`/api/info.native_view_input` объявляется только после инициализации указателя.


### Настройки дисплея

В веб-редакторе откройте «Устройство → Дисплей». Настройки включают режим
LVGL (`FULL` или `DIRECT`), число RGB565-буферов (1 или 2), передачу кадров
(`Dirty` или `Cyclic`), RLE и буфер порции. На странице Setup штатной
оболочки можно выбрать цветовую схему, режим LVGL, число буферов и режим
передачи. Сохранение параметров дисплея записывает выбор в NVS и планирует
перезапуск. При отсутствии сохранённого выбора используются
`DIRECT` и два буфера. `DIRECT` перерисовывает изменившиеся области.
Один буфер экономит 768 000 байт PSRAM, при этом LCD может читать буфер
одновременно с отрисовкой.

`GET /api/display/config` возвращает текущие и сохранённые настройки.
`POST /api/display/config` принимает CBOR с обязательными полями
`mode` (`full` или `direct`) и `buffers` (1 или 2). Дополнительные поля
`transfer` (`dirty` или `cyclic`), `rle` и `rleBuffer` меняют передачу.
Ответ `202` подтверждает запланированную перезагрузку. Набор доступных режимов
определяют параметры сборки `LVGL_CBOR_TRANSFER_DIRTY` и
`LVGL_CBOR_TRANSFER_CYCLIC`, по умолчанию включены оба.
